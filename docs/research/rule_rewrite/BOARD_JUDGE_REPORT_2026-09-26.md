# 보드 판정 측정 기록 — 2026-09-26

`tools/rule_judge/`로 측정한 값이다. 지표 정의와 실행 방법은
[판정기 사용법](#사용법)에 있다. **R1(텍스트 PUSH 기본값) 반영 후, R2(파괴 우선순위) 적용
전** 측정값이므로 R2 결정 이후 재측정이 필요하다. 그 결정과 나머지 미결 항목은
[미결 질문 목록](OPEN_QUESTIONS.md)에 있다.

## 1. 왜 이 기록이 있는가

`plans/kits/01_RULE_REWRITE_KIT.md` §7은 이미 "핵심 시스템과 무관한 우회만 남는 콘텐츠는
REFERENCE GAME 증거로 삼지 않는다"고 쓰고 있고, §11-12에 수동 검수가 있다. 그런데 그 문장
어떤 것도 자동으로 측정되지 않았다. 15개 보드가 모두 통과한 상태였고, 실제 플레이 시간
10분은 "보드당 45–90초"라는 작성 가설 × 15개로 충족되었다.

이 기록은 그 공백을 숫자로 메우는 것이 목적이다.

## 3. 확정된 결론

### 3.1 10번과 12번은 규칙을 쓰지 않는다

10번(공유 벽의 두 방)은 상태 공간 4,023개를 전부 열거했다. 결과:

```
first_solution_depth=5
유일한 해: R R R R R
규칙 변경 횟수: 0
개념적 해 곡선 전체: 1
```

계획서는 이 보드의 과제를 "한 BOX 규칙으로 두 METRIX를 동시에 만들고 공유 벽의 전체 이동
확인하기"로 적어 놓았다. 실제 최단 해는 오른쪽 다섯 회이고, 규칙 단어를 한 번도 만지지
않는다. METRIX整套가 이 보드에서는没有任何 Mandatory Encounter를 발생시키지 않는다.

12번(안쪽 벽 정렬)도 동일하게 6턴 `R R R R R R`, 규칙 변경 0회다.

### 3.2 01~08번은 보드의 79~87%가 비어 있다

`fill` 0.13~0.21. 05번은 13%. 설계 밀도가 낮다는 뜻이다.

### 3.3 여섯 보드는 공간 제약이 전혀 없다

03·05·06·08·13·16은 `walk 도달 = 100%`. 플레이어가 갈 수 없는 칸이 없다. 따라서 난이도는
100% 규칙에서 나와야 하는데, 이 보드들의 규칙 수는 3~5개다. 규칙으로 만들 수 있는 난이도
상한을 보드가已经达到 상태다.

### 3.4 16번은 해가 없다

도달 가능 상태 1,240개를 깊이 27까지 전부 열거했고, 어느 깊이에서도 승리 상태가 나오지
않다. 원작 배치를 우리 어휘로 옮긴 결과다.

봉쇄 원인은 규칙 충돌이다. `BABA IS MELT`는 왼쪽 벽에 붙어 있어 밀어 끊을 수 없고
(`MELT`가 `IS`에 막힘), BABA는 `BASIN IS HOT` 열을 반드시 건너야 하므로 전멸한다.
원작에서 이 레벨을 푸는 방법은 확인하지 못했다.

### 3.5 해가 하나뿐인 보드와 여러 개인 보드의 차이

A(규칙 궤적 dedup)와 B(종착 상태 dedup)의 차이가 아이디어 수를 드러낸다. 10번은 A=1이고
B가 10~5 사이에서 출렁인다. 아이디어는 하나인데 손으로 가는 길이 여러 개라는 뜻이며,
사람에게는 하나의 퍼즐로 experience된다.

## 4. 판정선은 아직 없다

`plans/kits/01_RULE_REWRITE_KIT.md`에 수치를 박는 것은 **후반 작업**으로 남긴다. 근거는 두
가지다.

1. 판정 기준은 원작 수치와 비교해야 한다. 원작 레벨 데이터는 아직 없다.
   `docs/research/rule_rewrite/ORIGINAL_LOGIC_DIVERGENCES.md` §6을 참고.
2. 위 표에서 발산과 정지 상태가 이미 갈라진다. 10·12는 A=1로 정지, 11은 growth 3.0.
   선을 긋기 전에 기준이 될 원본 표본이 필요하다.

## 5. 사용법

```
godot --headless --path . --script res://tools/rule_judge/judge.gd -- <board_id> <max_nodes> <max_depth>
```

인자를 비우면 `content/index.json`의 모든 보드를 훑는다. 이 스크립트는 씬 트리를 쓰지
않고 `RuleMovementSolver`/`RuleEvaluator`/`RuleParser`를 직접 호출한다. 그 결과가 실제 게임과
같은지는 `tests/core/test_rule_judge_parity.gd`가 매 실행마다 확인한다(15개 보드 × 16턴,
1,138 asserts). **판정기와 게임이 어긋나면 판정기의 수치는 버려야 한다.**

## 6. 판정기가 아직 하지 않는 것

- `declared_rule_required`: 초기 규칙 문장 하나를 제거한 변형이 여전히 풀리는지 검사.
  "선언한 규칙이 실제로 필요한가"의 직접 판정이며, 아직 없다.
- 3D 보드 14 미모델링 (제어 대상 전환을 모델링하지 않음)
- 해 개수 곡선의 예산 내 값은 총합이 아니다. `COMPLETE`가 아닌 보드의 곡선은 하한이다.
