# Rain World 조사 — Official Rain World Wiki 기반

조사 대상: **Rain World** (사용자 정정: "레인월드" = "rainworld")
목적: Kit의 Primary Reference로 쓸 수 있도록 **시스템과 UX 문법**을 추출한다.

출처 표기 규칙: `확인` = 위키/공식 페이지에서 직접 확인. `사용자 확정` = 사용자가 직접 지정. `미확인` = 아직 조사하지 않음. 원작의 표현을 옮기지 않고 시스템 규칙만 기록한다.

## 0. 사용자 확정 사항 (2026-09-26) — 조사 방향 정정

이 절은 위키 조사 결과보다 **우선한다**.

| 항목 | 확정 내용 |
|---|---|
| 맵 구조 | **이미 만들어진 맵을 탐험한다.** 절차적 룸 생성이 아니다. 따라서 룸 생성 규칙 조사는 필요 없다. |
| 카메라 | **사이드뷰** 고정. |
| HUD | **전혀 없다.** 상시 표시 정보 없음. |
| 인벤토리 UI | **전혀 없다.** |
| 거래 UI | **전혀 없다.** |
| 존재하는 UI | **로딩 / 사망 / 잠** 화면. 가운데 일러스트, 우하단 버튼 몇 개. |
| DLC | **Downpour / The Watcher 무시.** 본편만 대상으로 한다. |
| 카르마 | **따라가지 않는다.** 짝퉁이 된다. **완전히 다른 시스템으로 대체한다.** |
| 설계 기둥 | **Rain World / Hollow Knight 수준: 단순하면서 세련.** |

### 이 확정에서 빠지는 조사

- 룸/방 절차 생성 규칙 → **조사 대상이 아니다.** 맵은 authored 데이터다.
- Downpour / Watcher 크리처·영역 목록 → **조사 대상이 아니다.**
- 카르마 수치 규칙 → **참고용으로만 남기고 구현 대상에서 제외한다.**

### 이 확정이 남기는 핵심

지도해석: Rain World의 카르마는 "숫자 게이트"다. 사용자는 이걸 버리라고 했다.
따라서 이 Kit이 해결할 질문은 **"숫자 없는 진행 게이트가 무엇인가"** 이다. 답은 5절에서 다루지 않고 사용자에게 결정 받는다.

## 2. 핵심 루프 (확인)

- 플레이어는 **슬러그캣**이다. 무기(창)는 있지만 근본적으로 취약한 생물이다.
- 먹이를 얻고, **하나의 사이클**을 살아남아 **쉼터에서 잠**을 자야 한다.
- 잠을 자면 카르마가 오르고, 카르마가 **지역 간 문**을 열어서 진행이 가능하다.
- 죽으면 카르마가 떨어지고, 그 자리에서 다시 시작한다.
- 더 큰 크리처들은 **같은 생존 계획**을 가지고 있다. 즉 생태계의 일부다.

> 즉 이 게임의 성장은 "능력치"가 아니라 **카르마 수치와 영역 개방**으로 표현된다. 이것이 이 Kit에서 따라가야 할 성장 문법의 1순위 근거다.

## 3. 핵심 시스템

### 3.1 크리처 ID 시스템 (확인)

위키 원문 요지:

- 크리처, 오브젝트, 그 밖의 세계 엔티티는 **ID 시스템**으로 **무작위 외형·성격·그 밖의 무작위 통계를 고정**한다.
- 스투어웨이처럼 일부 크리처는 방 인덱스와 배치에 따라 **고정 ID**를 가진다.
- 대부분의 크리처(den을 쓰는 크리처 전부)는 **순차 트래커**로, 아직 쓰이지 않은 ID를 확실히 배정받는다.

해석: 같은 시드에서는 항상 같은 개체가 나온다. 저장은 픽셀이 아니라 **ID**로 한다.

### 3.2 Den (출혈/수중) 시스템 (확인)

위키 원문 요지:

- 대부분의 크리처는 **den**을 가진다. den은 화면 밖에 있을 수도 있다(브금, 스캐버커가 그 예).
- den은 **스폰 위치**를 정하고, **비가 올 때 물러날 장소**가 된다.
-어떤 크리처는 스폰 방식에 따라 den을 쓰지 않는다. 묶여 있는(테더) 개체는 방에 직접 배치되고, 이동 가능한 개체만 den을 쓴다.
- **den을 쓰는 크리처는 사이클 사이에도 세이브 파일에 보존된다.** 단, 죽지 않았을 때만.

den 재충전 규칙 (확인):

- 그 den의 개체를 **슬러그캣이 죽였고**, 주기가 지나 den이 비어 있으면, 후속 사이클에 새 개체가 채워질 확률은 **1/3**.
- 단, **Hunter / Artificer / Spearmaster**로 플레이할 때는 이 확률이 **50%**.
- 그 외의 경우(다른 크리처가 죽였거나 강제 종료 등)는 den이 **다음 사이클에 확실히** 새 개체로 채워진다.

해석: 이 테이블 하나가 "수집형 생물학"의 게임성을 만든다. 처치 여부가 아니라 **누가 죽였는지**가 재채워움 확률을 바꾼다.

### 3.3 Lineage(계보) Den (확인)

위키 원문 요지:

- 일부 den은 **lineage 시스템**을 가진다. den은 여러 개의 **순차 스테이지**로 나뉘고, 각 스테이지에서 다음 스테이지로 **진행할 확률**이 있다.
- lineage den의 개체를 **슬러그캣이 죽이고** 확률 판정을 통과하면, 그 den의 **현재 스테이지가 다음 스테이지로 넘어간다**.
- 현재 스테이지가 "개체를 생성하지 않는다"로 설정되어 있으면, 확률 판정은 **영역이 로드될 때마다** 시행한다.
- 마지막 스테이지는 다음 스테이지로 진행할 확률이 **반드시 0%**이다.

해석: "이 방에서 다음에 무엇이 나타날까"를 랜덤이 아니라 **전이 상태기계**로 만든다. authored content의 확장 단위 후보.

### 3.4 카르마 (확인) — **구현 대상 아님. 참고용으로만 보존**

| 규칙 | 내용 |
|---|---|
| 기본 역할 | **게이트**. 카르마 일정 수준 이상이어야 새 지역으로 진행 |
| 상승 | 사이클을 **먹이를 먹고 쉼터에서 자서** 마치면 +1. 이미 최대면 유지 |
| 표시 | hibernation 화면에서 올라가는 바퀴. 맵 버튼을 누르면 음식 게이지 왼쪽에 표시. 사망 화면에도 표시 |
| 하락 | 죽으면 감소 |
| 코-op | Jolly Co-Op에서는 전 플레이어가 카르마를 **하나로 공유** |
| 최대치 | 초기 최대 5. Echo 방문으로 5→7, 이후 Echo마다 +1. Echo 4개(또는 Five Pebbles) 방문 시 최대 10 도달. 그 이후 Echo는 최대치를 더 올리지 않지만 현재 카르마를 최대까지 채워준다 |

카르마 게이트:

- 지역 사이의 **Karma Gate**는 통과에 필요한 카르마를 **양쪽 방향 각각 2개 심볼**로 표시한다.
- 요구 카르마는 해당 구역의 난이도를 **대략적인 지표**로 쓸 수 있다.

카르마 플라워 (확인):

- 월드 고정 위치에 존재하며, 먹으면 카르마를 보강한다.
- **죽어도 카르마를 잃지 않는다.** 대신 플라워가 제공한 보강이 소모된다.
- 플레이어의 **직전 사망 위치에 새 플라워가 생성**된다.
- 보강된 카르마로 플라워를 또 먹으면 효과 없음. 보강 상태에서 굶어 죽으면 보강이 소모됨.
- Monk은 사망 위치에 플라워가 뜬다. Hunter 캠페인에는 플라워가 없고, 다른 슬러그캣은 최종 사망 위치에 플라워가 뜬다.

해석: **부활 지점과 진행 게이트를 같은 숫자 시스템으로 묶었다.** Kit이 따라갈 핵심 결합 중 하나.

### 3.5 스캐버거 사회 시스템 (확인)

스캐버거는 "Reputation-based" 행동이 위키 인포박스에 명시돼 있다. (확인)

| 항목 | 값 |
|---|---|
| 체력 | 1.1 |
| 즉사 기준 | 1.65 |
| 킬 포인트 | 6 |
| 머리 배수 | **13배** |

세계관 (확인):

- 네발 짐승이며 긴 전완과 짧은 다리를 가진다.
- 얼굴에 뿔·가지·부리 같은 형태적 특징이 있으며, 꼬리·가시·/frill이 개체마다 다르다.
- 색은 넓게 다양하나 대부분 **중간~저채도**.
- **제스처와 신체언어로 소통**한다.

평판에 따른 행동 (확인):

| 평판 | 행동 |
|---|---|
| 중립 또는 양수 | 중간 정도의 예의를 유지. **자극받지 않으면 비공격** |
| 매우 양수 | **.groups로 슬러그캣을 따라다니고**, 위협받으면 방어로 나선다. 단, 우호적인 무리를 두면 폭발물이나 창을 던져 오히려 해가 될 수 있다 |
| 음수 | **자극 없이 공격**하기 시작. 무기를 내려놓거나 천천히 움직이는 등 **평화적 행동을 보이면 공격하지 않을 수 있음** |
| 성격 상향 | 평균보다 공격성이 높은 개인은 **평판과 무관하게** 죽이려 들 수 있다. 이런 개체는 **신체언어로 미리 알려준다** |

교역 (확인):

- Gourmand는 제작으로 가치 있는 물건을 만들어 스캐버거에게 줄 수 있어 평판을 올리기 쉽다.
- Spearmaster는 창을 무한히 만들 수 있어 평판을 올리기 쉽다.

전투 수치 (확인):

- 창 1~2개로 죽는다. **머리 명중이면 즉사.**
- 멀리서 무기를 던질 수 있고 보통 무리로 있어, **스캐버거 통행료 같은 넓은 공간에서 특히 위험**하다.
- 통행료 지점에는 폭발물이 흩어져 있고, 던지면 **미작동 폭발물을 연쇄 기폭**시켜 다수를 죽일 수 있다.

기능 목록 (위키 목차 기준, 확인): Communication, Trading, Scavenger Tolls, Scavenger Merchant, Scavenger Treasury, Decals, Relationships, Variants & Attributes, Personality.

> **미확인**: 각 기능의 정확한 수치와 규칙. Reputation 시작값 섹션과 각 기능 본문은 미독해.

해석: 이게 이 게임의 "사교 시스템"이다. 개별 AI가 아니라 **집합의 기억과 체력**으로 관계를 표현한다. 여러 층위: 개인 성격 → 무리 → 전체 평판 → 화폐/보물.

## 4. 사용자 제공 캡처 관찰 (2026-09-26, 대화 입력)

아래 두 장은 사용자가 대화로 직접 제공했다. **아직 저장소 파일로 보존되지 않았다.** 필요하면 사용자가 파일로 넘겨야 한다.

### 캡처 1 — 일반 플레이 (사이드뷰)

관찰된 사실:

- **HUD가 화면에 없다.** 좌상단에도 우상단에도 우하단에도 상시 표시가 없다.
- 플레이 개체(하얀 포유류)가 배경 암벽 위 스탠스하게 있다. 개체가 유일한 시각 초점이다.
- 화면은 **3단 깊이**로 읽힌다: 전경의 어두운 덩어리(실루엣만), 중경의 구조물, 원경의 따뜻한 파.sfär의 산업 폐허.
- 배경에 원통형 파이프/탱크 구조가 반복되어 있다. 벽돌 벽 위에有機 무늬 식생이 올라와 있다.
- 색은 저채도 웜톤(분홍·호박·자주)에서 **자주빛 온도**로 수렴한다. 그림자 쪽으로 어둡게 가라앉는다.
- 개체의 하이라이트가 화면에서 가장 밝고 가장 채도 높은 점이다. **초점이 항상 개체 1곳뿐.**

### 캡처 2 — 잠(수면) 화면 + 지도

관찰된 사실:

- 화면 전체가 **어두운 배경 + 흰 선화**로 구성된다. 색면이 아니라 선과 기호가 정보를 전달한다.
- 좌측 절반에 **방사형 그래프**가 있다. 중앙 원에서 여러 갈래로 선이 뻗어 있고, 각 끝에 **기하학적 문자**가 있다.
- 그래프에 `The Chieftain` 이라는 라벨 하나. 즉 지도 위 **개체 이름 라벨**이 존재한다.
- 중앙 우측에 **큰 일러스트**: 웅크린 채 잠든 개체. 잠 화면의主角.
- 좌하단 `PASSAGE` 버튼. 우하단 `EXIT` / `CONTINUE` 버튼.
- 하단 중앙에 **작은 원 5개**가 2그룹으로 나뉘어 있다(3개 | 2개 구분으로 보인다).
- 좌상단에 도구 아이콘과 보라색 게이지 1개.
- 우측에 **점선 세로 2줄**에 마름모 마커가 늘어선다.

이 캡처에서 **따라갈 것과 버릴 것**을 나누는 작업이 아직 안 끝났다. 특히 점선 마커 열은 카르마로 추정되나 확인되지 않았다.

## 5. 미확인 (다음 조사가 필요한 것)

0절의 확정으로 조사 대상에서 빠진 것은 표시하지 않는다.

1. **맵 데이터 구조.** authored 맵이 실제 코드에서 어떤 형태인지. region/room 연결, 이동 가능한 경로, 잠금, 되돌아오기. 미확인.
2. **잠 화면 + 지도 화면 구성.** 캡처 2장으로 윤곽만 확인. 지도 기호体系和 그래프 레이아웃 규칙 미확인.
3. **사망 화면 구성.** 미확인.
4. **로딩 화면 구성.** 미확인.
5. **입력 스킴 전체.** 이동·연출·구르기·특수 행동의 키 배분. 리바인딩 존재 여부. 미확인.
6. **카메라 고정 방식.** 영역 전환 시 카메라가 어떻게 움직이는지, 영역 안에서 개체를多大追击하는지, 화면비. 미확인.
7. **개체 실루엣의 정보량.** 이미지 0개로 어떤 실루엳을 만들 수 있는가. 이 판정이 Kit의 표현 설계를 결정한다. 미완료.
8. **스캐버거 평판 수치와 상승/하락 조건.** 미확인.
9. **개발 과정.** Videocult의 개발 방식, 도구, 스코프. 미확인.
10. **오디오.** 사운드 디자인 진술, 사용 도구. 미확인.

## 5. 이 Kit이 따라갈 것으로 보이는 우선순위 (가설)

미확증. 계획서 확정 전까지 가설로만 쓴다.

1. 사이클 구조(먹이 → 쉼터 → 잠 → 카르마)
2. den / lineage 기반 크리처 지속성
3. 평판 기반 집단 행동
4. ID 기반 개인 고정
5. 진행 게이트
