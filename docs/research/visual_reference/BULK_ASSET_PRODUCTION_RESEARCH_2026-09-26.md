# 독창성과 일관성을 유지하는 이미지 대량 제작 조사

조사일: 2026-09-26. 상태: 조사·제안. 서비스 출력 비교나 구독 결제는 수행하지 않았다. 기존 제작 규칙을 대체하지 않는다.

> 후속 교정: 게임개발방 대화록을 반영한 [게임 에셋 특화 조사](GAME_ASSET_TOOLS_CHAT_RESEARCH_2026-09-26.md)를 우선 읽는다. 아래 Midjourney 우선 추천은 범용 이미지 비교에 치우쳤으며, 게임 에셋 제작 작업장 선정의 최종 추천으로 사용하지 않는다.

## 결론

현재는 같은 생성기에서 규칙과 기준 그림을 더 만드는 것보다, A/B 원본의 화풍을 다른 피사체에 옮길 수 있는 모델을 먼저 고르는 편이 타당하다. 그 뒤 승인된 인물·자산을 기준으로 변형을 제작하고, 성공한 작업만 일괄 처리로 옮긴다.

- **화풍 비교 우선 후보: Midjourney Style Reference.** 이미지 스타일의 영향도를 직접 조절할 수 있다. 우리 그림체에 더 잘 맞는지는 미확인이다.
- **대량 제작 작업장 우선 후보: Scenario.** 생성·편집·학습·반복 작업·자산 관리를 한 환경에서 구성하는 기능이 목적에 맞는다. 기능 적합성과 결과 화풍의 적합성은 별개다.
- **편집과 API 대량 처리 후보: Gemini/Nano Banana.** Google AI Studio에서 소량 비교 후, 통과하면 Gemini API의 batch로 확장하는 경로가 있다.
- **Higgsfield는 비교용 작업장 후보.** 서비스 이름만 바꾸면 화풍이 해결되는 것은 아니다. 내부 모델, 입력 이미지 전달 방식, 설정까지 구분해야 한다.

## 2. 문제를 나눠야 하는 이유

| 문제 | 필요한 제어 | 해결됐다고 볼 수 없는 것 |
|---|---|---|
| 화풍 | 실제 스타일 이미지와 영향도, 필요하면 스타일 학습 | 비슷한 색감이나 'painterly'라는 단어 |
| 같은 인물 | 승인된 인물 이미지, 편집·정체성 참조 | 같은 seed만 사용 |
| 포즈·단서·장면 | 구도/포즈 입력, 국소 편집, 내용 검사 | 화풍이 맞는 예쁜 그림 |
| 대량 작업 | 작업 목록, 큐, 실패 재시도, 파일·설정 기록 | 후보 4장을 한 번에 생성 |
| 독창성 | 프로젝트 고유의 인물·의상·생활도구·공간 설계 | 원본의 머리·의상·장식까지 재사용 |

위 구분은 이번 조사에 따른 작업 제안이다. 원인은 아직 확정되지 않았다. 긴 프롬프트, A/B 조합, 모델 자체 성향, 서비스의 프롬프트 변환은 각각 원인 후보다. 현재 실험 기록만으로 어느 하나가 단독 원인이라고 단정할 수 없다.

- [Scenario 제작 흐름](https://help.scenario.com/articles/7094354401-building-workflows-in-scenario): 수동 생성에서 성공한 단계를 Workflows와 Apps로 반복 가능하게 구성한다.

## 4. 실제 대량 제작 방식 제안

### 먼저 화풍이 되는지 확인

A 단독과 B 단독으로 같은 새 피사체를 제작해 원본과 비교한다. 내용이 복잡한 미라의 모든 세부 조건을 한 번에 넣기보다 화풍 재현 여부를 먼저 분리해서 본다. 원본 색 하나를 바꾸는 편집은 별도 과제다. 색 편집 성공만으로 다른 사람·다른 포즈에도 성공한다고 보지 않는다.

통과한 뒤에 A/B 조합과 실제 미라 제작으로 이동한다. Midjourney에서 성공했다고 Scenario나 Gemini에서도 같은 품질이 유지된다고 가정하지 않는다. 도구를 넘기는 구간에서도 한 번 확인해야 한다.

### 승인된 인물에서 분기

미라의 정면/반측면과 핵심 의상·소품을 승인한 뒤 표정·행동별 작업을 분기한다. 매번 마지막 생성물을 물려주는 긴 편집 사슬은 피하고, 승인된 기준으로 돌아가서 필요한 변화만 준다. 원본 A/B의 독특한 눈·헤어·장식이 결과 인물에 섞였는지도 본다.

### 성공한 작업을 목록으로 반복

한 행에 한 자산을 둔다:

`자산 ID | 기준 이미지 버전 | 모델/설정 | 변경할 내용 | 출력 규격 | 상태 | 비용 | 결과 경로`

상태는 대기/생성됨/수정필요/승인으로 충분하다. 인물·배경·소품은 나누어 처리한다. 첫 소량 묶음이 통과하면 같은 설정으로 다음 묶음을 생성한다. 개별 실패만 다시 작업하고 전체를 재생성하지 않는다. 스타일·얼굴·단서 오류는 생성 편집으로 고치며 기계적 배경 분리와 크기·피벗 정렬은 별도 반복 처리한다.

### 학습은 자료가 준비된 뒤

Scenario 공식 학습 안내에는 종류별 데이터 구성이 있으며, 단일 주제/스타일 LoRA에 5–15장 등의 출발 범위를 제시한다. 이것은 품질 보장이 아니다. [학습 안내](https://help.scenario.com/articles/5151772792-basics-of-model-training)

현재 A/B 두 장으로 두 스타일과 새 인물 전체를 안정적으로 학습한다고 약속할 수 없다. 승인된 다양한 그림이 모이고, 학습에 사용할 권리가 확보됐을 때 스타일 학습을 검토한다. 실패한 생성물로 장수만 늘리면 실패 특징까지 고정할 수 있다.

## 5. 비용과 다음 선택

비교할 수치는 월 구독료보다 아래 값이다.

**승인 자산 1개 비용 = (생성 + 재시도 + 편집 + 배분한 학습 비용) / 승인 수**

여기에 선택·수정 지시에 쓴 사람 시간도 기록한다. 각 후보에 같은 과제와 같은 최대 시도 수를 주고 화풍, 인물 유지, 단서 정확성, 승인율, 비용, 작업 시간을 비교한다. 실제 생성 실험 전에는 가장 싼 서비스나 가장 충실한 모델을 단정하지 않는다.

제안하는 최소 다음 단계는 Midjourney와 Scenario에서 선택한 모델 하나의 화풍 비교다. 편집 문제가 남으면 Gemini를 비교한다. 결과가 통과한 경로에서만 작은 자산 묶음을 만들고, 성공한 흐름을 일괄 처리로 옮긴다. 이번 조사에서 생성·학습·구독 구매는 실행하지 않았다.
