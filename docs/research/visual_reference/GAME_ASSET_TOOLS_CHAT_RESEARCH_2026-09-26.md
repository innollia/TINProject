# 게임 에셋 특화 도구 조사 — 게임개발방 대화록 기반

2026-09-26. 연구 제안이며 제작 정본을 변경하지 않는다. 서비스 기능은 공식 웹 문서로 확인했고 실제 생성 품질은 시험하지 않았다.

## 결론 교정

이전 조사는 범용 일러스트 서비스 비교에 치우쳤다. 게임 제작에서는 화풍 외에 방향별 캐릭터, 동작 프레임, 투명 배경, 타일 연결, 내보내기, 대량 작업 관리가 필요하다.

현재 TIN의 비픽셀 회화풍 인물·배경·소품 제작에는 **Layer를 첫 웹 작업장 후보로, Scenario를 비교 후보로** 둔다. 설정과 모델을 더 직접 제어해야 하면 **Comfy Cloud**를 비교한다. 이는 기능 적합성 순서이며 A/B 화풍 재현 성능 순위가 아니다.

픽셀 자산이 필요한 Kit라면 **PixelLab**, 비교 후보는 **Retro Diffusion**이다. 현재 A/B를 픽셀 화풍으로 바꾸자는 제안은 아니다. 움직이는 비픽셀 스프라이트는 **Ludo 또는 SpriteGen**을 별도로 평가한다.

## 공식 자료로 확인한 서비스

### Layer — 현재 비픽셀 게임 자산의 우선 조사 대상

게임 아트의 학습 스타일, 여러 모델 비교, 자산 관리, 반복 생성·편집을 제공한다. batch는 프롬프트 변수 조합을 펼치거나 여러 파일에 편집을 적용하고, 성공한 흐름을 재사용하도록 구성한다.

- [게임 아티스트용 기능](https://layer.ai/for/game-artists)
- [대량 생성·편집](https://layer.ai/features/batch-generation)
- [공식 API](https://layer.ai/docs)

**우리 문제와 직접 연결되는 주의점:** SDK 문서는 모델이 모르는 설정이 오류 없이 무시될 수 있고, 학습 참조가 온전히 적용되지 않아도 생성이 성공하면서 `reference_sets_degraded`를 보고할 수 있다고 설명한다. '참조 이미지를 첨부했고 생성도 성공했다'만으로 참조가 실제 적용됐다고 판단하면 안 된다. [생성 문서](https://layer.ai/docs/sdk/generate)

학습은 승인된 자료가 확보된 다음 단계다. 아이템 학습 가이드의 약 25장 권장은 아이템용 예시이며, A/B 두 장으로 우리 전체 그림체를 학습할 수 있다는 근거가 아니다. [아이템 학습](https://help.layer.ai/en/articles/11422236-how-to-train-a-model-for-in-game-items-in-layer)

### PixelLab — 픽셀 캐릭터·방향·동작·타일

공식 제품은 4/8방향, 아이소메트릭, 스켈레톤 기반 애니메이션, 인페인팅, 타일셋을 다룬다. API/MCP 경로도 안내한다. 회화풍 초상을 그대로 유지하는 서비스와 용도가 다르다. 로그에서 직접 사용 사례가 반복된다는 점이 강점이다. [공식 기능](https://www.pixellab.ai/)

### Retro Diffusion — 픽셀 생성의 자동화 비교 대상

공식 저장소에 이미지·애니메이션, 비동기 batch, 비용 추정, 참조 이미지 기반 사용자 스타일, MCP 예제가 있다. 사용자 스타일 등록을 곧바로 별도 모델 학습이라고 부르면 안 된다. 픽셀 정리 도구도 결정론적 처리와 신경망 재구성을 구별해야 TIN 후처리 규칙과 맞는다. [공식 API 예제](https://github.com/Retro-Diffusion/api-examples)

### Ludo — 움직이는 스프라이트의 제작·출력

업로드한 스프라이트의 Animate, Keyframe Animation, Transfer Motion과 엔진용 시트 출력을 지원한다. 공식 FAQ상 웹은 백그라운드 작업을 처리하지만 bulk mode가 없고 반복 batch는 API/MCP 경로다. 웹의 무제한 이미지 조건을 API나 애니메이션에 적용할 수 없다. 로그의 불만 후기도 있어 유료 제작 확대 전 실제 루프와 프레임 품질 비교가 필요하다. [공식 제작 FAQ](https://ludo.ai/docs/game-asset-generation)

### SpriteGen — 같은 이름의 두 도구를 구별

- [kumastudio 웹서비스](https://spritegen.kumastudio.app/): 검색 도구로 본문을 읽지 못했지만 직접 HTTP로 받은 공식 HTML 설명에서 캐릭터·동작 입력, 투명 스프라이트, GIF/스트립 PNG/WebP 다운로드를 확인했다. 내부 모델·batch·화풍 제어는 미확인이다.
- [aldegad/sprite-gen](https://github.com/aldegad/sprite-gen): 같은 로그 6176행의 별도 저장소. Codex/Claude 스킬로 상태별 행, 알파 정리, 프레임 추출, runtime atlas 작업을 안내한다. 웹서비스와 같은 제품이라고 확인되지 않았다. 독립적인 고성능 그림 모델로 간주하지 않는다.

### Comfy Cloud — 작화 통일 작업 흐름을 웹에서 운영

모델·노드·설정과 연결 순서를 관리하고 작업을 큐에 넣어 실행한다. 사용자 LoRA 반입과 지원 노드에는 플랜·호환성 제한이 있다. 로컬 workflow가 모두 그대로 작동한다고 가정하면 안 된다. 로그의 성공담을 재현하려면 사용 모델, 참조 방식, 노드, 설정이 추가로 필요하다. [공식 Cloud](https://comfy.org/cloud)

### 에테르·3D 도구

[에테르AI](https://www.aetherforgeai.com/ko)는 로그의 실제 링크까지 식별했다. 이번 조사에서는 우리 A/B 화풍과 batch의 구체 제어 근거가 부족해 우선 순위에 넣지 않았다. Meshy·Tripo와 3D→2D 렌더 이야기도 있으나, 현재 요청의 2D 회화풍 자산을 대체할 경로로 바로 권하지 않는다.

## 실제 적용 제안

1. **첫 비교는 Layer와 Scenario에서 같은 A/B 원본·같은 새 피사체로 한다.** 내부 모델과 참조 설정까지 기록한다. 작업장이 달라도 같은 모델이면 완전히 다른 생성기 실험이라고 세지 않는다.
2. **화풍이 확보된 인물에서 작은 묶음을 만든다.** 예: 한 인물의 표정 3종, 포즈 2종, 다른 인물 1명. 같은 얼굴 반복과 원본 모티프 유출도 확인한다. 이 수는 실험 제안이지 새 의무 규칙이 아니다.
3. **동작이 필요할 때만 스프라이트 경로로 옮긴다.** 영상에서 프레임을 잘랐다고 게임용 완료가 아니다. 고정 카메라, 발 위치, 크기, 루프 연결, 실제 공격 타이밍을 확인해야 한다. 조사 화면의 정지 인물에 이 단계를 강요하지 않는다.
4. **성공한 설정을 고정해 목록으로 생성한다.** 승인 기준에서 각 작업을 분기하고 실패한 항목만 재시도한다. 비용은 생성 수보다 승인 수와 수정 시간으로 비교한다.
5. **설정 제어가 부족하면 Comfy Cloud로 이동한다.** 더 긴 프롬프트를 계속 쓰는 대신 입력과 처리 단계가 실제 어떻게 연결되는지 통제한다. 필요한 모델과 학습 자료 없이 Comfy로 이동하는 것만으로 해결되지는 않는다.

독창성은 새 인물의 형태·의상·생활도구·세계 설정을 설계하는 단계에서 확보하고, 화풍과 인물 정체성의 반복은 참조·학습·편집으로 관리한다. 자산별 수작업 재작화가 필요한 성공 사례는 현재 TIN의 '생성 결과가 최종 그림' 조건에서는 그대로 채택할 수 없다.

## 이번 조사 한계

실제 계정 안에서 생성·유료 결제·설치·학습은 하지 않았다. 공식 기능 제공과 우리 화풍 재현 성능을 구분했다. 대화록의 결과 이미지·영상이 빠져 있어 체험담의 시각적 성공은 검증되지 않았다. 이전 Midjourney 중심 추천은 게임 에셋 작업장 선정에서는 뒤로 내린다.
