# Ena: Dream BBQ — 초현실주의 규칙 엔진

원본: [00_user_dumps/2026-09-26_01_essay_and_screenshots.md](00_user_dumps/2026-09-26_01_essay_and_screenshots.md)

사용자 결정:
> `초현실주의 세상이야. 어설프게 초현실주의를 하려 하지 말고 **명확한 규칙을 만들고 거기에 따라 세상을 비틀어서** 말도 안 되는 세계관을 만들어줘.`

---

## 0. 이 엔진이 하는 일 / 하지 않는 일

| | |
|---|---|
| **한다** | 실제로 작동하는 8개의 규칙을 정의하고, 그 규칙이 absurdity 를 **자동으로** 생성하게 한다 |
| **하지 않는다** | Ena 의 화면·크라야 질감·3D·채도 높은 색을 모방하지 않는다 |

### 0.1 시각 층위 결정 (중요)

사용자 스크린샷은 **3D 고채도 크라야 인형극**이다.
이 Kit 의 렌더는 **960×540 순수 검정 + 1px 헤어라인 무채색**이다. (`01_RENDER_PIPELINE.md`)

→ **초현실주의는 시각 층위가 아니라 규칙 층위에서 만든다.**
   Ena 표면의 모방이 아니라, Ena 가 실제로 쓰는 **기법**(해석의 지평선, 반복, 부분 해소)을
   이 Kit 의 시스템 위에서 재구현한다.

이 결정이 지켜지지 않으면 "어설픈 초현실주의"가 된다. 그래서 아래 검수 규칙이 있다.

### 0.2 유일한 판정 기준

> **플레이어가 R1~R8 중 하나로 되짚을 수 없는 요소는 버그다.**

초현실적 장면이 아무리 이상해도, 그것이 8개 규칙 중 하나의 결과라면 성공이다.
규칙으로 도출되지 않는 이상함은 장식이므로 넣지 않는다.

이것이 "어설프게 하지 말라"의 operational한 해석이다.

## 2. 규칙 8개

### R1. 모호 명사 (Noun Quest)

퀘스트 텍스트는 **명사구**다. 동사도, 행위자도 없다.

```gdscript
"legend_first_croak": {
  "quest_text": "첫 개구리",       # 명사구만
  "candidate_tags": ["wet_thing", "singer", "container"],
  "candidates": ["prop_vat_one", "prop_vat_two", "foe_banded_throat", "shop_back_room"],
}
```

- 후보는 **복수이고 전부 유효하다.** 고르는 순간이 아니라 **모아가는 것**이 진행이다.
- 어느 후보를 만져도 진행이 된다. 하지만 다른 경로다.
- 원작 구조 차용: 전설(Quest Stone 해금)에 체크형 과제가 있다. → `08` §4.2
- T9 대응.

**금지:** 퀘스트 텍스트에 동사 금지. `"~을 찾아라"` 류도 금지. `~` 만 쓴다.

### R2. 해석 적층 (Interpretation Stack)

모든 오브젝트는 **언급의 기록**을 쌓는다. 절대 해소되지 않는다.

```gdscript
"world.interpretations": {
  "prop_vat_one": [
    "누군가 여기서 손을 씻었다",
    "손을 씻은 게 아니라 수를 거는 곳이다",
    "처음부터 있던 그릇이다"
  ]
}
```

- append-only. **pop / collapse / resolve 연산이 없다.**
- 한 오브젝트의 적층은 **최대 5줄.** 넘으면 가장 오래된 줄이 밀린다.
  → 무한 누적으로 화면이 무너지지 않게.
- **중요: 적층은 설명일 뿐 규칙이 아니다.**
  오브젝트의 실제 동작(`prop_vat_one` 이 무엇을 주는지)은 적층과 무관하다.
  → 규칙은 맑고, 묘사만 흐리게. 이게 "어설픈 초현실"을 막는다.
- T1, T3 대응.

### R3. 단어 전염 (Word Contagion)

한 번 나온 표현은 **성질이 다른 출처에서** 되풀이된다.

```gdscript
"quest_counters": { "heard_vat": 4, "heard_wet_thing": 1 }
```

- 등장 출처가 **순환**한다: `NPC` → `오브젝트 텍스트` → `퀘스트` → `컷신` → 반복.
  같은 출처가 두 번 연속 나오지 않는다.
- 플레이어에게 보이는 진척은 **이 카운터 하나뿐.** 진행률 바를 그리지 않는다.
- 소수의 중요한 표현과 다수의 쓰레기 표현이 섞인다. 그러면 "이게 뭔데"가 지속된다.
- T2, T5 대응.

### R4. 서로 다른 언어 (Cipher NPC)

NPC 집단마다 **결정적 치환표**를 가진다. 배울 수 있다.

```gdscript
"cipher": {
  "family_a": { "map": [3,1,0,2], "word_count_fixed": true, "target_position": -1 },
  "family_b": { "map": [2,3,1,0], "word_count_fixed": true, "target_position": -1 }
}
```

- 어구의 **단어 수와 핵심 명사의 위치(항상 마지막)는 보존**된다.
  표면 문자만 뒤집힌다. → 배울 수 있다.
- 같은 NPC 는 항상 같은 치환표를 쓴다. → 일관성이 있다.
- 두 집단이 같은 대상을 말하면 **비교 가능**하다. 이것이 유일한 학습 통로다.
- **어떤 경우에도 "정상적인 대화"가 되지 않는다.** 어순은 끝까지 어긋나 있다.
- T8 대응.

### R5. 두 자아 (Two Selves)

주인공은 **배타적인 두 상태** 중 하나다. 어느 쪽인지는 **규칙으로 정해지지만, 그 규칙은 세계 안의 물리적 사실로만 주어진다.**

```gdscript
"protagonist": { "mode": "A" | "B" }
```

- 전설마다 **모드 선택 규칙이 다르다.**
  - 전설 3: `hp < 50%` 이면 B
  - 전설 7: 직전 선택이 `wrong` 면 B
  - 전설 11: 노드마다 교대
- 모드가 바꾸는 것:
  - 오브젝스에서 **사용 가능한 동사 집합** (`open` ↔ `break` ↔ `listen`)
  - NPC 의 반응 대사 풀
  - `status` 화면에 보이는 스탯 3개
- 규칙은 **명사로 주어지지 않는다.** "반드시 이렇게"가 아니라 세계 안의 사실로 주어진다.
  플레이어는 두 번 보면 규칙을 말할 수 있다.
- T7 대응.

### R6. 부분 해소 (Partial Resolve) — 핵심

명사 퀘스트의 "답"에 **도달해도 끝나지 않는다.**

```gdscript
# prop_vat_one 을 만진 결과
"quest_counters": { "resolve_prop_vat_one": 1 }
"world.interpretations": { "prop_vat_one": [ ... 새 줄이 추가됨 ] }
```

- **완료 플래그가 존재하지 않는다.** `solved` 같은 키를 어딘가에도 두지 않는다.
- 해답 오브젝트에 닿으면 `R2` 에 줄이 1개 늘고 카운터가 1 오른다. **끝이 아니다.**
- 다른 해답 후보는 계속 남아 있다. **그리고 이미 본 것도 다시 보면 다른 줄이 붙는다.**
- T3, T4, T6 대응. ← 이게 이 엔진의 핵심이며, 제거하면 안 된다.

### R7. 판정 금지 (No Verdict)

게임은 **자기 정답을 말하지 않는다.**

- 전설 선택지의 `grade`(right/wrong/neutral)는 **authored 이되 렌더하지 않는다.**
  → `08` §4.1 의 `grade` 필드는 내부 판정용.
- 어떤 화면도 `정답` `진실` `의미` 를 출력하지 않는다.
- 엔딩에 해설 크레딧을 붙이지 않는다.
- `beastiary`(`observe` 돌)도 **통계만** 보여준다. 해석은 보여주지 않는다.
- T6, T11 대응. → "재미"로 남기고 "예술"로 만들지 않는다.

### R8. 코믹 바닥 (Comic Floor)

초현실적 비트는 **반드시 실제 보상이나 실제 기계적 변화에 물려 있어야 한다.**

전설 노드 셋 중 하나 이상을 만족해야 한다:

1. 실제로 주는 것이 있다 (아이템, 스탟, 동사, 어펙스)
2. 실제 시스템을 여는 카운터를 건다 (`R3` 카운터 → 상점/제작/돌 조건)
3. 지역/화면을 연다

- **맛보기 텍스트 금지.** 기계적 효과도 감정적 효과도 없는 노드는 삭제한다.
- T10, T11 대응.

## 3. 규칙 간 상호작용

```text
R1 (명사 퀘스트)  ──닿으면──▶  R6 (부분 해소: 카운터 +1, 완료 없음)
                              └──▶  R2 (해석 1줄 추가)
R3 (전염)          ──언급할 때마다──▶  quest_counters.heard_* +1
R4 (치환)          ──대화──▶  비교 가능한 단어열 (학습 통로)
R5 (두 자아)       ──모드──▶  사용 가능 동사 집합 / NPC 반응
R7 (판정 금지)     ──모든 것에──▶  정답을 출력하지 않음
R8 (코믹 바닥)     ──모든 노드에──▶  보상/카운터/해금 중 1개 이상
```

### 3.1 한 번의 플레이 루프

```text
1. 전설이 명사 하나를 준다            (R1)
2. 플레이어는 그 명사에 관련된 대상을 어딘가서 본다
3. NPC/오브젝트가 그 단어를 되풀이한다  (R3) → 카운터가 오른다
4. 직접 도달한다                        (R6) → 카운터 +1, 해석 +1줄, 미완료
5. 다른 후보도 만진다                    (R6) → 해석이 쌓인다
6. 끝나지 않는다. 다른 전설이 툭 열린다   (R7: 판정 없음)
```

- 이 루프가 반복될 뿐이다. 5분에 한 번. 플레이타임의 대부분.
- 각 반복은 **정말로 작은 보상**을 준다. (재료, 어펙스 1개, 스탯 1점)
  → `R8`

### 3.2 전투와의 관계

자동 전투 AI(`05`)가 있는 게임이므로 absurdity 는 **탐색/제작/전설** 층에 있다.
전투는 그 결과를 받아줄 문법이다.

- 전설이 열어주는 카운터와 제작/상점 조건이 연결된다.
- `R5` 의 모드는 전투 중 **보이는 손패·사용 가능한 주문**을 바꾼다.
- 전투는 모호하지 않다. **명확하고 빠르고 손해가 크다.**
  → game의 무게중심이 주저앉지 않게 하는 장치. T11.
- 전투에 모호함을 넣지 않는다. "말도 안 되는" 것은 전투가 아니라 **해석**이다.

## 4. 이 엔진이 만들 세계관 (작업 예시)

아래는 **규칙 8개만으로 파생된** 결과다. 컨셉트이고 Phase 4 구현 대상이다.

### 4.1 예시: 첫 전설

```json
{
  "id": "legend_first_croak",
  "quest_text": "첫 개구리",
  "candidate_tags": ["wet_thing", "singer", "container"],
  "cipher_source": "family_a",
  "nodes": {
    "node_intro": {
      "text": "<Phase 4 작성>",
      "choices": [
        { "id": "ch_later", "goto": "END", "grade": "wrong" },
        { "id": "ch_help",  "goto": "node_count" }
      ]
    },
    "node_count": {
      "check": { "quest_counter": "heard_vat", "need": 3 },
      "on_pass": "node_touch",
      "on_fail": "node_count"
    },
    "node_touch": {
      "resolve": "prop_vat_one",
      "on_touch": "node_end_a",
      "text": "<Phase 4 작성>"
    },
    "node_end_a": {
      "ending": "end_wet_hands",
      "reward": { "affix": "aff_x", "tier": 1 },
      "note": "완료 플래그 없음. quest_counters.resolve_prop_vat_one 이 1이 될 뿐."
    }
  }
}
```

**플레이어 경험:**
- "첫 개구리" 를 받는다. 동사가 없다. 무엇을 세어야 하는지도 없다.
- NPC 가 이상한 말을 한다. 같은 낱말이 세 번 나온다. → 무슨 소리인지 신경 쓰인다.
- 지시에 따라 물건에 손을 댄다. **끝났다는 표시가 없다.**
- 보상에 인챈트 1개. `{ch_later}` 로 가면 보상이 다르다. **어느 쪽이 맞는지 안 알려준다.**
- 다른 전설이 열린다.

**R1~R8 로 되짚을 수 있는가:**
`R1` 명사 퀘스트 / `R3` 세 번의 전염 / `R6` 만져도 미완료 / `R7` 판정 없음 / `R8` 인챈트 보상. **가능.**

### 4.2 예시: 되짚을 수 없는 요소 (버그)

```json
{ "text": "잠깐, 이 세상이 왜 이러지?" }
```

- 어떤 규칙의 결과도 아니다. 장식이다. → 넣지 않는다.

## 5. 검수

| # | 검사 | 판정 |
|---|---|---|
| E1 | 전설 `quest_text` 에 동사가 있는가 | 있으면 fail |
| E2 | 각 비트가 R1~R8 중 하나로 되짚어지는가 | 안 되면 fail |
| E3 | R6 을 제거하면 게임이 성립하는가 | 성립하면 R6 이 약하다 → fail |
| E4 | 어떤 화면이 `정답`/`의미` 를 출력하는가 | 있으면 fail (R7) |
| E5 | `grade` 가 화면에 보이는가 | 있으면 fail (R7) |
| E6 | 기계적·감정적 효과가 0인 노드가 있는가 | 있으면 fail (R8) |
| E7 | 같은 출처가 R3 순환에서 연속 나오는가 | 있으면 fail (R3) |
| E8 | R4 집단의 어순이 결국 정상인가 | 정상이면 fail (R4) |
| E9 | 모드가 규칙 없이 바뀐다 | 있으면 fail (R5) |
| E10 | 15개 전설 각각에 R8 조건이 있는가 | 없는 것 있으면 fail |

**E3 가 가장 중요하다.** R6(부분 해소)이 없어도 게임이 굴러간다면
그 규칙은 장식이고, 그 순간 이 엔진 전체가 "어설픈 초현실주의"가 된다.

## 6. Phase 4 구현 순서

```text
1. R1 + R6 + R7  (명사 퀘스트, 부분 해소, 판정 금지)   ← 3개가 최소 코어
2. R3 (전염 카운터)
3. R8 (코믹 바닥 검증)
4. R2 (해석 적층 UI)
5. R4 (치환표)
6. R5 (두 자아)
7. 15개 전설 채우기 + 톤 확정
8. 5절 검수 10개 통과
```

- 1~3번만으로도 엔진은 성립한다. 4~6은 깊이를 더한다.
- R6 은 절대 후순위로 미루지 않는다. 1번에 같이 넣는다.
- Phase 1 에서는 **스키마만** 만든다. (`08` §4.1 의 `quest_text` / `resolve` / `grade` 필드)
  텍스트는 넣지 않는다. → `17` L-02
