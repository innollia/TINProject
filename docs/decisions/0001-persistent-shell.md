# ADR 0001: 영속 셸과 교체 가능한 모듈

- 상태: 채택
- 대상: `app/app_root.tscn`

## 배경

세 데모가 저장·입력·전환·설정을 공유하되 서로의 구현을 알지 않아야 한다. 모듈마다 앱 전체를 교체하면 전역 UI와 진행 상태의 수명이 불명확해진다.

## 결정

AppRoot, Core 서비스, MetaLayer, UIHost, DebugRoot를 유지하고 ModuleHost의 현재 자식만 교체한다. 설치 목록은 앱의 manifest 카탈로그에서 구성한다. core는 구체 모듈 경로를 참조하지 않으며 모듈은 주입된 컨텍스트와 좁은 계약만 사용한다.

명시적 승인 없는 autoload, 범용 EventBus, 내레이터 프레임워크는 도입하지 않는다. 진행과 문구는 작은 meta 스크립트가 처리한다. 완료 이벤트는 기록만 하며 자동 이동하지 않는다.

## 결과와 비용

셸은 정지 중에도 동작한다. 모듈 루트를 DISABLED로 설정하고 입력 라우터를 잠그므로 자식은 처리 모드를 상속해야 한다. UI 상단 150px는 전역 영역이다.

저장 상태는 버전이 있는 불투명 JSON이며 각 모듈이 이관을 책임진다. 로드 직후 이전 모듈 캡처에 의한 덮어쓰기는 change_module(id, true)로 캡처를 건너뛰어 방지한다. 검증 실패 시 기존 모듈과 저장 봉투를 유지한다. 임의의 모듈 런타임 오류까지 자동 롤백하지는 않는다.

진입점과 프로젝트 설정, core·모듈·테스트 구현은 각 담당자가 통합한다. 이 결정은 자동 테스트 성공이나 외부 테스트 패키지 설치를 의미하지 않는다.
