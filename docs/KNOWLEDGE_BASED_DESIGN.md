# 지식 기반 설계 규칙 — 강제 기준

작성: 2026-09-21. 사용자 확정 방향과 지식 기반 게임의 정의를 TINProject용으로 엄격화한 문서다.

## 1. 정의

TINProject에서 "지식 기반"은 단순히 퍼즐, 암호, 관찰 문제를 뜻하지 않는다.

- 핵심 자원은 캐릭터의 아이템·능력치·해금 플래그가 아니라 **플레이어가 실제로 이해한 지식**이어야 한다.
- 새로운 지식을 얻기 전에도 필요한 행동은 원칙적으로 이미 실행 가능해야 한다.
- 플레이어는 규칙·구조·인과·언어·공간·시스템을 이해한 뒤, 이전에는 생각하지 못했던 행동을 스스로 시도할 수 있어야 한다.
- 지식 획득은 새 버튼을 지급하는 것이 아니라 **기존 세계의 가능성을 재해석하게 만드는 것**이어야 한다.

## 2. 필수 판정

지식 기반이라고 부르려면 아래 조건을 모두 검토한다.

1. **지식 게이트**: 진행 차단의 본질이 "플레이어가 방법을 모름"이어야 한다.
2. **사전 실행 가능성**: 정답을 이미 아는 새 플레이어가 세이브 플래그 없이 수행할 수 있어야 한다.
3. **이해의 전이**: 배운 규칙이 한 번의 정답 입력에 소모되지 않고 다른 장면·상황·과거 장소의 해석을 바꿀 수 있어야 한다.
4. **재맥락화**: 새 정보 때문에 이미 본 장면이나 오브젝트의 의미가 달라지는 순간을 설계한다.
5. **비선형 복구 가능성**: 막혔을 때 다른 탐색·관찰·실험으로 관련 지식을 얻을 여지가 있어야 한다.
6. **실행 난도 분리**: 해법을 이해한 뒤 정밀 타이밍·연타·긴 반복 때문에 막히게 만들지 않는다.
7. **스포일러 민감성**: 정답 지식 자체가 진행 자원이므로 힌트·기록·테스트 문구가 해법을 자동 노출하지 않도록 한다.

## 3. 불합격 예시

아래는 그 자체로는 지식 기반 설계로 인정하지 않는다.

- 표찰에서 방향 세 개를 읽고 옆 방에서 그대로 입력하기.
- 세 후보 중 관찰상 정답 하나를 고르기.
- 단서를 전부 수집한 뒤 UI가 정답 후보를 제한해 주기.
- 특정 정보를 본 뒤 내부 플래그가 열리고 이전에는 불가능했던 입력이 활성화되기.
- 한 번 사용하고 다시는 의미가 없는 암호·순서 외우기.
- 오답 횟수만 쌓이는 독립 퍼즐을 여러 개 연결하기.
- "알고 있으면 스킵 가능"이라는 이유만으로 얕은 단일 입력 퍼즐을 지식 기반이라고 부르기.

현재 구현된 일부 사이클 2·3 프로토타입은 위 불합격 패턴에 해당할 수 있으며, 존재 자체가 향후 설계 기준을 충족했다는 증거가 아니다.

## 4. 권장 구조

좋은 지식은 최소 둘 이상의 효용을 갖는다.

- 현재 문제 해결
- 과거 장소 재해석
- 미래 경로 단축
- 위험 회피
- NPC/텍스트/기계의 의미 해독
- 전혀 다른 게임 모듈에서의 응용
- 숨겨진 기능의 자발적 발견

가능하면 하나의 지식이 여러 장면에서 서로 다른 형태로 드러나게 한다. "단서 → 바로 옆 정답"의 1:1 배치는 피한다.

## 5. 테스트 규칙

지식 기반 기능은 일반 상태 테스트 외에 다음을 검증한다.

- **fresh-state solve**: 관련 해금 플래그가 없는 새 상태에서도 정답 행동이 가능하다.
- **no-secret-flag**: 정답 가능 여부를 지식 플래그가 직접 제어하지 않는다.
- **wrong-order discovery**: 플레이어가 설계자가 예상한 순서와 다르게 정보를 접해도 시스템이 깨지지 않는다.
- **cross-context reuse**: 같은 지식이 둘 이상의 맥락에서 실제로 작동하는지 확인한다.
- **spoiler audit**: 기록·UI·테스트용 문구가 정답을 자동으로 설명하지 않는지 확인한다.

## 6. 프로젝트 내 위치

지식 기반 플레이는 TINProject 전체를 하나의 퍼즐 장르로 통일하기 위한 공통 루프가 아니다. 여러 게임 중 일부 또는 여러 게임을 가로지르는 강한 설계 축으로 사용한다. 게임마다 자체 장르와 규칙을 유지한다.
