# 지식 기반 게임 설계 기준

작성: 2026-09-21. 사용자 요청에 따라 "지식 기반 게임"을 TINProject에서 오해하지 않도록 엄격하게 정의한다.

## 1. 장르 정의

지식 기반 게임(Knowledge Based Game, MetroidBrainia)은 **플레이어가 지식을 얻고 이해하는 것 자체가 핵심 자원이 되는 게임**이다.

일반적인 게임이 능력치, 장비, 열쇠, 스킬 같은 캐릭터 측 자원을 얻어 진행 가능 영역을 넓힌다면, 지식 기반 게임은 플레이어가 다음과 같은 것을 이해함으로써 진행 가능성이 넓어진다.

- 게임의 구조
- 규칙과 예외
- 언어·기호의 의미
- 특정 사건의 사실관계
- 공간이나 시간의 작동 방식
- 시스템 간 인과관계
- 오브젝트가 실제로 무엇을 할 수 있는지
- 이전에 본 장면을 다시 해석하게 만드는 정보

이 정의는 폭이 넓다. 모든 지식 기반 게임이 동일하게 "처음부터 물리적으로 전부 접근 가능"해야 하는 것은 아니다.

## 2. TINProject에서의 판정 질문

어떤 콘텐츠를 "지식 기반"이라고 부르기 전에 아래를 반드시 적는다.

1. **플레이어가 새로 알게 되는 지식은 정확히 무엇인가?**
2. 그 지식은 단순 정답 문자열인가, 아니면 규칙·구조·인과·언어·사실에 대한 이해인가?
3. 그 지식을 얻기 전과 후에 **플레이어의 사고 또는 가능한 선택이 어떻게 달라지는가?**
4. 캐릭터에게 새 스킬/키/해금 플래그를 주지 않아도 그 지식이 실제 진행 자원으로 기능하는가?
5. 그 지식이 다른 상황의 해석, 추리, 경로 선택, 시스템 사용에 다시 쓰일 수 있는가?
6. 플레이어가 스스로 연결할 여지가 있는가, 아니면 UI가 단서를 모아 정답을 자동 조립해 주는가?

이 질문에 답하지 못하면 "지식 기반"이라는 라벨을 붙이지 않는다.

## 3. 강한 지식 게이트 — 선택적 상위 패턴

다음은 매우 강력한 지식 기반 설계지만 **모든 지식 기반 콘텐츠의 필수조건은 아니다**.

- 필요한 행동은 처음부터 가능하지만 플레이어가 방법을 몰라 수행하지 못함.
- 나중에 얻은 지식만으로 새 세이브에서도 즉시 같은 행동을 수행할 수 있음.
- 새 정보 때문에 예전에 본 장소·물체·대사가 전혀 다른 의미로 보임.
- 한 장소에서 배운 규칙이 멀리 떨어진 다른 상황에서도 작동함.
- 실제 해금 플래그 없이 플레이어의 이해만으로 순서를 건너뛸 수 있음.

이 패턴을 사용할 때는 fresh-state solve / no-secret-flag / cross-context reuse를 테스트한다.

## 4. 약한 구현을 지식 기반이라고 과장하지 말 것

아래는 지식 요소가 있을 수는 있지만, **그 자체만으로 강한 지식 기반 설계를 증명하지 않는다.**

- 표찰에서 방향 세 개를 읽고 바로 옆 장치에 그대로 입력하기.
- 세 후보 중 눈에 보이는 특징 하나로 정답을 고르기.
- 단서를 전부 조사하면 UI가 가능한 답을 사실상 하나로 줄여주기.
- 한 번 쓰고 버리는 암호·순서·숫자를 외우기.
- 오답 횟수만 쌓이는 독립 퍼즐을 연속으로 배치하기.
- "정답을 미리 알면 스킵 가능"하다는 이유만으로 단일 입력 퍼즐을 지식 기반의 충분한 구현이라고 주장하기.

현재 사이클 2~3의 일부 소규모 모듈은 이런 **얕은 프로토타입**일 수 있다. 그렇다고 해당 모듈을 폐기할 이유는 없으며, 더 큰 게임·상황 속에서 재사용하거나 규칙을 확장하면 된다.

## 5. 지식의 형태를 다양하게 허용

TINProject는 지식 기반 요소를 한 종류의 퍼즐로 통일하지 않는다. 예시는 다음과 같다.

- Golden Idol류의 사실관계 추론
- 언어 해독
- 시스템 규칙 발견
- 환경 관찰과 재해석
- 숨은 조작법 또는 affordance 발견
- 인과관계 추론
- 시간·공간 규칙 이해
- 이전 장면의 의미가 뒤집히는 정보
- 여러 게임/모듈에 걸쳐 재사용되는 지식

지식 기반 설계는 프로젝트 전체의 공통 반복 루프가 아니라, 필요할 때 강하게 가져다 쓸 수 있는 설계 축이다.

## 6. 테스트

지식 기반 요소의 종류에 맞춰 아래 중 필요한 검증을 선택한다.

- **knowledge statement**: 플레이어가 알아내야 할 내용을 한 문장으로 명시할 수 있는가.
- **resource check**: 진행의 핵심 자원이 아이템/스탯이 아니라 실제 플레이어 지식인가.
- **recontextualization**: 새 지식이 기존 장면의 해석을 바꾸는가.
- **cross-context reuse**: 같은 이해가 다른 상황에서도 실제로 쓰이는가.
- **fresh-state solve**: 강한 지식 게이트를 표방한 경우 새 상태에서도 지식만으로 수행 가능한가.
- **no-secret-flag**: 강한 지식 게이트를 표방한 경우 숨은 해금 플래그가 정답 가능 여부를 대신 결정하지 않는가.
- **spoiler audit**: 기록 UI나 힌트가 연결 과정을 대신 해버리지 않는가.
- **wrong-order robustness**: 정보를 예상 순서와 다르게 얻어도 설계가 무너지지 않는가.

## 7. 참고 범위

사용자가 지정한 기준 문서의 핵심 정의는 "플레이어가 게임 구조·규칙에 관한 정보 또는 특정 지식을 이해하게 되는 것 자체가 핵심 자원"이라는 점이다.

대표 범주는 Myst, Outer Wilds, The Witness, Golden Idol, Animal Well, Chants of Sennaar, Return of the Obra Dinn, Tunic, Öoo 등처럼 서로 형식이 크게 다르다. 따라서 TINProject에서도 지식 기반을 특정 퍼즐 포맷 하나로 축소하지 않는다.
