# 세계관·서사 비평 실행 절차

버전: 1.0 / 2026-09-27 사용자 승인. 절차의 적용 승인이고 원안의 내용 승인이나 효과 검증은 아니다.

## 1. 적용 범위와 입력

설계 비평, 반복되는 오독의 진단, 집필 파이프라인 검토에 적용한다. 짧은 사실 확인과 명확한 단일 수정에 다섯 비평을 의무화하지 않는다. 발상 단계에서 이 문서를 새 콘텐츠의 특성 배정표로 사용하지 않는다.

작업 시작에는 [입력 양식](critical_review/REVIEW_PACKET.md)을 채운다. Kit04에는 [구별할 축과 현재 결정](critical_review/KIT04_DIMENSIONS.md)을 필요한 부분만 붙인다. 사용자 요청이 현재 컨텍스트 분석이면 새 자료를 읽어 분석 대상을 바꾸지 않는다.

입력마다 `USER`(사용자 원문·확정조건), `SOURCE`(원작 관찰), `PROPOSAL`(작업자 제안), `UNKNOWN`을 붙인다. SOURCE에는 출처와 직접 관찰/사용자 설명/커뮤니티 기록 여부를 둔다. 요약·원작 해석은 관찰과 구분한다. 누락된 자료를 기억으로 채우지 않는다. 충돌은 해당 항목만 표시한다.

작성자의 긴 대화, 변명, 자기 평가, 폐기된 해석을 비평 패킷에 넣지 않는다. 폐기된 해석은 필요한 경우 '현재 적용 금지' 한 줄로만 남긴다. 출처 원문은 외부에 보존하고 판단에 필요한 발췌와 위치를 제공한다. 승인되지 않은 세계 초안은 PROPOSAL이다.

## 2. 차원 혼동 검사

사용자의 관찰 → 내가 세운 가정 → 제안하는 변화 → 실제로 바뀌는 변수를 짧게 대조한다. 한 변수에서 다른 변수로 이동했다면 연결 근거를 요구한다. 상관 가능성과 동일한 의미를 구분한다. 내부 사고 전체를 출력할 필요는 없으며 검증 가능한 근거와 판단 요약을 남긴다.

서로 다른 처방으로 이어지는 해석이 실제로 존재하고 입력으로 구별할 수 없다면, 그 처방만 보류하고 차이를 가르는 질문 하나를 한다. 해석 수를 채우거나 확정된 내용을 다시 묻지 않는다. 모호하지 않은 부분은 계속 처리한다.

## 3. 다섯 전문 관점과 서로 다른 검토 방식

이는 검토 역할이지 실제 학위·경력이나 서로 독립적인 인간 전문가를 주장하는 명칭이 아니다. 역할의 말투를 연기하지 않는다.

| 역할 | 주 검토 방식 | 해야 할 검사 |
|---|---|---|
| 금기·혐오·잔혹성 이론 비평 | 숨은 전제 추출 | 작성자가 정상성·신체·욕망·존엄에 대해 당연하게 보호하거나 강제하는 전제를 원문에서 찾는다. 잔혹함에 교훈·기능을 요구하는 가정도 검사한다. 강도와 다양성을 혼동하지 않는다. |
| 서사학 연구 비평 | 인과 역추적 | 장면·관계·결과에서 출발해 그것을 강제한 설정과 작성 규칙까지 거슬러 간다. 원작 관찰→해석→의무화의 근거가 끊긴 곳을 찾는다. 결말의 예측 가능성을 자동 결함으로 삼지 않는다. |
| 일본 미소녀 캐릭터·게임 문법 비평 | 원작 사례 대조 | 관련된 실제 사례와 대상의 역할·행위·선택을 대조한다. 여성 비율·매력·성적 접근·서약·호감도·관계망을 구분한다. 근거가 없으면 작품 고유 판정을 유보한다. |
| 초현실·부조리·기괴소설 비평 | 반례 탐색 | 초안과 작성 규칙의 보편 명제를 깨는 반례를 찾는다. 현실적인 심리가 유일한 기준인지, 세계 내부 조건에서도 성립하지 않는지 구분한다. 규칙을 깨기 위한 무작위 기벽을 처방하지 않는다. |
| 레퍼런스 각색·편집 비평 | 작품명 치환·적용 범위 검사 | 원작 특유라고 주장하는 비평의 작품명을 치환한다. 내용이 그대로면 특수성 근거를 재요구한다. 일부 특징의 전원 의무화와 서식에 의한 획일화도 검사한다. |

주 검토 방식은 역할 간 동질화를 줄이기 위한 작업 분담이다. 한 방식을 따르느라 사실·사용자 조건을 무시하지 않는다. 각 역할의 산출물을 먼저 고정한 뒤 합친다. 역할별 지적 개수는 강제하지 않는다.

### 비평 세션에 전달할 실행문

> 패킷의 USER와 SOURCE를 구분하고 TARGET을 검토하라. 지정된 전문 관점과 주 검토 방식을 사용하라. 작성자의 의도를 변호하거나 설정을 새로 쓰지 마라. 각 지적은 대상 위치·근거 발췌·숨은 가정·영향·철회 조건을 가진다. 원작 특유의 주장은 구체 사례로 뒷받침하라. 원안과 충돌한다는 이유만으로 비평을 철회하지 말고, 근거 없는 지적은 버려라. 발견한 문제가 없으면 없음으로 보고하라. 다른 비평의 결론은 입력으로 받지 마라. 출력은 지적 목록과 근거 부족 항목뿐이다. 파일 수정 권한은 없다.

작성 세션 → 사용자 개설의 별도 비평 세션들 → 통합 평가 → 사용자 변경안 검사 → 수정 세션 순서다. 프로젝트의 별도 세션 원칙과 소유권을 유지한다. 세션 생성·메시지 전달·서브에이전트 호출은 이 문서로 자동 허가되지 않는다.

별도 컨텍스트가 없으면 `SAME_CONTEXT`로 표시한 예비 검토는 가능하다. 다섯 역할을 독립 검증으로 세거나 과거 작성 이력이 제거됐다고 주장하지 않는다. 독립 실행 여부는 세션 식별자·입력 패킷 버전으로 기록한다.

## 4. 통합 평가

각 지적의 기록: `id / 관점 / 대상 위치 / 근거 / 관찰인지 해석인지 / 숨은 가정 / 영향 / 철회 조건 / 관련 축`.

1. 근거 검사: 사실 오독·사용자 조건 위반·근거 없는 처방은 제외한다. '정상적인 사람이라면' 같은 상식도 검증 대상 가정이다.
2. 혼동 검사: 지적과 처방이 서로 다른 축으로 이동하지 않는지 확인한다.
3. 특수성 검사: 원작 특유라는 주장에만 작품명 치환을 적용한다. 일반적인 논리 모순·사용자 지시 위반·소유권 위반은 치환 후에도 유효하다. 프로그램의 문자열 치환은 의미 판정의 증거가 아니다.
4. 의미 중복 검사: 같은 대상·가정·문제를 지적하면 표현이 달라도 묶는다. 역할 수와 관계없이 동일 입력 오류에 기대고 있으면 공동 오답이다.
5. `COMMON`은 근거 있는 공통 결함, `UNIQUE/MINORITY`는 고유·소수 지적, `UNSUPPORTED`는 탈락으로 보존한다. 각 원 지적의 ID를 유지한다. 빈도는 진실성이나 중요도 점수가 아니다.

사용자 보고는 살아남은 고유·소수 지적을 중심으로 `문제 위치 / 숨은 가정 / 영향 / 철회 조건`만 간결하게 낸다. 공통 결함은 내부에 보존하고 중복 설명은 생략한다. 사용자 판단이나 진행을 막는 공통 결함은 짧게 별도 표시한다. 보고할 고유 지적이 없으면 없다고 한다.

## 5. 변경과 다시 쓰기

채택된 지적 → 구체 변경안 → 사용자 검사 → 해당 소유자의 수정 순서다. 비평 절차·도구 설치의 승인은 콘텐츠 변경의 승인이 아니다. 기존 사용자 승인이나 명확한 수정 지시가 있으면 그 범위의 승인을 재요청하지 않는다.

수정 세션에는 채택된 지적, 승인된 변경 범위, 필요한 정본과 연결 계약을 전달한다. 탈락 비평이나 작성자의 방어 논리를 다시 섞지 않는다. 공통 지도와 사건 연결을 선행하고 지역·인물을 독립 집필하는 기존 규칙을 유지한다. 일반 절차는 특정 세계 법칙·인물 수·비극·호감 장면을 새로 의무화하지 않는다.

## 6. 회귀평가와 완료 증거

[평가 안내](critical_review/EVALUATION.md)와 [시험 사례](critical_review/eval_cases.jsonl)를 사용한다. 시험은 답변 문구가 아니라 금지된 추론과 권한 위반을 검사한다. 명확한 지시까지 보류하는 과잉 차단도 실패다.

변경 전후에 같은 입력과 같은 모델 설정으로 실제 답변을 생성하고, 독립 평가자가 입력·답변·판정 기준을 대조한다. 평가 기준은 응답 생성자에게 주지 않는다. 표현 변형은 별도 컨텍스트에서 실행하고 사례별 원문 답변을 보존한다. 동일 컨텍스트의 자가 점검과 과거 대화의 사후 평가는 통제된 전후 비교가 아니다.

도구 검증은 JSON 형식·누락·판정 근거·집계만 확인한다. 의미 판정과 모델 호출을 수행했다고 주장하지 않는다. 독립 실행 결과가 없으면 효과는 `NOT_RUN`이다. 준비된 문서·시험 수를 행동 개선의 증거로 보고하지 않는다.
