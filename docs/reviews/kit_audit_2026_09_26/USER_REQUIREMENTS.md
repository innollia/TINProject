# 이번 검수에 적용한 사용자 요구사항

기준: 2026-09-26 이 검수 대화에서 사용자가 다시 제공한 다른 작업 대화의 원문. 이 문서는 그 지시의 적용 범위를 정리한 검수 입력이며, 새 Kit 계획이나 기존 작업자의 정본을 대체하지 않는다.

## 1. 대상과 판정 방식

대상은 신규 3-Kit 라운드의 Rain World / Mosa Lina / Swallow the Sea 계열, 별도 Stone Story RPG Kit, BLACK SOULS 2 기반 쯔꾸르라이크 Kit의 다섯 개다. Rule Rewrite, Odd Road, Golden Idol 및 Retired Prototype은 이번 개별 보완 문서의 대상이 아니다.

- 목적은 한시적 무료 모델에 많은 코드 작업을 독립적으로 맡겨 실제 플레이 가능한 결과를 만드는 것이다. 병렬 제작과 범용 절차 비주얼 구현은 명시된 작업 방식이다.
- 사용자는 앞서 제기됐던 충돌을 무시하고 진행하라고 했다. 과거의 순차 Kit 구현 규칙, 공유 기능 선행 금지, 루트 `GRILLING_STATE.md`의 오래된 상태로 현재 작업을 중단시키는 권고를 하지 않는다.
- 각 계획은 구현자가 적힌 것만 만들어도 충분하도록 세부 동작, 데이터, 입력, 실패·복귀, 콘텐츠, 표현까지 구체적이어야 한다.
- 실제 누락과 내부 모순은 검수한다. 특히 없는 API, 연결되지 않은 행동, 충족 불가능한 완료조건은 과거 규정 충돌과 구별한다.
- 제작 중인 파일의 부재를 완료 주장 뒤의 회귀로 단정하지 않는다. `확인된 기능 결함`, `계획의 빈틈`, `작업 중 미구현`, `미검증`을 구분한다.
- 외부 게임의 실제 장면/UI 자료를 임의로 추정하지 않는다. 이번 작업은 보완 문서 작성이며 이미지 생성·편집 요청이 아니다.

## 2. 신규 세 Kit의 공통 요구

- Rain World 조사, Mosa Lina 조사, Swallow the Sea 유사 개발을 각각 진행해 세 Kit 모두 실제 플레이 가능하게 만든다.
- 이상한 나라의 앨리스를 포스트아포칼립스적으로 재해석한 세계관을 사용한다. 세계관 문서도 충분히 방대하게 작성한다.
- 이미지와 스프라이트 제작을 Procedural Generation으로 대체한다. 절차적 애니메이션을 구현하고, 배경에도 물리 반응과 말랑한 움직임을 적용한다.
- 세 Kit가 사용할 범용 절차 비주얼 기능을 만든다. 이 지시는 플레이 맵까지 자동 생성하라는 의미가 아니다. Kit별 지형·레벨 저작 방식과 시각 자산 생성 방식을 분리해서 검수한다.
- 소리 도구의 최종 선택은 **nkido**다. 초기 `strudel.cc` 언급보다 이 결정을 우선한다. 상황별 소리 에셋을 미리 생성하고 세 Kit의 필요한 상황에 연결한다.
- 실제 게임 장면과 UI 레퍼런스 이미지는 사용자에게 요청한다. 새 계획이나 제작 코드에 필요한 자료와 이미 받은 자료를 구분한다.
- 상태 문서는 각 Kit 관련 `docs/research/` 내부에서 관리한다. 여러 작업이 공유하는 루트 `GRILLING_STATE.md`를 이 라운드가 임의로 덮어쓰지 않는다.

### Rain World 계열에서 특히 고정된 것

- 기본 Rain World 범위이며 Downpour / Watcher는 제외한다.
- 사이드뷰, 이미 저작된 맵을 탐험하는 구조다.
- 카르마 및 그와 유사한 누적 수치 관문은 전부 제외한다. 단순하면서 세련된 별도 체계가 필요하다.
- 상시 HUD, 인벤토리 UI, 거래 UI가 없다.
- 로딩·사망·잠 화면은 중앙 일러스트와 우하단 버튼 몇 개가 기준이다. 일러스트도 공통 절차 비주얼 요구 안에서 제작한다.

## 3. Stone Story RPG — 독립 슬롯

- 별도 새 Kit이며 BLACK SOULS 2 Kit를 대체하지 않는다.
- Kit 내부 소유 범위에서 작업한다. 허용된 AppRoot 등록은 유지하며 되돌리는 것을 보완점으로 제안하지 않는다.
- Primary Reference는 Stone Story RPG, 시스템 확장은 Dark Souls 3, 분위기·스토리·내용은 Ena: Dream BBQ다.
- **Stone Story RPG 구조를 먼저 구축한 뒤 Dark Souls 계열 보강을 얹는다.** 다른 게임의 장르 문법이 기본 구조를 대신하는지 점검한다.
- 완료 기준은 사용자가 지정한 **Stone Story RPG 규모**다. 공통 10분 Reference Game으로 완료 범위를 축소하지 않는다.
- 자료조사는 사용자가 맡는다. 제공된 자료로 계획을 진행하되 없는 자료를 에이전트가 외부 조사나 기억으로 채우지 않는다.
- 모든 이미지 작업을 코드 기반 절차 생성·애니메이션으로 대체한다. **ASCII 표현은 금지**한다.
- 속성은 단순 물/불/돌 대신 Dark Souls 계열 방향을 사용한다. 원작의 판정과 수치를 완전히 복사하는 요구가 아니다.
- 어펙스 기호는 무기 강화로 달라진 내용을 나타낸다.
- 목표 화면비는 16:9다. 사용자 원문에 포함된 Rain World 해상도·스케일링 설명은 제공 자료로 취급한다. 그것만으로 이 Kit의 특정 내부 해상도나 렌더 구현이 승인됐다고 단정하지 않는다.

## 4. BLACK SOULS 2 기반 쯔꾸르라이크

- BLACK SOULS 2가 가장 중요한 Primary Reference이며 **분량까지** 기준이다. 한 보스·한 지역·10분 시연으로 전체 요구를 닫지 않는다.
- 스토리, 캐릭터, 적 디자인의 범용 규칙을 추출해 독자 콘텐츠를 만든다. 이 Kit에서는 **앨리스를 완전히 제외**한다. 신규 3-Kit의 앨리스 세계관과 섞지 않는다.
- 계획은 여러 파일로 나누며 콘텐츠·스토리를 특히 상세히 작성한다.
- 큰 지도를 먼저 만들고 위치별 정보를 구체화한다. 지역별 전체 정보, 캐릭터 외형·대사·갖가지 상호작용, 복잡한 연결 흐름까지 독립 구현 가능한 수준으로 정한다.
- 여러 orthogonal axis와 서로 다른 pressure clock, 분기별 많은 NPC 상호작용 덩어리를 요구한다.
- Absurdist comedy / Political absurdism이 핵심이다. 전형적인 상황, 얕은 기괴함, 이름만 바꾼 반복 콘텐츠를 피할 명확한 뒤틀림 규칙이 필요하다.
- 사용자 메모는 정본이 아니라 문장 단위 아이디어 원천이다. 독립 아이디어 최소 60%를 변형해 활용한다. 특정 캐릭터의 대사 한 번에 사용하는 것도 허용되므로 모든 seed를 별도 퀘스트로 늘리지 않는다.
- Romance / affection / body horror는 허용한다. 성적 성인 콘텐츠는 제외한다.
- 사용자 A~H 자료가 나타내는 NPC 선택지, 극단 선택의 빨간 글씨, 전투 명령, 적의 다음 공격 시간, 문서·사건 결과를 실제 구현과 연결해 검수한다.
- `godot-jrpg`는 검토 후 적합하면 사용할 수 있는 후보이며 필수 의존성이 아니다.
- 계획의 분량과 실제 플레이 콘텐츠 사이에 큰 축소가 생기지 않는 것이 주요 검수 항목이다.

## 5. 이번 검수 산출물의 경계

검수자는 새 문서만 추가한다. 기존 소스·콘텐츠·계획·작업 상태를 대신 수정하거나 작업 중인 에이전트에게 새 구현을 지시하지 않는다. 이 문서들의 보완 항목은 기존 요구를 구체적인 수정·검증 과제로 연결하며 새로운 장르 기능을 추가하는 요청이 아니다.
