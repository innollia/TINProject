# 뭉탱이 상태 스토어 — 설계 결정 (2026-09-26)

Owner **W0**. 경로 `core/worldstate/**`.

## 0. 문제

세 Kit은 `ModuleHost`에 하나씩만 올라간다. 모듈은 서로를 모른다. 그러므로 각 Kit이 자기 저장을 쓰면 **결과적으로 3개 게임**이 된다. 프로젝트의 1급 요구(같은 장소가 다른 장르 문법으로 바뀌는 경험)가 깨진다.

해법은 `PROJECT_DECISIONS.md` §14에 이미 정해져 있다: **뭉탱이가 하나의 원본을 소유하고, 각 Kit가 필요한 부분을 사용한다.** 그 원본이 이다.

## 1. axiom

> **세 Kit의 저장은 원본이 아니다. 원본은 여기 있고, Kit는 뷰만 갖는다.**

- 이 스토어는 **3개 축**만 가진다. 축은 늘리지 않는다.
- 모듈은 축을 **읽고**, 쓰기는 **요청**한다. 판정은 이 스토어가 한다.
- 모듈끼리 직접 참조하는 경로는 **존재하지 않는다.** 이 스토어도 예외가 아니다.
- **값은 절대 정규화하지 않는다.** (§4)
- `body` 축은 **확정 사실과 가변 능력을 섞지 않는다.** (§2.1.1) `body.scale` 은 닫힌 6단 사다리 값이다. (§2.1.2)

## 2. 세 축

| 축 | 정체 | 소유 | 런타임 쓰기 |
|---|---|---|---|
| `body` | 플레이어 몸 | sideview_ecosystem | 그 Kit만 |
| `creature` | 개체 개인 상태 | sideview_ecosystem | 그 Kit만 |
| `place` | 장소 지형 | authoring(런타임 읽기 전용) | 없음 |

### 2.1 `body` — 몸

신체 상태의 집합. Keyrain·크기·부재·상처가 전부 **그냥 값**이다. 파생 상태를 저장하지 않는다. 상처는 `{ part, kind, severity, permanent }` 같은 **관측 가능한 사실**로만 저장한다. "체력 3/5" 같은 요약값을 저장하지 않는다.

Kit A가 팔 하나를 영구히 잃으면 `body.missing`에 사실이 쌓인다. 다른 Kit은 그 사실을 **자기 물리 규칙으로 해석**한다. 1개 팔로 화물을 들 수 있는가, 수영 부력이 다른가. 그 해석은 각 Kit의 몫이다.

### 2.1.1 몸 필드는 두 부류다 — 확정 사실과 가변 능력

몸 축의 필드는 두 부류로 나뉜다. **둘을 섞지 않는다.**

| 부류 | 정체 | 필드 | 되돌아가는가 |
|---|---|---|---|
| **확정 사실** (진행 축) | 이미 일어난 일. 잃은 부위, 흉터, 잃은 감각 | `missing`, `wounds` | **아니오** |
| **가변 능력** (능력 축) | 지금 이 몸이 무엇을 하는가. 현재는 `scale` 하나 | `scale` | **예** |
| 판정 불가 | Kit 이 자기 기준으로 적은 관측값 | `facts` | 스토어의 일이 아니다 |

규칙은 세 개다.

1. **기록된 확정 사실은 지워지지 않는다.** 새 값이 이미 기록된 사실을 담고 있지 않으면 그 요청은 `body_fact_is_permanent` 로 거절된다. 비워 넣는 것도 목록을 갈아끼우는 것도 그 사실을 지우는 것이다. 기록된 사실이 애초에 없는 필드를 빈 값으로 쓰는 것은 지우는 것이 아니다 — 그건 "없음"과 "아무것도 없음"의 차이이고, `§4` 가 지키는 그것이다.
2. **가변 능력은 되돌아간다.** `scale` 은 몇 번을 오가도 그 값 그 자체로 남는다. 되돌릴 수 있다는 것은 **저장하지 않아도 된다는 뜻이 아니다.** 현재 크기는 `body` 축에 저장하고 세이브/로드가 복원한다. 가역성은 저장 면제를 만들지 않는다.
3. **두 부류를 서로의 증거로 쓰지 않는다.** 가변 능력을 진행 게이트로 쓰지 않고, 확정 사실을 장비처럼 다루지 않는다. 스토어는 한 부류를 다른 부류에서 파생하지 않는다. `requires_body` 는 능력 조건만 받고(`§2.3`) 누적값·권한 계열 이름은 `requires_body_not_capability` 로 거절된다. 어떤 Kit 이 현재 크기를 자기 통행 스택으로 써도 그것은 그 Kit 의 해석이고 스토어의 판정이 아니다.

이 구분은 세계관 헌법의 **"몸의 변화는 일방이 아니다"** 라는 불변식이 그대로 성립한다는 사실에서 나온다. `scale` 이 가역이므로 그 필드에 예외 규칙이 필요 없다. 단, **가역성이 임의 복원을 허락하지는 않는다** — 되돌릴 수 있는 것은 되돌릴 수 있을 뿐이고, 저장되는 값의 영역은 닫혀 있다(`§2.1.2`).

`facts` 를 어느 부류에도 넣지 않는 것은 회피가 아니다. 확정 사실이라 부르면 Kit 이 자기 관측값을 다시 쓸 수 없게 되고, 가변 능력이라 부르면 관측값이 통과 조건으로 들어간다. 스토어는 `{"facts": {"lift": 200}}` 이 관측인지 요약인지 구분하지 못한다(`§4`). 그래서 정직한 답은 "다룰 수 없다"이고 그 필드는 두 부류 어느 쪽에도 들어가지 않는다.

### 2.1.2 `body.scale` 은 닫힌 6단 사다리다

```
speck 0.05 · hand 0.12 · doll 0.28 · common 0.65 · tall 1.50 · colossal 3.60
```

- **`body.scale` 은 위 여섯 값 중 하나여야 한다.** 그 외의 수는 거절된다.
- **`1.0` 은 사다리 값이 아니다.** "정상 크기"로 읽히기 때문에 금지한다. 붕괴한 세계에 기준 크기가 있다는 belief 가 생길 자리다. 그래서 `1.0` 거절에는 다른 거절 사유와 다른 이름을 붙인다.
- **가장 가까운 값으로 눌러 맞추지 않는다.** `0.9` 를 `common` 으로, `1.49` 를 `tall` 으로 옮기는 것은 정규화다(`§4`). 사다리 밖의 값은 그대로 **거절**된다.
- **이 금지는 몸 축의 최상위 `scale` 필드에만 걸린다.** 상처의 `severity`, `missing` 의 항목, `facts` 안의 관측값, 요구조건의 `scale_min` 임계값은 다른 문제다. 그 자리에 `1.0` 을 금지하는 것은 이 규칙이 아니다.
- **연속 실수가 금지되는 이유.** "지금 몇 배"가 화면에 읽히면 크기가 수치 문법으로 읽힌다. 요구조건은 경계선이어야 하는데 연속 실수는 경계선을 흐린다. 사다리는 값의 개수를 닫아 판정을 유한하게 만들고, 어느 Kit 도 자기 숫자 체계를 새로 만들지 못하게 한다.
- rung **이름**은 저장하지 않는다. 값이 진실이고 이름은 파생 라벨이다. 두 번째 상태로 저장하면 중복 상태가 된다.

닫힌 값 집합은 **값의 영역을 닫는 것**이고 정규화가 아니다. 정규화는 값을 바꾼다는 뜻이고, 여기서는 저장된 값이 한 비트도 바뀌지 않는다. 사다리 밖의 수는 이 축이 받아들이지 않는 값이다. 여섯 값과 인덱스는 `docs/scale_collapse/01_SCALE_ALGEBRA.md` §1 의 표와 같다. 다만 그 문서의 판정 위치는 여기와 다르며, 그 충돌은 §8 에 남긴다.

### 2.2 `creature` — 개체

개체는 **ID로 고정된 개인**이다. (Rain World의 den/ID 규칙을 그대로 쓴다 — 같은 시드에서 같은 개인이 같은 성격으로 나온다.)

```
creature = {
  id: String              # 전역 유일. 이 라운드에서 유일.
  archetype: String       # 종/유형. 생성자가 정한다.
  stage: int              # lineage 단계
  state: String           # 살아있음/사망 등 authored 값
  traits: Dictionary      # 성격·공포·욕구 등 난수에서 고정된 것
  memory: Array[Dictionary]  # 이 개체가 기억하는 사건 목록. 숫자 점수가 아니다.
  den: String             # 은신처 장소 id
}
```

`memory`는 **점수판이 아니다.** "이 몸이 세 번 죽었다"가 아니라 "이 몸이 ���한 사건들"의 목록이다. 수치는 개체가 **스스로 세는 것**이지 스토어가 계산하지 않는다.

### 2.3 `place` — 장소

authored 지형. 세 Kit이 **같은 place id**를 자기 카메라·스케일로 렌더한다. 지형 데이터 자체는 authored content 파일에 있고, 스토어는 어떤 장소가 어디에 붙어 있는지와 현재 상태(포커스 여부 등)만 들고 있다.

```
place = { id, region_id, tags: Array[String], requires_body: Dictionary }
```

`requires_body`는 그 장소가 요구하는 **몸 조건**이다. 권한 게이트가 아니라 능력 조건이다. (카르마식 임계값 금지)

## 3. 인계 규칙

모듈 교체 시 `ModuleContext.arrival`을 통해 이 스토어의 **읽기 전용 뷰**가 전달된다.

| 규칙 | 내용 |
|---|---|
| 전달 방식 | 값 복사가 아니라 **참조**. 모듈은 스토어의 뷰를 받아 읽기만 한다. |
| 쓰기 | 모듈은 `request_mutation(axis, patch)`를 호출한다. 스토어가 축별 규칙으로 **수용 또는 거부**하고, 거부 사유를 돌려준다. |
|拒绝의 근거 | 축 소유자가 요구 조건을 정의한다. 예: `place` 쓰기는 항상 거부(런타임에서 지형은 불변). |
| 모듈 격리 | 축 소유 Kit이 **로드되어 있지 않아도** 판정된다. 판정은 이 스토어가 하므로, 소유 Kit의 부재와 무관하다. |
| 생성 직렬화 | 축 값은 전부 JSON-safe다. 픽셀·절대 경로·노드 참조를 넣지 않는다. |

## 4. 정규화 금지 (하드 규칙)

`PROJECT_DECISIONS.md` §14의 기준 사례를 그대로 규칙으로 쓴다.

- 체력 200인 몸이 통상 1~3 문법 구간에 들어와 피해 1을 받으면 **199**다. 1~3으로 환산하지 않는다.
- 单位 변환 금지. 크기·무게·시간을 다른 축으로 옮겨 적지 않는다.
- 값이 없을 때 **모듈이 임의 기본값을 만들지 않는다.** 축은 "없음"을 유지하고, 모듈은 "없음"으로 처리하거나 그 행동을 멈춘다.
- 이미 아는 해법은 상태로 강제하지 않는다. (플레이어 머릿속 지식은 별도 축이 아니다)

## 5. 세 축이 한 장면에서 엮이는 방식

아래는 **계약이 실제로 쓰이는 모양**을 고정하기 위한 예시다. 수치는 개방이고, 각 Kit 계획서가 확정한다.

### 장면 A — 폐 정원 (`place.ruined_garden`)

세 축을 동시에 읽는 장면. 이 한 장면이 "1개 게임"인지 "3개 게임"인지를 가른다.

- `place` : 정원은 authored 지형 하나. Kit A는 사이드뷰로, Kit B는 2D 플랫폼 축으로, Kit C는 하강 축으로 **같은 좌표에서** 그린다.
- `creature` : 정원에 `id = fix.gardener` 개인이 산다. Kit A에서 죽었다면 그 사실이 축에 남고, Kit C에서도 **죽은 개체**로 나타난다. Kit C는 그 개체를 자기 방식으로(시체/잔해/조용한 빈자리 중 하나로) 표현한다.
- `body` : Kit A에서 잃은 팔이 Kit B에서는 화물 운반 능력, Kit C에서는 부력을 바꾼다. **어느 Kit도 이를 정규화하지 않는다.**

**이 장면의 판정 테스트:** `place.ruined_garden`에 `body.missing`이 있는 상태로 세 Kit을 차례로 들어가, 그 사실이 세 번 모두 살아있음을 단언한다.

### 장면 B — 다과 계단 (`place.tea_stair`)

- `body` : 계단 통과는 **몸 스케일**을 요구한다. 스케일은 상수가 아니라 `body.scale` 값이다.
- `creature` : 경비 개체(`id = fix.butler`)가 요구하는 것은 숫자 신분이 아니라 **메모리에 있는 사건들**이다. "이 몸이 한 일"이 통과를 바꾼다.
- `place` : 계단은 `requires_body = { scale_min: 0.7 }` 같은 **능력 조건**만 가진다.

### 장면 C — 바로크 가면 (`place.mirror_march`)

세 축이 동시에 개입하는 전환 지점.

- `body` : 통과에 특정 상처 상태를 요구한다. 상처는 요약값이 아니라 `{ part, kind, severity, permanent }` 사실이어야 한다.
- `creature` : 가면 안의 개체는 Kit A의 축을 읽되 자기 몸으로 재현한다.
- `place` : 한 장면이 두 장르 문법을 동시에 보여주는 지점.

## 7. 저장 소유

- 세 Kit의 세이브는 **뷰**다. 원본은 이 스토어의 세이브 한 벌이다.
- 세 Kit 각각이 자기 버전을 가지되, 이 스토어가 `ax` 버전을 따로 들고 셋을 정합시킨다.
- 복원 실패는 조용히 기본값으로 덮지 않는다. **정직한 실패**를 낸다.

## 8. 미결 (W0가 나중에 확정)

- 축 증가 금지. `resource` 같은 축이 필요해 보이면 **먼저 Kit 안에서** 해결하고, 두 번째 실제 사용처가 확인될 때만 여기를 건드린다.
- 세 장면의 수치·크리처 ID는 Kit 계획서가 확정한다.
- **사다리 판정의 위치 (§2.1.2).** 여기서는 스토어가 사다리 밖의 `scale` 을 거절한다. `docs/scale_collapse/01_SCALE_ALGEBRA.md` §2.2 는 "몸의 scale 이 `0.13` 일 수 있다", §4 K6 은 "Kit 이 `body.scale = 1.0` 을 쓰면 스토어는 그대로 `1.0` 을 저장한다. 정직한 실패다", §7 은 "이 사양이 `core/worldstate` 에 요구하는 것: 없다"고 적는다. 같은 값 목록을 공유하면서 **판정 위치가 정반대**다. W0 가 어느 쪽을 정본으로 정하느냐에 따라 `core/worldstate/tests/` 의 기존 스케일 픽스처가 통째로 다시 쓰여야 한다. 지금 구현은 스토어가 거절하는 쪽이다.
- **`facts` 의 부류 (§2.1.1).** `facts` 는 두 부류 어디에도 들어가지 않는다. 그 결과 ① Kit 이 자기 관측값을 다시 쓸 수 있고 ② 관측값이 통과 조건으로 쓰이지 않는다. 남은 구멍은 `facts["scale"]` 이다. 거기에 rung 이 아닌 크기를 적으면 사다리 규칙을 우회한 두 번째 통로가 열린다. 스토어가 이것을 거절할지 Kit 계획서가 금지할지 W0 가 정한다.
