# at-icons Inkscape 조립 워크플로

## 1. 목적

이 문서는 `res://addons/at-icons/`의 실제 SVG 원본을 Inkscape에서 조립해 월드 에셋을 실험하는 절차를 정한다.

목표는 미리 고른 아이콘 묶음을 정렬하는 것이 아니다. 현재 실루엣을 보고 다음에 필요한 조각을 전체 라이브러리에서 선택하며 형태를 발전시키는 것이다.

## 2. 절대 경계

- 생성형 이미지 제작과 편집을 사용하지 않는다.
- `image_gen`, GPT Image, 외부 생성형 이미지 API를 호출하지 않는다.
- 코드로 완성 SVG나 래스터 아트를 생성하지 않는다.
- 사용자가 제공한 레퍼런스 이미지는 읽기 전용이다.
- at-icons 원본 파일을 덮어쓰지 않는다.
- Inkscape 접근 실패나 Computer Use 오류를 다른 이미지 생성 방식으로 우회하지 않는다.
- 편집기를 제어할 수 없으면 중단하고 실패 지점을 보고한다.

`tools/build_at_icons_inkscape_symbols.ps1`은 기존 SVG를 변형 없이 Inkscape 심볼 컨테이너로 묶는 설치 도구다. 이 도구를 에셋 형상 생성에 사용하지 않는다.

## 3. Inkscape 진입 경로

로컬 편집기는 Computer Use 플러그인의 `@oai/sky` 연결로만 제어한다.

`mcp__node_repl__js`에서 최초 한 번 초기화한다.

```javascript
if (!globalThis.sky) {
  const { sky } = await import("@oai/sky");
  globalThis.sky = sky;
}
```

그다음 아래 순서를 따른다.

1. `sky.list_apps()`로 실행 중인 앱을 읽는다.
2. `displayName === "Inkscape"`인 항목에서 대상 창의 `app`, `id`, `title`을 얻는다.
3. `sky.get_window({ app, id, title })`로 창을 가져온다.
4. `sky.activate_window({ window })`로 Inkscape를 전면에 둔다.
5. `sky.get_window_state({ window, include_screenshot: true, include_text: true })`로 화면을 확인한다.
6. 좌표 입력 직전마다 새 화면 상태를 얻는다. 이전 스크린샷 좌표를 재사용하지 않는다.
7. 클릭, 드래그, 키 입력 뒤에는 다시 화면을 읽고 결과를 확인한다.

앱이 목록에 없거나 창을 활성화할 수 없으면 그 상태에서 멈춘다.

## 4. 심볼 라이브러리

사용하는 원본 세트는 `addons/at-icons/node2d/`의 618개다.

나머지 다섯 폴더는 같은 도형의 Godot 노드 분류별 색상 변형이므로 별도 심볼 세트로 사용하지 않는다. 색은 조립 과정에서 목적에 맞게 변경한다.

프로젝트 보관본:

`assets/shared_art_study/inkscape_symbols/tin-at-icons-node2d.svg`

Inkscape 설치 위치:

`%APPDATA%/inkscape/symbols/tin-at-icons-node2d.svg`

재설치가 필요하면 프로젝트 루트에서 다음을 실행한다.

```powershell
& '.\tools\build_at_icons_inkscape_symbols.ps1'
```

Inkscape의 `Object > Symbols`에서 `tin at icons node2d`를 선택한다.

## 5. 조립 방식

### 금지하는 시작 방식

- 대상별 아이콘 풀을 미리 확정
- 후보 아이콘을 전부 캔버스에 배치
- 전체 개수를 먼저 채운 뒤 한 번에 재정렬
- 규칙적인 행과 열을 만든 뒤 완성으로 간주
- 저·중·고 조합안을 동시에 원샷 제작

### 기본 반복

1. 빈 작업 사본에서 대상과 지금 풀 형태 문제를 한 문장으로 적는다.
2. Symbols 패널에서 구조용 조각 1~3개를 고른다. 원본 이름과 도상이 대상에서 맡을 역할과 같으면 배치 전에 제외한다. `tree`로 나무 몸체, `leaf`로 나뭇잎을 만드는 방식은 시작부터 무효다.
3. 배치 후 전체 실루엣을 확인한다. 첫 조각을 원래 pictogram 의미로 읽게 되면 즉시 교체한다.
4. 남은 문제를 한 문장으로 기록한다. 예: `줄기 방향은 읽히지만 수관 무게가 없다.`
5. 그 문제에 필요한 조각 1~4개만 전체 Symbols 패널에서 찾아 추가한다. `plant` 같은 이름 검색에 결과가 없다는 이유로 라이브러리에 쓸 형태가 없다고 결론 내리지 않는다.
6. 배치, 회전, 미러, 가로·세로 비율 조절, 색 전환, 겹침을 적용한다. 원본 심볼의 일부를 잘라내거나 크롭·클리핑·마스킹하지 않는다.
7. 다시 화면을 확인하고 실루엣의 무엇이 바뀌었는지 적는다. 기존 문제가 해결되지 않았으면 그 조작을 취소하고 다른 구조를 시험한다. 세부 한 조각만 손본 결과를 다음 단계나 후보로 승격하지 않는다.
8. 한 조각의 이동·회전·색 변경이 5분 넘게 걸리거나 두 번 재시도해도 형태가 개선되지 않으면 그 조작을 중단한다. 편집기 병목을 기록하고 다른 구조를 시험한다. 실루엣이 개선되는 동안에만 4~7을 반복한다.

아이콘 수는 목표가 아니라 결과다. 같은 기호 반복이 효과적이면 반복 사용한다.

## 6. 단계별 저장

의미 있는 판단 지점마다 별도 사본을 저장한다.

- `01_structure`: 최소 구조가 읽히는 단계
- `02_mass`: 덩어리와 실루엣을 보강한 단계
- `03_features`: 비대칭, 리듬, 표정 또는 기능을 보강한 단계
- `candidate`: 아래 후보 판정 기준과 구조 검사를 통과한 경우에만 저장

`01_structure`를 저장할 때부터 주요 오브젝트는 서로 다른 원본 조각을 조합해야 한다. 단일 대상 아이콘을 확대·색 변경한 결과는 실험 단계로 세지 않는다.

각 단계에는 다음을 기록한다.

- 사용 아이콘 수와 종류 수
- 이번 단계에서 새로 추가한 아이콘
- 해결하려던 시각 문제
- 개선된 점
- 남은 문제
- 대상이 읽히는지와 원본 pictogram 의미가 먼저 보이는지
- 같은 문제를 푸는 데 든 작업과 파츠 교체의 용이성

### 후보 판정

후보는 파일명이나 단계 번호가 아니라 판정 결과다. 다음을 모두 만족해야 `candidate`로 저장한다.

- 목표 대상이 한눈에 읽힌다.
- 원본 pictogram 의미가 대상 의미보다 앞서지 않는다.
- 시도한 방식 가운데 작업이 적고, 수정·파츠 교체가 쉬운 쪽이다.
- 직전 단계와 비교해 해결된 형태 문제가 실제 화면에서 확인된다.

조건을 만족하지 못하면 가장 정보가 많았던 실패 단계를 보존하고, 남은 문제를 기록한다. 이 조합 실험에는 고정된 픽셀 크기별 내보내기 비교를 넣지 않는다.

후보가 될 만한 변화가 있으면 먼저 `candidate_draft.svg`로 저장하고, 직전 단계와 비교하는 읽기 전용 검사를 실행한다. 구조 검사와 실제 화면 판정을 모두 통과한 뒤에만 `candidate.svg`로 저장한다.

```powershell
py -3 tools/check_at_icons_candidate.py --target tree --previous assets/shared_art_study/adaptive_retest/03_features.svg --candidate assets/shared_art_study/adaptive_retest/candidate_tree.svg
```

위 명령은 무효 나무 후보를 거부하는 예다. 새 시도에서는 두 SVG 경로를 새 작업 파일로 바꾼다. `--target`은 `tree`, `bomb`, `rabbit`, `human` 중 하나다. 검사는 그림 내용이 같은 단계 승격, 대상과 이름이 같은 심볼의 문서 내 잔존, 클리핑·마스킹·래스터 삽입을 거부한다. 심볼 정의만 남아 있어도 보수적으로 거부하므로 Inkscape에서 불필요한 정의를 정리한 뒤 다시 검사한다. **검사 통과는 후보 승인이나 시각적 합격이 아니다.** 실루엣, 원본 도상 의미, A·B와의 추상적 방향은 실제 편집기 화면에서 직접 판정한다.

## 7. 캐릭터 파츠 실험

중립 인체와 커스터마이징 파츠는 한 덩어리로 합치지 않는다.

- 머리
- 얼굴
- 몸통
- 팔
- 다리
- 의상 상의
- 의상 하의

각 파츠는 교체 가능한 별도 그룹으로 유지한다. 먼저 몸통·머리·사지의 결합 위치를 검증하고, 이후 얼굴·머리·의상을 한 종류씩 추가한다. 여러 완성 캐릭터를 한 번에 만들지 않는다.

## 8. 보고 기준

과정 보고에는 실제로 확인한 화면만 사용한다.

- `시작함`은 Inkscape 문서를 열었다는 뜻이다.
- `배치함`은 배치 뒤 스크린샷을 다시 확인했다는 뜻이다.
- `저장함`은 Inkscape 제목의 수정 표시가 사라졌거나 저장 상태 메시지를 확인했다는 뜻이다.
- 편집 결과가 부족하면 완성으로 부르지 않고 실패 원인과 다음 반복을 적는다.
