# Jev를 어떻게 쓰나 (측정으로 정한 것)

2026-09-28에 쟀다. 시험지는 형님 디스코드 판단 사건 중 규칙을 만들 때 쓰지 않은 봉인분 80건이다. 결과물 판정은 형님이 캡처·기획에 내린 판정 26건(J01~J32 중 Jev가 답한 것)이다. 채점은 Jev 채점기로 했다. 같은 예측을 LLM 채점기와 Jev 채점기로 매겨 보니 선택 판정 94%, 이유 판정 90%가 같았다.

## 측정

| 방식 | 선택 적중 | 이유 적중 | LLM 호출 |
|---|---|---|---|
| LLM이 형님 기록(규칙 40개, 비슷한 사건 25개)을 읽고 직접 답 | 76% (61/80) | 57% | 건마다 큰 호출 1번 |
| Jev가 주어진 선택지 중 고름 | 64~66% | - | 0 |
| 혼합: 주어진 선택지에서 Jev 확신 0.7 이상이면 Jev, 아니면 LLM | 73% (58/79) | - | 절반(39/79건)만 |
| LLM 답 + 주어진 선택지를 후보로 → Jev가 최종 선택 | 62% (46/74) | - | 건마다 1번 |
| 에이전트가 기록 없이 쓴 후보 4개(조건부 포함) → Jev | 44% (31/71) | 26% | 20건에 1번 |
| 에이전트가 기록 없이 쓴, 딱 잘라 말하는 후보 3~4개 → Jev | 55% (44/80) | 39% | 20건에 1번 |

- Jev 확신도: 방식과 상관없이 0.7 이상이면 약 70%가 맞았고, 0.5 미만이면 34~56%였다. LLM이 스스로 매긴 확신도는 0.5 미만이어도 69%가 맞아 신호가 흐리다.
- LLM 답에 Jev가 동의하지 않을 때도 LLM은 74% 맞았다(동의할 때 75%). Jev의 반대는 LLM 오답 신호가 아니다.
- 결과물 판정: Jev 통과 확률 0.5 기준 81%(전부 퇴짜라고 해도 73%). 퇴짜 18/19를 맞혔고 통과는 3/7만 맞혔다.

## 여기서 나온 규칙

1. 형님 특유의 답을 맞히는 데는 기록을 읽은 LLM이 가장 낫다. Jev는 LLM을 대신하지 못하고, LLM 답을 뒤집는 심판으로 쓰면 오히려 떨어진다.
2. 에이전트가 기록 없이 후보를 쓰고 Jev가 고르게 하면 형님 특유의 답이 후보에 빠지거나 약하게 쓰여서 낮다. 얼버무리는 후보("상황에 따라")가 섞이면 Jev가 그쪽을 고른다. 틀린 판정을 뜯어보니 대부분 이 경우였다.
3. Jev가 잘하는 곳
   - 채점·검수: 예측이 실제와 같은 방향인지, 이유가 핵심을 짚었는지. LLM 채점기와 거의 같고 토큰이 거의 안 든다.
   - 선택지가 주어진 닫힌 질문과 결과물 통과/퇴짜의 1차 판정.
   - 확신도로 길 나누기: 확신이 높으면 Jev 답을 쓰고, 낮으면 LLM이 기록을 읽고 판단하거나 형님께 묻는다. LLM 판단이 절반으로 줄고 적중은 3%p만 준다.
4. 그래서 스킬 흐름은 '후보 → Jev → 확신이 낮으면 에이전트가 기록을 읽고 직접 판단(형님 결정이면 형님께 질문) → 형님 답 기록'이다.

## 아직 안 잰 것

- 에이전트가 형님 기록(`evidence`)을 먼저 읽고 후보를 쓰는 방식. 형님 특유의 답이 후보에 들어갈 가능성이 커진다.
- state를 영어로 번역해 넣는 방식(문서상 영어가 가장 정확하다).
- 결과물 판정은 26건뿐이고 통과가 7건이라 통과 쪽 숫자는 흔들림이 크다.

## 재현

저장소 `tools/avatar_judge/decision/`에서 (모두 LLM 토큰을 거의 안 쓴다)
- `eval_gold.py --regrade v2-llm --grader jev`: 채점기 일치율
- `_pipeline.py jgold jcompare`: Jev가 주어진 선택지에서 고르기
- `_pipeline.py acand2 aeval2 acompare2`: 에이전트 후보 → Jev(후보 생성에만 LLM 호출 4~5번)
- `_pipeline.py mkcand aeval3 aeval4`: LLM 답을 후보에 넣기, 새 state로 선택지 고르기
- `verify_gate.py`: Jev 동의 여부와 LLM 적중
- `eval_verdicts.py`: 결과물 판정
