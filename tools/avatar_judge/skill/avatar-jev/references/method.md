# 분신을 어떻게 쓰나 (측정으로 정한 것)

쓰임: TINProject 게임 개발 AI가 '중요한 결정'이라며 멈췄을 때 형님 대신 고른다. 일상 질문용이 아니다.

## 1. 게임 개발 결정 150건 (2026-09-28, 주 측정)

`decision/harvest_decisions.py`로 TIN 문서(AGENTS.md, PROJECT_DECISIONS.md, Kit 계획·상태 문서, grilling 기록 등 78개)에서 모았다. 모델 호출 11번이 들었다.
- AI가 묻고 형님이 답한 것 83건, 형님이 AI 방향을 바로잡은 것 67건. AI 추천이 기록된 것 54건.
- 판정할 결정 자신과, 낱말이 많이 겹치는 기록(같은 결정이 다른 문서에 적힌 것)은 근거에서 뺐다.
- 선택지는 모델이 문서를 읽고 정리했다. 그래서 선택지 문장에 답이 조금 드러날 수 있다. 형님 기록 없이 일반 게임 디렉터로 고르게 한 대조군이 59%(찍기 40%)인 것이 그 몫이다. 아래 비교는 모두 같은 선택지로 했으므로 차이는 믿을 만하다.

| 조건 | 맞힘 | AI 추천이 기록된 54건 |
|---|---|---|
| 분신, 비슷한 기록 제외(겹침 0.35 이상) | 128/150 (85%) | 분신 89% vs 추천대로 56% |
| 분신, 더 엄격하게 제외(겹침 0.2 이상) | 125/150 (83%) | 분신 83% vs 추천대로 56% |
| 게임 개발 결정 기록을 근거에서 모두 뺌 | 111/150 (74%) | 분신 76% |
| 형님 기록 없이 형님 취향 설명 한 줄만 | 102/150 (68%) | 분신 70% |
| 형님 기록도 설명도 없는 일반 게임 디렉터 | 88/150 (59%) | 63% |
| 찍기 | 40% | |

- 형님 기록이 일반 디렉터 대비 24%p를 올린다(59% → 83%). 가장 큰 몫은 게임 개발 결정 기록(+9%p)과 취향 설명 한 줄(+9%p)이다.
- 확신도(엄격 제외): accept 101건 93%, weak 13건 85%, ask 36건 56%. 3분의 2를 93%로 처리하고, 나머지만 형님께 올리면 된다.
- 추천이 기록된 54건에서 늘 분신 답으로 가면 83%, 분신이 확신할 때만 분신이고 나머지는 추천대로 가면 78%였다. 그래서 확신이 낮아도 분신 답으로 진행하고, 질문만 형님께 올린다.
- 분야별(엄격 제외): creature 91%, visual 89%, reference 87%, workflow 88%, world 82%, production 96%, creative 73%, ui 70%, scope 45%. Kit 범위 결정은 약하다.

재현(모두 Jev만 쓴다): `eval_gamedev.py --name gd1`, `--near 0.2`, `--no-decisions`, `--blind`, `--generic`.

## 2. 디스코드 일상 판단 80건 (참고)

일상 판단(관계·생활·공부 등)에서는 형님 기록을 읽은 LLM이 76%로 가장 나았고, Jev가 주어진 선택지에서 고르면 64~66%였다. 에이전트가 기록 없이 후보를 쓰고 Jev가 고르면 44~55%였다. 얼버무리는 후보("상황에 따라 다르다")가 섞이면 Jev가 그쪽을 과하게 골랐다. 게임 개발 결정은 멈춘 AI가 이미 선택지를 쓰기 때문에 이 문제가 적다.

## 3. Jev가 잘하는 것

- 주어진 선택지에서 고르기: 멈춘 AI의 질문은 선택지가 이미 있어서 가장 잘 맞는다.
- 확신도로 길 나누기: 확신하면 그대로 진행, 아니면 형님께 질문을 올린다.
- 채점·검수: 맞다/틀리다 판정은 LLM 채점기와 선택 94%, 이유 90%가 같았고 토큰이 거의 안 든다.
- 결과물 통과/퇴짜 1차 판정: 26건에서 81%(전부 퇴짜라고 하면 73%). 퇴짜 18/19, 통과 3/7.

## 4. 아직 안 잰 것

- 새로 생기는 결정(문서에 아직 없는 것)에서의 적중. 앞으로 형님이 답할 때마다 `record.py`로 쌓고 다시 잰다.
- 선택지를 모델이 아니라 멈춘 AI가 쓴 원문 그대로 넣었을 때. 채팅 기록 속 실제 질문으로 재면 더 정확하다.
- state를 영어로 번역해 넣는 방식(문서상 영어가 가장 정확하다).
