# avatar-jev: 멈춘 게임 개발 AI 대신 형님 답을 고른다

TIN 작업자 지침은 게임 경험을 바꾸는 선택을 형님께 물으라고 한다. 이 스킬은 그 질문을 형님께 올리기 직전에 돌린다. 분신이 확신하면 그 답으로 계속 진행하고, 확신이 낮을 때만 형님께 올린다.

쓰지 않는 곳: 코드 구조, 파일 배치, 테스트 방법, 수치 튜닝, 버그 수정 방법(AI가 스스로 정한다). 일상 질문.

## 얼마나 맞나 (2026-09-28)

TIN 문서에 남은 게임 개발 결정 150건으로 쟀다. AI가 묻고 형님이 답한 것 83건, 형님이 AI 방향을 바로잡은 것 67건이다. 결정마다 그 결정 자신과 비슷한 기록은 근거에서 뺐다.

| 방법 | 형님 답을 맞힌 비율 |
|---|---|
| 분신(Jev + 형님 기록) | 83% |
| AI 추천대로 진행(추천이 기록된 54건) | 56% (같은 54건에서 분신 83%) |
| 형님 기록 없는 일반 게임 디렉터 | 59% |
| 찍기 | 40% |

분신이 확신한 101건(`gate`가 accept)은 93%가 맞았다. 확신이 낮은 36건(ask)은 56%였다. 자세한 것은 `references/method.md`.

## 준비 (한 번)

1. Python 3.10 이상. 표준 라이브러리만 쓴다.
2. Jev 키: 환경변수 `TYPESAFE_API_KEY`, 없으면 `<데이터 폴더>/raw/jev_key.txt`.
3. 데이터 폴더(형님 기록): 환경변수 `AVATAR_JUDGE_DATA` → 이 폴더의 `data_dir.txt` → 저장소 안이면 자동(`tools/avatar_judge`) → `~/.avatar_judge` 순서로 찾는다.
4. 확인: `python scripts/jevlib.py` → `key ok`, `decision ok`, `data dir` 세 줄이 나오면 된다.

명령은 이 스킬 폴더에서 돌린다. Windows에서 `python`이 안 잡히면 파이썬 전체 경로를 쓴다.

## 절차

1. **멈춘 AI의 질문을 입력 파일로 옮긴다.** 한글이 명령줄에서 깨지지 않게 JSON 파일로 넘긴다.
   ```json
   {"case": "무엇을 정하는지 한 줄. 어느 Kit·작업 중인지. 선택지마다 화면·플레이가 어떻게 달라지는지.",
    "candidates": ["선택지 1 문장 그대로", "선택지 2 문장 그대로", "선택지 3"],
    "recommended": 0}
   ```
   - `candidates`: AI가 쓴 선택지를 그대로 넣는다. "(추천)" 표시와 추천 이유는 빼고, `recommended`에 추천 번호(0부터)만 적는다. 분신이 추천에 끌리지 않게 하려는 것이다.
   - 선택지마다 무엇이 다른지가 문장에 드러나야 한다. "A안", "B안"처럼 이름만 있으면 뜻을 풀어 쓴다.
   - 캡처·에셋 통과/퇴짜면 `"mode": "verdict"`를 넣고, 후보는 형님 말투 한 줄 평으로 쓴다(아래 '후보 쓰는 법').
2. **돌린다.** `python scripts/choose.py case.json` → 같은 폴더에 `case.result.json`. 화면에는 영어 한 줄 요약만 나온다.
3. **`gate`대로 한다.** 어느 경우든 분신이 고른 선택지(`pick`, `answer`)로 작업을 계속한다. 시험에서 분신은 확신이 낮을 때도 AI 추천보다 자주 맞았다.
   - `accept`: 형님께 묻지 않는다. 보고에 한 줄만 남긴다: "분신 판정으로 진행: <answer> (확신 <confidence>)".
   - `weak`: 진행하고, 형님께 "이미 이렇게 진행함" 확인 질문으로 올린다.
   - `ask`: 진행하고, 형님께 번호 붙인 질문으로 올린다. 원래 맥락을 자르지 않는다: 어느 Kit·어느 작업 중인지, 지금까지 한 것, 선택지마다 화면·플레이가 어떻게 달라지는지, 있으면 캡처. 분신이 고른 것, 두 후보의 확률, AI 원래 추천도 함께 적는다. 결과의 `evidence`에 형님 기록이 있으니 질문을 쓸 때 참고한다.
   - `agrees_with_recommendation`이 false면 보고에 "AI 추천과 다름"을 적는다.
4. **형님이 답하면 기록한다.** `answer.json`을 쓰고 `python scripts/record.py answer.json`.
   ```json
   {"question": "...", "context": "Kit 05 괴물 디자인 중", "options": ["...", "..."],
    "choice": 1, "recommended": 0, "quote": "형님 원문", "reason": "왜", "category": "creature"}
   ```
   `category`: creative, visual, creature, ui, scope, reference, world, production, workflow 중 하나. 기록한 답은 다음 판정부터 가장 강한 근거가 된다. 규칙을 다시 만들 필요는 없다.

## 후보 쓰는 법 (AI가 선택지를 새로 써야 할 때, 결과물 판정)

- 후보마다 딱 잘라 말하는 입장 하나를 쓴다. 서로 방향이 달라야 한다.
- "상황에 따라 다르다", "~에 따라 갈린다", "둘 다 일리 있다" 같은 얼버무리는 후보는 쓰지 않는다. Jev가 이런 후보를 과하게 고르고, 형님은 거의 늘 딱 잘라 답한다. 결과의 `hedge_candidates`에 걸리면 고쳐 쓰고 다시 돌린다.
- 결과물 판정이면 형님 말투의 짧은 반말 한 줄 평을 쓴다("흔해서 펑", "굳. 발 딛는 게 말랑함", "배경은 좋아. 물체가 딱딱한게 문제"). 통과 쪽 하나 이상과, 이유가 서로 다른 퇴짜 쪽 여러 개를 섞는다.
- 후보끼리 길이와 공들인 정도를 맞춘다. 네가 맞다고 보는 후보만 자세히 쓰면 Jev가 그쪽으로 쏠린다. 후보는 2~12개, 3~6개가 알맞다.

## 결과 읽기

- `pick`(0부터 번호), `answer`, `confidence`, `stable`(후보 순서를 뒤집어 다시 물어도 같은 답인가), `probabilities`(두 번 물은 평균).
- `applied_rules`, `flip_if`: 들어맞은 형님 규칙과 뒤집히는 조건.
- `verdict.pass_prob`, `verdict.score`: 결과물 판정일 때 통과 확률과 0~100점(형님 통과 기준 70점). Jev는 퇴짜를 잘 맞히고(19건 중 18건) 통과는 약하다(7건 중 3건). 퇴짜라고 해도 새 핵심 동사나 새 구조가 보이면 한 번 더 본다.
- 문턱은 환경변수로 바꾼다: `AVATAR_ACCEPT`(기본 0.7), `AVATAR_ASK`(기본 0.5).
- 형님께 보고할 때 근거 원문(형님 대화·메모)을 길게 옮기지 않는다. 고른 것과 숫자면 된다.
- 약한 분야: Kit 범위(scope) 결정은 45~64%만 맞았다. scope 결정은 확신이 높아도 형님께 확인 질문으로 올린다.

## 안 되는 것

- Jev는 글을 만들지 않는다. 이유는 후보에 적은 것이 전부다.
- Jev는 글(텍스트·JSON)만 읽는다. 이미지·영상은 에이전트가 묘사해서 넣는다.
- 지시문은 영어가 가장 정확하다(스크립트가 영어로 묻는다). 형님 기록은 한국어라 조금 떨어질 수 있다.
- Jev 서버가 가끔 503을 낸다. 스크립트가 재시도하고, 그래도 실패하면 `error`가 나온다. 그때는 원래 규칙대로 AI 추천으로 진행하고 형님께 묻는다.

## 계속 보완하는 법

분신은 형님이 실제로 정한 게임 개발 결정이 쌓일수록 나아진다. 질문을 지어내지 않는다. 맥락을 잘라낸 가상 질문은 답을 받아도 쓸모가 없다(2026-09-28 형님: "질문들이 맥락을 전부 잘라버려서 의미가 전혀 없어").

1. **질문은 실제로 멈춘 결정에서만 나온다.** 게임 개발 AI가 멈춘 결정에서 `gate`가 `ask`일 때, 그 결정을 원래 맥락 그대로 올린다(절차 3). 한 번에 하나씩 올리고, 여러 개를 묶어 설문으로 만들지 않는다.
2. **밀린 결정도 같은 방식으로 한다.** TIN 문서에 '사용자 확인 대기'·'이미 이렇게 진행함'으로 남은 결정에도 분신을 돌린다. 분신이 확신하는 것은 올리지 않는다.
3. **답은 바로 기록한다.** `record.py`에 형님 원문(`quote`)과 이유를 꼭 넣는다. 형님이 AI 방향을 바로잡은 말("아니 그게 아니라")은 `kind: "corrected"`로 넣는다. 가장 값진 기록이다.
4. **경계는 그 맥락 안에서 묻는다.** 답이 갈릴 만한 결정이면 "무엇이 바뀌면 반대로 고르시나요?"를 같은 결정에 붙여 한 줄로 묻는다. 맥락 없는 새 질문으로 따로 만들지 않는다.
5. **새 기록이 20건쯤 쌓이면 다시 잰다.** `<데이터 폴더>/decision/`에서 `python eval_gamedev.py --name <이름> --near 0.2`. Jev만 쓰고 모델 호출은 없다. 전체 적중, AI 추천 대비, 분야별 약한 곳을 본다.
6. **틀린 판정을 고친다.** 결과 파일(`raw/gold_runs/<이름>.jsonl`)에서 틀린 결정을 찾는다. 근거가 없어서 틀렸으면 기록을 더 모은다. 근거가 있는데 틀렸으면 `choose.py`의 `PICK`이나 `evidence.py`의 `PERSON`을 고치고 5번으로 다시 잰다. 점수가 떨어지면 되돌린다.
7. **스킬을 고쳤으면** `python scripts/install.py --codex --kiro`로 설치본을 갱신한다.

하지 않는 것: `decision/ask.py`로 규칙끼리 부딪히는 곳에서 가상 상황을 지어내 묻기.
아직 없는 것: 쌓인 답으로 판단 규칙(`judgment_model.json`)을 다시 만들기, 여러 해상도 기억(세션 → 주제 요약 → 사건), 뒤집히는 조건 채점.

## 다른 에이전트로 옮기기 (Kiro가 멈췄을 때)

- 이 폴더가 스킬의 전부다. Kiro 전용 도구를 부르지 않고, 모델 호출도 하지 않는다.
- Codex: `python scripts/install.py --codex` → `~/.agents/skills/avatar-jev`에 복사되고 데이터 폴더 위치가 `data_dir.txt`에 적힌다. Codex를 다시 켜고 `$avatar-jev`로 부른다. 예전 Codex는 `--codex-old`(`~/.codex/skills`).
- Kiro: `python scripts/install.py --kiro`.
- 다른 PC: 데이터 폴더(`tools/avatar_judge`)를 통째로 복사한다. git에 없는 `raw/`와 `decision/judgment_model.json`도 같이 옮긴다. 그다음 `AVATAR_JUDGE_DATA`를 그 경로로 두거나 `install.py --data <경로>`.
- 스킬을 고쳤으면 `install.py`를 다시 돌려 복사본을 갱신한다.
