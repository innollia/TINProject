# proc_bake — 절차 생물·배경 제작 목록

기준 이미지: Rain World 계열. 1x 실루엣만 봐도 무엇인지 판별되어야 한다.
이 문서는 **무엇을 몇 개 만들지**를 고정한다. 여기 없는 것은 만들지 않는다.

## 0. 판정 게이트 (이것을 통과하지 못한 산출물은 폐기하고 다시 만든다)

| 번호 | 게이트 | 검사법 | 실패 예 |
|---|---|---|---|
| G1 | **실루엣 판독** | 이미지를 40px로 줄여 회색으로 찍고, 1초 안에 "이건 뭐야"가 답해야 한다. 발/눈/꼬리 위치가 구분된다 | 네모난 통, 막대 다리 4개 |
| G2 | **부위 분해** | 실루엣에 오목(concave) 지점이 2개 이상 있다. 둥근 덩어리만으로 구성되지 않는다 | 타원 3개 겹침 |
| G3 | **가관절 연속성** | 관절이 뚝 끊기지 않는다. 다리↔몸통 접합이 `smooth_min`으로 녹아 있다 | 다리가 몸에서 떨어져 뜸 |
| G4 | **명도 3단** | body / shade / key 가 실제로 다르게 보인다. 평평한 단색 금지 | 단색 실루엣 |
| G5 | **윤곽선** | 2px 이상 먹선이 실루엣 **바깥**에 앉아 있고, 폭이 고르다 | 1px 헤어라인, 부분 소실 |
| G6 | **움직임** | 스트립 8프레임에서 첫/중간/마지막이 다르다. 다리는 접지선에서 떨어지지 않는다 | 전 프레임 동일 |
| G7 | **색 혼합 금지** | 같은 palette role을 2개 파트가 공유하되 색이 다르면 다른 role이어야 한다 | 전부 body |
| G8 | **각 금지** | 모든 윤곽이 매끈하다. 직각·계단 없음. 끝은 둥글거나 뾰족하게 가늘어진다 | 사각 도형, 톱니 |

G1~G3이 실패하면 모양을 고친다. G4~G5가 실패하면 팔레트/`shade_depth`를 고친다.
G6이 실패하면 관절각·`stride`·`cycle`을 고친다. 도형 문제가 아니라면 손대지 않는다.

### 0.1 위 표는 눈으로 보는 판정이다. 기계 판정과 다르다

`python -m procbake.check` / `bake` / `legcheck`가 함께 돌린다. **기계 게이트를
눈 판정보다 우선하지 말 것** — 게이트가 이 프로젝트에서 세 번 조용히 틀렸고,
눈이 한 번은 게이트를 이겼다. 교정값은 `HANDOVER.md` 3절.

| 게이트 | 명령 | 기준 (실측 교정값) |
|---|---|---|
| G1 실루엣 | `bake` → `<name>_bake.json`의 `silhouette.dev_small` | **>= 0.06**. 타원은 0.02, 실물 생물은 0.27~0.80. 40px 축소본에서도 유지돼야 한다 |
| G1 보조 | 같은 파일의 `fill_ratio` | 0.18~0.45 |
| G2 부위 오목 | `check`의 `conc` | **>= 2**. 0이나 1이면 덩어리다. 오목은 **볼록**이 아니라 **볼록껍질 밖**이어야 센다 |
| G3 다리 | `legcheck` | 모든 체인이 자기 정지 자세에서 풀린다. 무릎 내각 **>= 45도**, 발은 자기 골반에서 수평 **0.42스팬 이내** |
| G4 스케일 | `bake`의 `G4` | 월드 스케일 **>= 0.22**. `scale`은 부모 기준이라 체인을 따라 곱해진다(0.4×3 = 0.064) |
| G8 각 | `check`의 `sharp` | **< 0.14**. 윤곽이 이만큼이라도 뾰족하면 면으로 보인다 |
| 배경 깊이 | `backdrop` | 인접 레이어 명도차 **>= 0.020**, 전후 확산 **>= 0.075** |
| 배경 중앙 | `backdrop` | 중앙(가로 50% × 세로 40%)이 좌우 3분의 1보다 **빽빽하면 안 된다** |

## 1. 신체부위 SVG 라이브러리 (총 46개)

`tools/proc_bake/shapes/*.svg`. 한 파일 = 한 부위. 반드시 직접 path를 그린다.

규약: `viewBox` = 최종 픽셀(1 unit = 1 px), **+X = 성장 방향**, y는 아래로 증가.
`data-joints` = 자식이 붙는 중심선. 첫 점이 이 부위 자신의 원점.
곡선만 쓴다(M/L/H/V 직선만으로 닫힌 도형 금지). 끝은 둥글게 또는 가늘어지며 마감.

## 2. 생물 (총 30종)

**규약**: 최소 부위 8개, 최대 16개. 파손 관절 2~3조. 눈은 반드시 1쌍(또는 0).
모양만 다른 판타지 생물이 아니라 **부위 배치가 다른** 개체. 4족 2족 무족 구분.
파레토: "a dog with a bug head" 같은.

| # | 이름 계열 | 부위 구성 | 계열 근거 |
|---|---|---|---|
| 01–06 | 포유류 사냥꾼 | torso_rodent/insect + head_×2 + limb×2조 + tail | 4족, 꼬리 균형추 |
| 07–12 | 양서·수서 | torso_frog/slug + limb_digitigrade/web + eye_cluster | 낮은 자세, 접지 넓게 |
| 13–18 | 곤충·절지 | torso_insect + limb_segmented×3 + antenna + wingarm | 6족 이상, 분절 |
| 19–24 | 어류·연어류 | torso_fish + tail_fluke + fin + lure | 수평, 지느러미 |
| 22–27 | 초현실 생물 | torso_blob + lure_bulb + frill + 안테나 | 규칙 없음 |
| 28–30 | 공포 몬스터 | head_maw + horn + shell + tail_sting | 과도한 부위 |

각 종마다 `specs/creatures/NN_name.json` 1개. 각 spec 200줄 이내.

## 3. 배경 (총 12장)

`1280x720` 정적 + 레이어 3~5. 카메라 고정. `assets/art/generic/jobs/<job>/output/`.

Rain World 배경 문법: **전경 실루엣 / 중간 구조 / 원경 색면** 3층 분리.
가장자리만詳, 중앙은 비워서 플레이 영역이 된다. 소품은 8~20개.

1. 산소 없는 빗물 industrial (관·기어·방울) 2. 버섯 동굴 3. 얼음 동굴
4. 폐쇄된 연구소 5. 부유 잔해 6. 무덤 도시 7. 젖은 협곡
8. 균사 직조실 9. 가라앉은 선착장 10. 태운 숲 11. 이끼 동굴 12. 기계 예배당

## 4. 제작 순서와 병렬화

1. **라이브러리 병렬** — 1.1~1.7 을 4개 세션이 파일명으로 분리해 동시에 집필.
   충돌 없음(각자 다른 파일명). 선행: `limb_femur` `torso_lizard` `head_blunt` `tail_taper` 를 표본으로 참고.
2. **개별 검수** — `python -m procbake.bake --preview-shape <name>` 로 부위별 콘택트시트 생성, 눈으로 확인.
3. **생물 병렬** — 라이브러리 46개 확정 후 종 30개를 3개 세션이 10개씩.
4. **배경 병렬** — 12장을 2개 세션이 6개씩.
5. **자가 피드백 루프** — 각 산출물 PNG 를 반드시 열어 보고, G1~G8 로 자가 채점, 실패하면 해당 부위/각도만 고쳐 재렌더. **스스로 판단해 승인까지 반복.**

## 5. 금지

- 타원만 겹쳐 만든 몸통. 부위 수는 많아도 **실루엣에 오목이 없으면 실패**.
- 색만 다른 개체. 파트를 이름만 바꿔 복붙 금지.
- 각진 도형, 톱니, 계단형 외곽선.
- GPT/생성형 이미지 도구. 전부 코드로 그린 벡터.
- 스프라이트시트 완성품을 한 번에 그리고 프레임 채우기. (이 시스템은 실루엣만 굽는다)
- 산출물 PNG 는 `out/` 하위로만. 원본 shape/spec 은 `shapes/` `specs/` 에.
