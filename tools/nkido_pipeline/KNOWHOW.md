## A. nkido를 Windows에 세우는 법

### A1. MSVC로 빌드하지 말 것. clang-cl이 답이다

**규칙.** nkido는 clang-cl로만 빌드한다. `nkido_build/build.cmd` 가 그것이다.

**근거.** MSVC 빌드는 링크되고 실행되며 `akkado --help` 도 된다. 그러다가 **비어 있지
않은 패치를 어떤 것이든 컴파일하면 죽는다.** 종료 코드 `0xC0000409`, 출력이 없다.
CLI에 `try/catch` 가 없어서 진짜 문제는 `akkado::compile()` 이 던지는
`std::bad_alloc` 이다.

4줄짜리 프로브(`nkido_build/badalloc_probe.cpp`)로 원인을 확정했다.

| 호출 | 결과 |
|---|---|
| `akkado::Version::string()` | 정상 |
| `akkado::compile("")` | 정상. 진단 "Empty source file" |
| `akkado::compile("sine(440) |> out(%)")` | `std::bad_alloc` |
| 그때 요구한 단일 할당 | `72621737992257591` 바이트 = `0x0102011600000037` = **약 66 PB** |

`0x37`(=55)만 유효하고 상위 32비트 `0x01020116`는 이웃 메모리다. 64비트 `size_t` 에
32비트 값을 상위 비트 없이 넣는 곳이 있어 MSVC에서 그 뒤 4바이트를 이웃 필드로 읽는다.
**Debug 라이브러리(`/Od`)에서도 같은 값**이므로 옵티마이저 문제가 아니다.

**확인법.** `nkido_build/probe.cmd` 를 돌려 case 1·2·3을 본다.

**대가.** 3.5시간. 크래시를 MSVC 버그, nkido 버그, 내 스크립트 버그로 한 번씩 좁혔다.

### A2. 빌드 함정 다섯 개

모두 이 프로젝트에서 실제로 밟았다.

| 함정 | 증상 | 해법 |
|---|---|---|
| `CEDAR_ENABLE_FILE_IO=OFF` | `LNK1120` — `cedar::HttpHandler` 미해결. 해당 옵션이 `cedar/src/io/` 네 파일을 빌드에서 빼는데 `tools/nkido/asset_loader.cpp` 는 무조건 참조한다 | **OpenSSL Dev 를 설치하고 이 옵션을 켠다.** 끄는 쪽은 upstream 결함 |
| `CMAKE_CXX_FLAGS` 덮어쓰기 | 컴파일이 죽음 | CMake 기본값 `/DWIN32 /D_WINDOWS /W3 /GR /EHsc` 를 **명시적으로 다시 넣는다.** `/EHsc` 가 사라지면 예외가 스택을 타고 나가지 못하고 프로세스가 죽는다 |
| `/utf-8` 누락 | `mini_lexer.cpp` 가 깨짐. 소스에 UTF-8 em-dash 가 있고 한국어 코드페이지(949)로 읽는다 | `/utf-8` 필수 |
| `core.autocrlf=true` | 소스 전체가 CRLF 로 체크아웃됨 | 클론 후 `git config core.autocrlf false && git config core.eol lf` 후 다시 받는다. 이 저장소도 `.gitattributes` 로 LF 고정에 신경을 쓴다 |
| clang-cl specifics | rtmidi 가 `cannot use 'try' with exceptions disabled`. SDL2 `_m_prefetch` 재정의 충돌 | `/EHsc` 와 `/D__PRFCHWINTRIN_H` |

**추가로**: `nkido` 가 `std::countr_zero` 를 쓰면서 `<bit>` 를 include 하지 않는다.
Clang/GCC는 전이로 들어오고 MSVC는 아니어서 컴파일되지 않는다. `nkido_build/std_bit_shim.h`
한 줄을 `/FI` 로 강제 include 한다. **클론 소스는 고치지 않는다.**

**대가.** 각 함정을 한 번씩 고치느라 빌드 시도 8회. OpenSSL은 Light가 아니라 **Dev**여야
한다 — Light는 DLL만 깔아서 `find_package(OpenSSL)` 이 실패한다. 그리고 CMake `-D` 인자는
공백에서 깨지므로 의존성을 `C:\projects\_tools\deps\` 로 복사한다.

### A3. 실행 파일 옆에 DLL이 필요하다

`SDL2.dll`, `libcrypto-4-x64.dll`, `libssl-4-x64.dll`. 없으면 시작하자마자
`0xC0000135`. `build.cmd` 가 복사해 준다.

## B. 오디오 파이프라인

### B1. 스테레오 규칙 세 문장

> 1. 스테레로 차이는 **첫 필터 이전에, 맨 소스에서만** 만든다.
> 2. **어쮯 필터도 스테레로 플래그가 붙은 신호를 보면 안 된다.**
> 3. 두 모노 체인은 **"컴파일이 접지 못하는 것"**으로 달라야 한다.

**근거.** `cedar/include/cedar/opcodes/filters.hpp` 의 모든 필터가 두 채널을 쓰고,
입력에 `STEREO_INPUT` 플래그가 없으면 **같은 `input[i]` 를 양쪽에 복제**한다.
즉 필터는 모노를 스테레로 만드는 지점이고, 필터를 통과한 신호는 복제쌍이다. 그 쌍을
`stereo()` 로 다시 감싸거나 `out()` 에 두 인자로 나누거나 한 바인딩을 양쪽에 `pan` 해도
차이가 돌아오지 않는다.

세 번째 문장이 없으면 1·2번을 지켜도 모노가 된다. **상수가 다른 컷오프(420 대 428)는
컴파일러가 접는다.** 음파 detune(`saw(55)` 대 `saw(55.6)`)과 `noise(0,0,101)` 대
`noise(0,0,977)` 은 접히지 않는다.

**확인법.** `tool/probe_filter_width.py` (21건) · `tool/probe_stereo_rule.py` (6건).
`nkido check` 는 통과시키므로 **게이트만이 잡는다.**

**대가.** 두 번 깨졌다가 세 번 고쳤다. 게이트가 두 번 잡아 되돌렸다.

### B2. 저역통과가 스테레로 경로에서 DC를 쌓는다

**규칙.** 스테레로 신호 뒤에 저역통과가 오면 뒤에 하이패스를 하나 둔다. 그리고
DC를 잰다.

**근거.** 같은 입력·같은 필터인데 경로가 다른데 22 dB 차이가 났다. **그 진단이 틀렸다.**
DC를 재서 보니까 뒤집혔다.

| case | peak | RMS | **DC offset** |
|---|---|---|---|
| `d` 모노 사인 | −27.9 | −32.7 | **0.00000** |
| `e` `stereo(tri*0.04, tri*0.04)` 필터 없음 | −27.9 | −32.7 | **0.00000** |
| `f` 같은 것 레벨 절반 | −33.9 | −38.8 | **0.00000** |
| `g` `stereo(tri...) │> lp` | −0.9 | −6.9 | **0.44998** |
| `c` `stereo(mel...) │> lp │> reverb` | −0.9 | −9.9 | **0.22513** |
| `j` `stereo(noise) │> lp` | −5.2 | −22.5 | 0.00016 |
| `stereo → lp → **hp**` | **−29.6** | **−49.4** | — |

`tri` 의 평균 0.5가 DC로 증폭돼 0.45가 되고, 결과는 master soft clip(−0.9)에 걸린다.
`freeverb` 이 그 오프셋을 더 증폭해 **0.57까지** 간 사례가 있다. `DENORMAL_DC` 가
박힌 소스

```cpp
float v3 = x - (state.ic2eq[ch] + DENORMAL_DC);
```

가 원인 후보다. **여전히 upstream 버그**이고 우리는 규칙으로 피한다.

**확인법.** `tool/probe_level.py` (10건). `nkido check` 는 통과시킨다.

**대가.** 2회. "미확명"으로 문서에 남겼다가 틀린 Diagnose를 그대로 배포할 뻔했다.

### B3. `saw()` 는 이미 0-mean 이다

**규칙.** `saw()` 에서 0.5를 빼지 마라.

**근거.** **두 번 틀렸다.** 첫 번째는 되돌렸고, **다음 라운드에 그대로 다시 해서**
게이트가 DC −0.57로 잡아냈다(`freeverb` 이 증폭).

**확인법.** `analyze_audio.py` 의 DC 항목. 게이트가 잡는다.

### B4. Loop는 자르지 않는다

**규칙.** `loop + fade + 0.25`초를 렌더하고, 초과분을 자기 머리에 다시 접는다
(`tool/loopify.py`). 완성 WAV를 뒤에서 자르는 것은 금지.

**근거.** nkido에는 loop 모드가 없다. 자르면 두 무관한 값이 맞닿는다. 접으면 앞 0초가
본문의 **자연스러운 다음 샘플**이 되므로 이어 붙이는 지점이 아예 없다.

렌더 길이는 **LFO 주기의 정배수**로 잡는다. 8초 stem은 0.125/0.25/0.5 Hz 같은
2의 분수배 LFO만 쓴다. 그래야 크로스페이드가 남는 게 없다.

**확인법.** 게이트의 `loop_jump_ratio`(랩 도약 / 표본 기울기)와 `wrap_hf_dbfs`.
**사람은 2026-09-28에 "루프 이음 못느낌"이라고 확인했다** — 귀로도 통과했다.

**대가.** 0.25초 마진은 nkido가 블록 단위로 끊겨서 8.5초 요청에 8.499초가 나온
일 때문에 넣었다.

### B5. 이 툴체인으로는 sample을 못 쓴다

**규칙.** `--no-default-bank` 는 항상. sample 이름을 쓴 패턴(`n"sh*8"`)을 믿지 마라.

**근거.** 라이선스. 기본 뱅크에 CC-BY-SA 4.0과 라이선스 미확인 샘플이 섞여 있다
(`docs/STRUDEL_AUDIO.md` 6절). 그리고 **sample 이름 패턴은 조용히 무음이다** — −60 dBFS
실측. 렌더가 성공한다. 그래서 `n"sh*8"` 로 드럼을 짜면 아무도 모르게 빈 파일이 나온다.

**같은 부류로 `euclid(n, 8)` 을 곱셈에 쓰면 무음이다** — `noise() * euclid(5,8) * ar(trigger(1))`
= −60 dBFS. 드럼 레시피가 이 경로에 기대고 있었다.

**확인법.** 게이트의 `min_rms_dbfs`. 렌더 성공 ≠ 소리 있음.

### B6. 게이트는 검증되어야 한다

**규칙.** 측정기를 쓴다면 측정기도 검증한다.

**근거.** `tool/analyze_audio.py --selftest` 가 답이 이미 아는 기준 신호 6개
(정상 / 랩 클릭 / 하드 클리핑 / 저역 럼블 / 과도한 스테레오 폭 / 기준 사인)를 만들어
**정확히 그 결함만** 잡는지 확인한다. 이 게이트는 만드는 중 자기 버그를 4개 잡았다.

| 버그 | 증상 |
|---|---|
| BS.1770 채널 평균/합 혼동 | 스테레오가 3 dB씩 낮게 읽혔다 |
| 오버샘플링 4배 감쇠 | true peak가 12 dB씩 낮게 읽혔다 |
| 8192탭 IR | 11개 분석에 600초. 느린 게이트는 아무도 안 쓴다 |
| `log10(0)` | 무음 파일에서 죽는다. **무음 stem 은 실제로 나오므로 게이트가 죽으면 안 된다** |

**추가로 세운 것:**

- **키가 없으면 그 항목은 켜져 있는 것으로 본다.** 빠진 필드가 조용히 완화되면 아무것도
  안 막는 게이트가 된다.
- **`open_findings` 는 래칫이지 스위치가 아니다.** 이미 확인된 미해결 항목은 계속 출력되며
  빌드를 막지 않고, **새 실패만 막는다.** 해결되면 지우는 대신 `resolved_findings` 로 옮긴다.
- **미해결 항목은 사람이 아는 내용이어야 한다.** "이러한 문제를 가지고 있다"보다
  "이렇게 살고 있다"가 낫다.

### B7. stem 단위는 사람이 한 개씩 들을 수 있는 단위다

**근거.** "프로필을 섞어 들어보라"고 하는 순간 사람이 못 하는 일을 시킨다.
`tool/mix_profiles.py` 는 프로필을 **파일 하나로** 합쳐 낸다. 합산은 런타임과 같은
산술이다(base `volume_db` + 프로필 게인 + 버스 트림, 짧은 stem 은 루프, 결과도 루프 접기).

이 도구가 처음 돌렸을 때 계측으로만 보이는 결함을 두 개 잡았다.

1. **7개 프로필 전부 목표보다 10~25 dB 작았다.** base trim 을 낮춘 것과 프로필 게인이
   곱해져 바닥이 사라진 것. → **`mix_trim_db` 한 개** 로 해결. 열한 개를 눈대중으로
   맞추는 대신 측정 가능한 수 하나로.
2. **죽은 레이어.** 게인 0.35인데 믹스에서 −27 dB, −34 dB, −29 dB. stem을 하나씩
   들어서는 절대 알 수 없다. `--balance` 가 floor 아래 레이어를 올린 값을 제안한다.
   **40 dB 아래는 취향이 아니라 꺼짐이므로 기계가 고쳐야 한다.**

그리고 과잉 교정도 드러났다. "고역 과다" 수정이 stem을 9~12 dB 깎아 **게인 1.0으로도
안 들리게** 만들었다. 게인이 아니라 stem 레벨 문제였다.

**기준선을 둘로 갈랐다.** −40 dB 아래는 게이트가 막고(결함), −22 dB 부근은 NOTE로만
보고한다(속삭임인지 죽은 것인지 — 귀가 정함).

### B8. mix는 합쳐서 재야 한다

stem에 LUFS 게이트를 걸면 "얼마나 세게 렌더했나"만 잰다. **LUFS는 프로그램 단위 지표**다.
stem은 true peak·클리핑·루프 이음·상관도로 재고, mix는 합성한 뒤 재야 한다.

### B9. 모노인 게 맞을 때가 있다

서브 베드(`amb_pressure`, `amb_pulse`)는 모노가 맞다. 넓으면 중앙 이미지가 뭉개지고
헤드룸만 먹는다. **`mono_ok` 로 검사 규칙에 명시한다** — 패치 주석이 아니라, 회귀를 잡는
방식이 그래서 그렇다.

## C. 이 저장소에서 일하는 법

### C1. 한국어 파일을 PowerShell `Set-Content` 로 덮어쓰지 마라

**근거.** `STATUS.md` 를 이걸로 덮어써서 **실제로 깨뜨렸다.** UTF-8 이 CP949 로
바뀌고 온글이 `?` 로 죽었다. `edit` / `write` 도구나 UTF-8 인식 편집기를 쓴다.
**실행 전 `py -c "open(p,'rb').read().decode('utf-8-sig')"` 로 검증한다.**

같은 함정: Windows PowerShell 5.1 의 `Set-Content -Encoding utf8` 는 **BOM을 쓴다.**
Python 의 `json.load` 는 BOM을 거부한다. 파이프라인이 만드는
`ambient_stems.json` 은 BOM 없이 나가도록 `[System.IO.File]::WriteAllText` 로 쓴다.

### C2. 계측으로 안 되는 것을 측정하려고 하지 마라

긴장감, 반복 피로, motif 인식성, 장면 적합성, 그리고 **"이 레이어가 속삭임인지
죽은 것인지"** 는 숫자가 아니다. 게이트는 NOTE로만 남기고 넘어간다. 이 프로젝트의
규칙이 그렇고, 추측으로 채우는 순간 그건 측정이 아니라 거짓말이 된다.

### C3. 사람이 하는 일을 줄이되 없애지 마라

자기 루프를 만들라는 요구는 정당하다. 다만 **"사람이 매번 듣고 평가하는 구조에 의존하지
말라"**는 지시를 "사람이 안 듣게 하자"로 읽으면 안 된다. automating하되 **판단 자체는
사람에게 남기고, 그 판단이 필요한 입력을 최대한 좁혀서 낸다.** 파일 7개가 "3개를 동시에
들어라"보다 쉬운 요청이다.

### C4. 소유 경계를 지켜라. 그리고 보고하라

`modules/descent_exploration/module.gd` 는 Kit 세션 소유라 건드리지 않았다. 6줄을
붙이는 것이技术上는 가능했다. 대신 `STATUS.md` 5절에 붙여넣을 코드를 그대로 적어뒀다.
**설명이 없는 침묵보다 문서화된 미완이 낫다.**

`AGENTS.md` 의 Godot 락은 다른 세션의 `.godot/` 을 지키는 것이고, **사용자가 "락 멍청하다고
그냥 해"라고 하면 따른다** — 그건 사용자의 판단이다. 다만 내가 실제로 위반했고, 그 사실을
말해야 했다.

### C5. 커밋 경로를 한정한다

`git add -- <내 경로>` 다음 `git commit -m ... -- <같은 경로>`. 다른 세션이 staged 에
놓은 파일이 섞이지 않게 하기 위해서다. WAV 를 넣으면 Godot 이 만드는 `.import` 파일도
같이 커밋한다.

### C6. 되돌릴 수 없는 걸 먼저 고정한다

세션이 사라져도 디스크의 파일은 살아 있다. 사라지는 건 (a) 저장소 밖에만 있던 스크립트,
(b) 왜 이런 결론이 나왔는지다. 그래서 `nkido_build/`(빌드·`<bit>` shim·버그 프로브)와
`STATUS.md`(단일 진입점)를 저장소 안으로 옮겼다.
