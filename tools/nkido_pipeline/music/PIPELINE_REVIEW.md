## 3. 이번 라운드가 실제로 만든 것

`tool/analyze_audio.py` — 객관 게이트. numpy만 쓴다.

- **integrated LUFS** (ITU-R BS.1770-4 K-weighting, 400 ms 블록 75% 중첩, 절대 -70 / 상대 -10 게이팅)
- **true peak** 4배 오버샘플 (windowed sinc)
- 클리핑 샘플 수, DC offset, 옥타브 밴드 밸런스, 20–40 Hz 과잉
- **채널 상관도** — 스테레오가 실제로 벌어졌는지
- **루프 이음 불연속** — 랩 지점 도약이 신호 자체의 표본 기울기에 비해 몇 배인지, 그리고 그 지점의 고주파가 전체보다 몇 dB 밝은지
- mix 합성 후 LUFS / true peak

`--selftest`이 있다. 답이 이미 아는 기준 신호 6개(정상, 랩 클릭, 하드 클리핑, 저역 럼블, 과도한 스테레오 폭, 기준 사인)를 만들어 **정확히 그 결함만** 잡는지 확인한다. 게이트를 아무도 검증하지 않은 게이트로 두지 않기 위해서다.

이 게이트가 만드는 것 중 하나가 **자기 검증**이다. 만들다가 세 가지 실제 버그가 나왔다.

- BS.1770 채널 평균/합 혼동 — 스테레오가 3 dB씩 낮게 읽혔다
- 오버샘플링 4배 감쇠 — true peak가 12 dB씩 낮게 읽혔다
- 8192탭 IR — 11개 stem 분석에 600초. 게이트가 느리면 아무도 안 쓴다

### 4.1 nkido 채널 규칙 — 실측으로 규명됨

지난 라운드 보고에서 `amb_surface` 에 대해 이렇게 썼다.

> "Two decorrelated noise seeds keep the stereo field from collapsing."

**틀렸다.** `amb_surface` 는 넓었고(상관도 0.70) `amb_air` 는 좁았다(1.000).
차이가 난 것이 시드도 pan도 아니었다. `tool/probe_filter_width.py` 로 21개 경우를
그려 봤다.

소스 반쪽은 즉시 나왔다. `cedar/include/cedar/opcodes/filters.hpp` 의 모든 필터가
이렇게 돈다.

```cpp
for (std::size_t ch = 0; ch < 2; ++ch) {
    float x = (ch == 0) ? input[i] : (stereo_in ? input_r[i] : input[i]);
```

**필터는 항상 두 채널을 쓰고, 입력이 `STEREO_INPUT` 플래그가 없으면 같은
`input[i]`를 양쪽에 복제한다.** 즉 필터는 모노를 스테레로(복제로) 만드는 지점이다.
그러면 필터를 이미 통과한 신호는 두 채널이 같은 쌍이고, 그 쌍을 다시 넓혀도
차이가 돌아오지 않는다.

예측 가능한 규칙이 나온다. **넓은 쪽(상관도 0.0 근처):** 01·11·12·15·19·21.
**좁은 쪽(1.000):** 02–07·09·10·13·14·16·17·20.

> **스테레오 차이는 첫 필터 이전에, 맨 소스에서만, `out()` 인자 하나로 만들어야 한다.**
> 다른 시드를 준 맨 소스를 `stereo()`로 감싸고, 그 한 신호에 필터를 걸고,
> `out()`에 인자 하나만 준다.

| 확인된 것 | 사례 |
|---|---|
| 필터 인스턴스 2개 자체는 문제가 아니다 | 19: `out(stereo(A \|> lp, B \|> lp))` → 0.000 |
| 컷오프가 달라도 무관하다 | 13: 400 vs 1600 → 1.000 |
| q가 달라도 무관하다 | 14 → 1.000 |
| 컷오프가 오디오레이트여도 무관하다 | 05·06 → 1.000 |
| 필터 종류도 무관하다 | 02 `hp`, 03 `lp`, 04 `bp`, 07 `moog` → 전부 1.000 |
| 두 필터를 **연쇄**하면 무너지지만, 첫 입력이 이미 넓으면 괜찮다 | 20 → 1.000, 21 → 0.000 |
| `out()`에 인자 두 개를 주면 무너진다 | 17·18 대조: 1.000 / 0.000 |
| 한 바인딩을 양쪽에 pan 하면 무너진다 | 지난 라운드의 `out(x.pan(0.15), x.pan(-0.15))` → 1.000 |

수정:

```
// 이전: 모노가 됨
air = noise() * 0.30 |> lp(@, breath, 1.6) |> hp(@, 120)
out(air.pan(0.15), air.pan(-0.15))

// 지금: 상관도 0.00
field = stereo(noise(0, 0, 101) * 0.22, noise(0, 0, 977) * 0.22)
out(field |> lp(@, breath, 1.6) |> hp(@, 120))
```

`amb_column` 도 같은 규칙으로 고쳤고 0.69가 되었다. 두 건은
`analysis_targets.json` 의 `resolved_findings` 로 옮겨 이력을 남겼다.

### 4.2 되돌린 것

`saw()` 에서 0.5를 빼 DC를 잡으려는 시도는 **DC −0.71**을 만들어 상태를 더
나쁘게 만들었고 되돌렸다. `saw` 는 이미 0-mean이고 처음의 0.00208은 체인
어딘가의 잔여다. 가설이 아니라 실측이다.

### 4.3 위 배치가 어떻게 굴러가는가

`analysis_targets.json` 의 `open_findings` 는 **스위치가 아니라 래칫**이다.
이미 확인된 미해결 항목은 `KNOWN` 으로 계속 출력되고 리포트에도 남지만 빌드를
막지 않는다. **새로운 실패만 막는다.** 항목을 조용히 지우면 게이트는 아무것도
안 막는 게이트로 돌아간다. 해결된 항목은 지우는 대신 `resolved_findings` 로 옮긴다.

`mono_ok` 도 같은 이유로 목록이다. "이건 모노가 맞다"를 패치 주석이 아니라
검사 규칙에 적는 편이 회귀를 잡는다.

## 6. MusicSpec 컴파일러 — 착수했으나 **막혀 있다**

`tool/compile_music.py` (사양 → `.akkado` × layer) 와 세 개의 구성요소 프로브
(`probe_rhythm.py` 12건, `probe_melody.py` 9건, `probe_level.py` 10건)를 썼다.
문법은 거의 다 굴러가지만 **음향 결과가 신뢰할 수 없다.** 계측해서 알아낸 것만 적는다.

### 6.1 얻은 것

- **문법 규칙 2개.** `@.field` 는 파이프 안에서만 가능하다(`wide * adsr(@.gate, ...)` 는
  E003). 감싸인 신호를 먼저 바인딩하고 그 다음에 pan 해야 한다. `chord` 와 `voicing` 이
  둘 다 선점 이름이라 재바인딩이 E150.
- **드럼에 샘플을 쓸 수 없다.** 라이선스 때문에 `--no-default-bank` 라서
  `n"sh*8"` 같은 패턴은 **조용히 아무것도 렌더하지 않는다.** 확인했다: −60 dBFS.
- **`euclid(n, 8)` 을 곱셈에 쓰면 무음이다.** `noise() * euclid(5,8) * ar(trigger(1))`
  는 −60 dBFS. 드럼 레시피는 이 경로에 기대고 있었다.
- **게이트에 `min_rms_dbfs` 를 넣었다.** 렌더는 성공했는데 소리가 없는 경우를 이제 잡는다.
  이 판정은 위 두 가지 무음 케이스를 즉시 잡았을 것이다. 게이트가 무음 파일에서 죽던
  버그도 고쳤다(`log10(0)`).

### 6.2 스테레로 필터 경로의 이상 — **해결됨. 2026-09-28 청직 이후**

22 dB"라고 적었고, 원인은 **미확인**으로 남겼다. **틀렸다.** DC를 재서 보니까
수치가 뒤집혔다.

1. `stereo()` 자체는 레벨을 바꾸지 않는다. `e`와 `f`가 정확히 −6 dB 간격이다.
2. **저역통과가 스테레로 플래그가 붙은 신호를 보면 최저역대(DC 포함)에 에너지가
   모노 경로보다 훨씬 많이 쌓인다.** `tri` 의 평균 0.5가 DC로 증폭돼 0.45가 된 것이
   `g`, `j`는 저역대 전체다. 결과는 마스터 soft clip(−0.9)에 걸리고, `freeverb` 이
   그 오프셋을 더 증폭한다 — 실제补丁에서 DC 0.57을 봤다.
3. **뒤에 하이패스를 하나 두면 사라진다.** 그래서 `stereo → lp → hp` 는 멀쩡하다.

`cedar/include/cedar/opcodes/filters.hpp` 에 DC 처리 하자가 있다.

```cpp
float v3 = x - (state.ic2eq[ch] + DENORMAL_DC);
```

`DENORMAL_DC` 를 빼는 방식이 스테레오 경로에서 상쇄되지 않는 것으로 보인다.
**여전히 upstream 버그**이고, 우리는 규칙으로 피한다. 근본 수정은 하지 않았다.

### 6.3 규칙이 세 문장으로 확장됐다

§4.1 의 한 문장으로는 부족했다. 실제 stem 을 고치며 세 번째 문장을 얻었다.

> 1. 스테레로 차이는 **첫 필터 이전에, 맨 소스에서만** 만든다.
> 2. **어떤 필터도 스테레로 플래그가 붙은 신호를 보면 안 된다.**
> 3. 두 모노 체인은 **"컴파일이 접지 못하는 것"**으로 달라야 한다.

세 번째가 없으면 1·2번을 지켜도 모노가 된다. **상수가 다른 컷오프(420 대 428)는
컴파일러가 접는다** — 그래서 `amb_drone` 의 두 체인이 바이트 단위로 같아졌다.
음파 detune(`saw(55)` 대 `saw(55.6)`)과 `noise(0,0,101)` 대 `noise(0,0,977)` 은
안 접힌다. 이건 `probe_filter_width.py` 의 13·14번이 미리 예고했고, 안 보고
같은 실수를 했다.

그리고 `saw()` 는 이미 0-mean 이다. **그걸 두 번 놓쳤다** — 한 번은 되돌렸고,
다음 라운드에 그대로 다시 해서 게이트가 DC −0.57로 잡아냈다. 이건
`README.md` 8.3절에 금지 항목으로 적어 두었다.

청취 피드백(`STATUS.md` 4절) 중 계측으로는 안 잡혔던 것들이
`amb_air` 의 고역 과다, `amb_surface` 의 과대 음량, `amb_pulse` 의 "외계 총",
`amb_pressure` 의 "소리가 안 들림", `amb_cavern` 의 "정체불명의 불협화음",
그리고 `bgm_swell` 과 `bgm_descent` 가 **구별되지 않는 것**이었다. 6번은
Crossfade 를 전제로 한 설계가 통째로 무의미해진다는 뜻이라, 트라이톤을 2옥타브
올리고 아크를 반대로 돌려 ears 가 분리할 수 있게 고쳤다.
