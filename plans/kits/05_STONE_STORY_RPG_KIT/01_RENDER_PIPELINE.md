## 3. Ena 스크린샷에서 실제로 관찰된 것 (근거)

`docs/research/stone_story_rpg/02_ena_dream_bbq/00_user_dumps/`의 9장.

### 3.1 공간

- **돔 안**: 청록→노랑→주황 하늘 그라데이션, 어두운 청록 지오데식 립, 흰 구름, 주황 모래 바닥, 밝은 회색 자갈길이 굽어 들어감.
- **협곡**: 어두운 청록 암벽 양옆, 주황 하늘 + 검은 태양 광선, 위로 흐르는 노란 용암줄, 떠 있는 암반, 금빛 아치, 세로 각인 석주.
- **분홍 대성당**: 5중첩 아치 문, 회색 자갈 바닥에 흰 꽃잎, 녹색 하늘에 빛나는 점 하나.
- **실내 복도**: 무지개 체스판 바닥(적/노/파/초), 베이지 벽, 문틀들.
- **방**: 초록 세로줄무늬 벽지, 바닥에 번지는 붉은 팔, 회색 체스판.

→ **모든 장면이 하늘 또는 벽과 바닥을 가진다.** 평평한 검정 화면이 없다.

### 3.2 색

- 주황(바닥/모래), 청록(하늘/암벽), 분홍(건물), 보라(옷/개복), 노랑(표지/차량/벌복), 초록(식물/바닥 얼룩).
- 채도 높고 명도 대비가 약하다. 검정/흰색이 아니라 **선명한 색면**.
- 색은 **오브젝트별로** 다르고, 한 공간 안에서 4~6색이 동시에 산다.

### 3.3 스케일 대비

- 돔, 대성당, 협곡 같은 **거대한 구조물** 옆에 아주 작은 인형/개체.
- 기차가 하늘에 떠 있고, 리무진이 협곡을 가로지른다.
- → **큰 것 / 작은 것**이 같은 화면에 있어야 한다.

### 3.4 개체

- 6개 다리 달린 검은 덩어리(눈 1개). 몸통에서 다리가 방사형으로 나간다.
- 뿔 달린 인형 둘이 같은 화면. 같은 종이 서로 다른 크기/옷.
- 노랑·보라 유니폼 벌. 다리에 껍질, 뒤에 배낭.
- 분홍 코, 창백 피부, 긴 백发的 마법사. 큰 모자.
- → **몸체가 있고, 부분이 다르고, 옷(색면)이 있다.**

### 3.5 초현실 문법

- 나팔수(협곡 벽의 세로줄무늬) + 용암 + 떠 있는 기차 + 각인 석주가 **같은 화면**에 공존.
- 백조실이 화분 위에 손가락으로 spawn. 장난감이 실제 크기로_present.
- 표지판에 화살표 2개. 목적지가 없다.
- → **일상적인 규칙(중력·크기·재질)이局部적으로 깨진다.** 규칙은 하나인데 세계가 거짓말을 한다.

## 4. 비주얼 계약

### 4.1 공간 규칙 (반드시 지킨다)

```text
모든 조명된 장면 = 하늘 또는 천장  +  지평선  +  바닥  +  구조물 1개 이상
```

- **빈 검정 화면 금지.** 배경이 없다면 면으로 채운다.
- 지평선 높이 고정: 화면의 38% (`y = 0.38 * H`). 카메라는 고정이되 바닥 대역이 스크롤한다.
- 구조물은 `evidence` 등급 오브젝트다. 배경 벽이 아니다.

### 4.2 면 규칙

- 기본 단위는 **채워진 면**. `draw_polygon` / `draw_circle` 의 채움.
- 선은 면의 경계 또는 1px 액센트로만.
- 면 색은 팔레트 역할에서 온다. PVE `ProceduralPalette` 를 쓰되 **채도를 살린다.**
  (`01_RENDER_PIPELINE` 1판이 강제한 그레이스케일 변환은 폐기)
- 면 겹침 허용. 얇은 면이 그 위에 얹힌다(옷, 표식, 하이라이트).

### 4.3 색 규칙

- 공간당 **4~6색**. 그 이상이면 뭉개진다.
- 색 3역할: `ground` `sky` `structure` + 개체/소품 액센트 2~3색.
- 채도 하한을 둔다. 무채색 면 금지(순수 검정 배경만 예외적으로 금지 대신 **하늘/바닥이 있어야**).
- 강조색은 물체가 아니라 **공간 구성용**으로 쓴다. 상태 표식에는 쓰지 않는다.

### 4.4 스케일 규칙

- 한 화면에 **큰 것 1개 이상**과 **작은 것 2개 이상**이 같이 있다.
- "큰 것" 판정: 화면 높이의 25% 이상을 차지.
- 개체(적/보스/NPC)는 `small`. 구조물은 `large`.
- → 판정이 코드에서 아니라 **content 의 `scale` 필드**로 나온다.

### 4.5 개체 규칙

- 4속성이 **몸체를 만든다** (이미 구현). 이제 **면으로 채운다.**
  - `다리` → 다리 면의 개수와 굵기. 많으면 방사형으로 넓게.
  - `동그라미` → 몸체 면의 곡률. 1.0이면 원, 0이면 각.
  - `틀림` → 면이 축에서 벗어난 정도. 비대칭.
  - `놀랍다` → 표정/눈의 개수와 흔들림. 예측 불가일수록 눈이 많다.
- 개체는 **눈을 가진다.** 눈에 표정/기색이 있다. (눈이 없으면 개체로 안 읽힌다)

### 4.6 소품 규칙 (초현실의 자리)

- 공간 안에 **일상 규칙을 어기는 소품**이 1~3개 있다. 지오메트리 규칙으로 도출한다.
  예: `float` 태그 = 중력 무시, `oversize` = 실제 배율의 3~5배, `nested` = 같은 것이 안쪽.
- **소품은 반드시 R1~R8(또는 새 규칙집)로 되짚을 수 있어야 한다.** 근거 없는 이상함은 넣지 않는다.
- 근거가 없는 소품이 눈에 들어오면 그 자리에 아무것도 그리지 않는다.

### 4.7 UI 규칙 (docs/UI_WORKFLOW.md / UI_IMPLEMENTATION_RULES.md 준수)

- **도트 폰트·미니멀 텍스트 UI 금지.** 1판의 시스템 폰트 12/14 는 화면 톤과 안 맞는다.
- UI 는 화면과 **같은 색 언어**를 쓴다. 검정 배경 + 흰 글자 금지.
- 크기: 본문 16px 이상, 제목 24px 이상. 최소 12px는 쓰지 않는다.
- focus 는 **형태**(굵은 테두리 / 밝은 면)로. 색 변화만으로 금지 (R2).
- 선택(적용됨)과 focus(다음 대상)를 다른 표기로. (R2)
- 최대 데이터에서 겹침/잘림 0. 고정 행 높이와 고정 열 위치. (R3)
- disabled 는 다른 형태 + intent 없음. (R5)
- HUD 는 4개 이하. 계획서/레퍼런스가 요구할 때만.

### 4.8 금지

- 순수 검정 단색 배경
- 1px 헤어라인만으로 공간을 만드는 것
- 무채색/그레이스케일 강제
- 채우지 않은 면
- 저밀도 빈 화면
- 근거 없는 초현실 소품
- 코드 주석·디버그 문자열의 화면 노출
- 이미지 파일 / ASCII 문자

## 6. 근거 규칙 (초현실은 여기서 나온다)

`ambiguity_rules.md` 의 R1~R8 은 **서사 규칙**이었다. R9~R12 를 추가해
**시각 규칙**으로 만든다. 규칙은 먼저 세우고 세계를 비튼다.

| # | 규칙 | 시각 결과 |
|---|---|---|
| R9 | **몸통 규칙**: 모든 보이는 것은 면과 관절로 구성된다 | 개체도 구조물도 같은 조립 규칙 |
| R10 | **크기 규칙**: 크기는 authored 값이고 장면 안에서 최대 1개만 규칙을 깬다 | 큰 것 1개. 나머지는 규칙을 지킨다 |
| R11 | **중력 규칙**: 기본은 아래로 내려앉는다. `float` 소품만 예외 | 하늘에 뜬 기차, 공중 소품 |
| R12 | **배치 규칙**: 같은 것은 서로 같은 자리를 차지한다. 한 개만 중복 가능 | 중첩된 동일 물체 1쌍 |

- R10~R12 중 **규칙을 깨는 것은 authored 로 1~3개뿐.** 세 개가 동시에 깨지지 않는다.
- 화면마다 어느 규칙이 깨졌는지는 **코드에서 추론하지 않고 content 가 명시한다.**

## 7. 해상도

- 960×640 유지: 1920×1280가 정확히 2배다.
- **면 채움 화면에서는** 정수 배가 더 중요해진다(선이 번지는 것을 막으려고).
- 720p(1배)에서 색면 대비가 약해질 수 있다 → 팔레트 대비값을 1배 기준으로 조정.
- Q12 재확인 필요. (960×640 / 1280×720 / 1920×1080 네이티브)
