# 신규 게임형 모듈 — 유령 저택의 밤 행렬

필수 입력: [설계 철학](../../docs/DESIGN_PHILOSOPHY.md), [모듈 계약](../../docs/MODULE_CONTRACT.md), [UI 작업](../../docs/UI_WORKFLOW.md), [UI 레퍼런스 적용 지도](../../docs/UI_REFERENCE_ADAPTATIONS.md), [시각 방향](../../docs/VISUAL_DIRECTION.md), [지식 기반 설계](../../docs/KNOWLEDGE_BASED_DESIGN.md), [검증 절차](../../AGENTS.md).

## 출처와 작업 범위

**사용자 요청:** UI 연구를 적용하는 새 게임모듈 계획을 만들되 2026-09-22 제공한 메모 뭉치에서 소재를 가져온다. 코드/씬은 이번에 만들지 않는다.

**사용자 메모에서 채택한 소재:** 탐험가, 비 오는 동굴과 막힌 입구, 연금술 실험실, 귀부인 안방, 움직이는 그림이 있는 복도, 새벽 4시 유령 파티, 피아노를 가르치는 두 유령, 장롱 뒤 서재, 시간표와 지도, 가면·천·가위로 위장, 꾸몽머리로 행렬 교란, 정문 열쇠, 깊은 어둠/유령 근처의 광기, 눈맞춤 경직과 뒤로 물러나 숨기, 반경 2m 발광 보조 아이템, 종류별 첫 게임오버 연출, 그림/피아노 의자/가면 유행 결말, 통 속 물건의 조합 이스터에그. “발견하지 못하고 지나갈 가능성”도 이 모듈에 적용한다.

**AI 설계안:** 작업명과 임시 ID `ghost_procession`, 2D 고정 방 화면, 행동 단위 시간, 방 그래프·행동 비용·위험 수치·복구 정책·대체 동선·파일/API는 아래의 구현 기본안이다. 사용자 확정 이름/라우트가 아니다. 공포만 지속시키지 않고 이상한 파티 예절과 실패 후 가면 유행 같은 기묘한 유머를 살린다.

우주 조난/관계 시뮬레이션/회사원 추격 등 다른 메모를 같은 세계로 합치지 않는다. 이불 반란은 기존 후보로 유지하며 이번 신규 계획의 소재가 아니다. 이번 작업에서 모듈 등록·외부 패키지 설치·테스트 실행·화면 검수가 완료됐다고 기록하지 않는다.

## 1. 실제 게임 레퍼런스와 가져올 루프

1차 인디게임 레퍼런스는 **The Sexy Brutale**. [개발 참여사 소개](https://abstraction.games/game/the-sexy-brutale)와 [공식 판매 페이지](https://store.steampowered.com/app/552590/)에서 가면무도회 저택, 관찰·탐문, 동시 진행 사건과 시간 반복을 확인했다. 가져올 루프는 **방과 인물을 관찰 → 사건 순서 파악 → 다른 위치/행동으로 개입 → 같은 저택의 달라진 상태 확인**이다. TIN에서는 살인 저지 대신 위장·시선 회피·행렬 탈출로 변형한다. 원작의 12시간 루프·능력 가면 해금·인물·저택 배치는 가져오지 않는다.

보조 상호작용 레퍼런스는 **The Count Lucanor**. [공식 Nintendo 소개](https://www.nintendo.com/en-ca/store/products/the-count-lucanor-switch/)의 탐험·단서·탁자 아래/커튼 뒤 숨기를 확인했다. 안전한 은신 위치를 세계 사물로 읽고 관찰 후 이동하는 구조를 참고한다. 원작 자산과 이야기는 복제하지 않는다.

이번 확인은 텍스트 자료 조사다. 구현 전 실제 화면에서 저택 탐색/지도·시간 정보/은신 상태를 보고 캡처 출처를 남긴다. 기존 TIN 화면의 1152×720 baseline도 그때 확보한다.

## 2. 반복해서 사용하는 게임 문법

방을 본다 → 물건/틈/인물을 선택한다 → 관찰하거나 준비한 물건을 사용한다 → 행동으로 시간과 시선/위장 상태가 변한다 → 결과를 보고 이동/후퇴/은신/재계획한다.

지도와 시간표는 별도 퍼즐의 답 입력창이 아니라 이 행동을 계획하는 도구다. 가면 제작·그림 회피·행렬 합류도 같은 선택/대상 지정/확인/취소를 사용한다. 자유 조작에서 갑자기 리듬 입력·연타·정밀 조준으로 바꾸지 않는다.

플레이어가 배울 지식:
- 눈맞춤은 즉시 움직일 수 없는 끝이 아니라 후퇴/은신을 고를 상황이다. 깊은 어둠은 시선을 끊어도 오래 머물면 위험하다.
- 가면과 천은 행렬에서 필요한 외형을 만들지만, 빛/거리/행동까지 모든 위험을 무효화하지 않는다.
- 연주·행렬 시간표는 방의 관찰 가능성과 동선을 바꾼다. 같은 시간표를 복도와 공원에서 다시 사용한다.
- 실패 연출이나 이스터에그 발견이 탈출 능력 해금 플래그가 되지 않는다. 필요한 물건과 물리적 조건이 같다면 단서를 읽지 않아도 아는 행동을 실행할 수 있다.

## 3. 방 그래프와 콘텐츠 범위

사용자 동선의 중심: **동굴 → 실험실 → 안방 → 복도 → 파티 엿보기 → 음악실 → 장롱 뒤 서재 → 준비/합류 → 공원 행렬 → 정문**.

```text
동굴 ─ 실험실 ─ 안방 ─ 복도 ─ 음악실 ─ 비밀문 ─ 서재
                         │                     │
                         ├─ 연회장 ─ 공원 ─ 정문│
                         └─ 준비실 ─ 서비스 통로┘
```

준비실/서비스 통로는 AI 추가 동선이다. 서재를 발견한 뒤 같은 복도를 다시 통과하거나 서비스 통로를 통해 준비실로 갈 수 있게 하여 이동 지식을 재사용한다. 방 graph의 edge에는 양방향 여부·조건·소음·도착 anchor를 기록한다. 지역을 부분 reset할 수 있어도 문/아이템/유령 상태가 다른 지역과 모순되지 않게 reset group을 명시한다.

최초 시스템 검증 콘텐츠는 복도·음악실·서재·준비실·행렬 구간에 집중한다. 30~60분 첫 authored slice는 동굴부터 정문까지의 목표이며 측정 전 달성으로 쓰지 않는다. 이후 방·파티 손님·물건 반응·행렬 변형은 같은 데이터로 추가한다. 8시간 분량을 방 개수나 대기 반복으로 약속하지 않는다.

첫 탈출 경로는 메모 그대로 **위장 준비 → 행렬 합류 → 공원에서 꾸몽머리 교란 → 정문 열쇠 사용**이다. 준비 순서는 자유이며 서재→복도와 서비스 통로의 두 경로를 검증한다. 대체 탈출 엔딩을 임의로 추가하지 않는다. 행렬 진입 전 부족한 준비가 있어도 뒤로 돌아갈 수 있고, 잘못 던져 소모한 핵심 물건은 체크포인트 복구로 회수 가능해야 한다.

### 첫 authored run의 장면 연결

이 순서는 일회성 컷신이 아니라 같은 탐험·관찰·이동·은신 문법으로 플레이한다.

1. 탐험가가 비와 천둥이 들리는 깊은 동굴에서 깨어난다. 주변에서 챙길 물건을 찾고 입구를 확인하지만 무너진 돌로 막혀 있다. 돌무더기에 손을 대고 옮기며 가려진 문을 발견한다. 지도나 목표 화살표가 문 위치를 먼저 알려주지 않는다.
2. 문 너머는 폐허가 된 연금술사의 실험실이다. 책장/작업대에서 통 속의 뇌와 여우 박제를 살펴보고, 여우 입에 물린 ‘운터머리’를 선택적 조합 발견으로 둔다. 실험실은 귀부인 안방 안쪽에 숨겨져 있었고, 안방을 나서면 긴 복도에 닿는다.
3. 복도에서 파티 소리가 점차 들린다. 움직이는 그림은 관찰 대상으로 보이되, 단순히 화면이나 메뉴에 시선을 둔 시간만으로 실패시키지 않는다. 벽 틈으로 거실의 유령들을 엿보면 방의 시계에서 새벽 4시를 직접 읽을 수 있다.
4. 유령과 눈이 마주치면 짧은 경직 상태가 시작된다. 입력을 막지 않고 뒤로 물러나거나 가까운 방/가구 뒤로 숨을 수 있게 한다. 음악실 문턱의 삐걱임과 함께 피아노가 멈추고, 남자 유령이 여자 유령을 가르치던 연주를 둘이 잠시 돌아본 뒤 다시 잇는다. 플레이어는 장롱 뒤의 비밀문을 찾아 서재로 들어간다.
5. 서재에서 실제 지도와 축제 시간표를 발견하고, 가면·천·가위로 위장을 준비한다. 공원 행렬에서 꾸몽머리를 던져 혼란을 만든 뒤 정문 열쇠로 탈출한다. 준비물이나 시간표를 놓쳐도 현장에서 돌아가거나 관찰로 다시 계획할 수 있고, 선택 발광 아이템이나 이스터에그를 못 찾아도 이 경로는 성립한다.

통 속의 뇌·여우 박제 조합은 세계의 이상함과 발견 보상을 위한 선택 콘텐츠다. 그 조합이 정문 열쇠, 필수 위장, 지도, 행렬 교란 수단을 대신하거나 해금하지 않는다. 선택 비밀은 실제 관찰·시험으로 발견할 수 있지만, UI가 미발견 항목의 위치·개수·조합 정답을 나열하지 않는다.

## 4. 행동·위험·일정 모델

시간은 실시간 초가 아닌 유효한 행동 tick으로 진행한다. 문서 읽기/목록 focus/옵션 변경은 0tick, 방 이동·물건 사용·은신·기다리기는 기본 1tick이다. 순수 관찰문 읽기는 0tick, 몸을 내밀어 엿보기는 위험 행동 1tick으로 명확히 구분한다. 예상 비용은 선택 시 텍스트로 보여주며 취소는 소비하지 않는다. 이는 사용자 메모의 행동 전 예상 행동력 표시를 비용 미리보기로 응용한 AI안이고 새 AP 전투 시스템은 아니다.

처리 순서: 명령 검증 → 원자적 플레이어 효과 → tick 증가 → 해당 tick의 유령 이동/행사 이벤트(stable ID 순) → 시선/은신/위장 판정 → 광기/결말 → 상태 변경 통지. 도착한 유령과 플레이어의 판정은 같은 tick의 최종 배치를 사용한다. 메뉴를 오래 읽었다고 위험이 늘지 않는다.

일정은 `rehearsal → gathering → procession → dispersal` 단계와 데이터상의 시작 tick으로 구성한다. 새벽 4시는 최초 파티 관찰의 이야기 시각이다. 구체 분 단위 환산과 단계 길이는 튜닝값이며 사용자 시간 설정을 임의로 늘리지 않는다. 행렬을 놓친 경우 관찰 기록을 유지한 체크포인트 재시도를 제공한다. 보상을 받기 위해 같은 대기 행동을 오래 반복시키지 않는다.

위험 기본안:
- `gaze_state = clear / warning / locked`. 눈이 맞으면 warning을 거쳐 locked가 되지만 실제 조작 입력창을 막지 않는다. locked에서는 후퇴/은신/도움 설명을 계속 사용할 수 있다. 잡힘은 다음 위험 행동에도 시선이 끊기지 않을 때 판정한다. 첫 조우도 반응할 선택 기회가 있다.
- 그림을 오래 본다는 메모는 “위험 경고 후 계속 응시하기” 행동을 반복하는 것으로 변형한다. 단순 hover/메뉴 focus 체류시간 때문에 죽지 않는다.
- `madness`는 0~100 정수. 깊은 어둠 tick +1, 가까운 유령 tick +2를 초기값으로 두고 겹치면 +3, 시선 밖의 밝은 안전 지점에서는 tick당 -2. 100은 포획/광기 실패 데이터로 연결한다. 수치는 AI 튜닝값이며 긴 대기 유도가 되지 않게 안전 회복을 명시적으로 선택할 수 있게 한다.
- 위장 상태는 장착 물건 tag와 가시성/행동 조건으로 계산한다. 획득 사실만으로 위장 완료가 되지 않는다. 가면·천·가위 조합은 관찰 가능한 변화로 검증한다.
- 발광 아이템은 반경 2m의 실제 주변 사물 가독성을 높이는 선택 보조물이다. 카메라 밖/벽 너머/숨은 문/미발견 아이템 목록을 드러내지 않는다. 새 발각 페널티를 임의로 추가하지 않는다.

## 5. UI 레퍼런스가 실제 화면을 결정하는 방식

### 탐험과 눈맞춤 — Dead Space contextual UI

1152×720에서 방은 거의 전 화면, 하단 약 72px만 현재 행동/비용 안내로 사용한다. 선택 전에는 눈에 띄는 상태판이 없고 소리·그림 움직임·가구·틈이 관찰 대상을 만든다. focus하면 대상 가까이에 이름, 확인하면 짧은 관찰, 자세히 읽기를 요청할 때만 오른쪽 읽기 면을 연다.

시선 경고는 유령의 시선/대상 방향과 화면 가장자리의 서서히 짙어지는 색, “시선이 붙잡힘” 텍스트를 함께 사용한다. 후퇴 가능한 실제 출입구/은신물에 조작 focus를 줄 수 있지만 자동 정답 경로 화살표는 그리지 않는다. locked에서도 화면을 완전히 붉게 덮거나 입력을 없애지 않는다. 감소 모드는 색 변화 대신 고정 테두리·상태 문구로 같은 위험을 전달한다.

광기는 평상시 큰 숫자바를 두지 않고 상승/회복 전환에서 하단 상태 문장을 표시한다. 플레이어가 상태를 요청하면 현재 값과 **관찰 가능한 원인**을 정적으로 읽을 수 있다. 은신 뒤 시선 문구가 사라져도 어둠 침식 문구는 남아 두 위험이 다름을 보여준다.

### 서재 지도·축제 시간표 — Destiny Director와 전략 inspector

지도 열기 전에는 현재 방과 발견한 출구만 기억한다. 서재에서 실제 지도/시간표를 조사하면 문서에 적힌 방/일정을 읽을 수 있다. 문서에 그려진 장소와 직접 방문한 장소는 텍스트로 구별하고 숨은 방을 자동 채우지 않는다.

읽기 화면은 왼쪽 약 2/3 지도, 오른쪽 약 1/3 선택한 방/일정의 요약이다. 기본은 방 이름과 알려진 연결, focus는 관찰한 위험/일정, 상세는 관련 관찰 전문이다. 취소는 전문→같은 방/일정→현장으로 복귀한다. 지도에서 선택은 경로 메모일 뿐 자동 이동 명령이 아니다. 마우스의 방 선택과 패드의 인접 방 focus가 같은 상세를 연다.

시간표 행을 고르면 관련된 **이미 알려진** 방 이름을 같은 읽기 면에 표시한다. 현재 단계는 텍스트 밑줄로, 미관찰 위험은 “안전”으로 추정하지 않는다. 귀부인 안방→복도→음악실과 서비스 통로를 비교할 때 관찰 사실이 나란히 남는다. 탈출 정답을 자동 생성하는 경로 추천은 없다.

### 위장·물건 조합 — Destiny 기본/선택/상세와 카드 target 패턴

물건 목록은 이름/보유 상태 → focus 요약과 사용/조합/상세 → 전문과 출처의 세 깊이로 연다. 가면·천의 현재 장착 상태는 텍스트로 구별한다. 조합 A 선택→B 지정→예상 비용/알려진 조건→확정 또는 취소이며, 틀린 조합은 물건을 소모하지 않는다. 아직 모르는 조합 정답 목록을 펼치지 않는다.

꾸몽머리 던지기는 공원의 실제 대상 구역 선택으로 돌아와 확정한다. 슬롯 아이콘을 누르는 별도 미니게임을 만들지 않는다. 실패 시 현재 행렬과 물건 결과를 그대로 보여주고 재시도 선택을 제공한다. 발광 아이템·통 속 물건 조합은 발견하지 않아도 탈출 가능하다. 도전과제는 로컬 발견/결말 기록으로만 계획하고 전역 보상·수집률 HUD를 만들지 않는다. 선택 발견의 성취를 남기기 위해 미발견 비밀을 잠긴 목록이나 남은 개수로 노출하지 않고, 발견 후의 기록만 보여준다. 어느 비밀도 탈출 필수 조건이 되지 않는다.

### 선택에서 결과로 — Persona 5 시선 유도와 Metaphor 강도

지도 방/시간표 행/선택 물건의 밑줄과 상세 면의 제목 기준선을 같은 높이에서 읽게 한다. 다른 본문은 계속 읽을 수 있는 대비를 유지한다. 원작 팔레트·각진 컷아웃·장식은 복제하지 않는다.

시작 튜닝: focus 80ms < 물건 사용/위장 확정 140ms < 비밀문 발견/파티 상태 변화 220ms < 체크포인트 복귀 300ms. 발견은 실제 장롱/비밀문이 먼저 반응한 뒤 해당 관찰 제목을 한 번 강조한다. 실패는 그림 속 주인공/피아노 의자/가면 유행의 장면 변화로 표현하고 텍스트는 보충한다. 처음 본 결말만 전체 장면을 재생하고 이미 본 결말은 짧은 결과와 재시도로 간다. 입력으로 연출을 넘겨도 상태 적용이 중복되지 않는다.

## 7. 저장·부분 reset·실패 복구

저장 v1 봉투의 모듈 상태는 JSON 값만 포함한다: `content_revision`, `attempt{room_id,anchor_id,tick,phase,world_flags,ghost_positions,inventory,equipped,gaze,madness}`, `observations[]`, `seen_endings[]`, `checkpoint{attempt_snapshot}`. `phase/ghost_positions`는 tick/이벤트와 일관성을 검사한다. 포커스·진행 중 tween·Node 참조는 저장하지 않는다.

`load_state({})`는 동굴 초기 상태. 알 수 없는 선택 ID는 유효 대상으로 복귀하되 필수 방/일정 정의가 손상됐으면 현재 정상 상태를 보존하고 실패를 알린다. inventory/world의 unique item 중복을 거부한다. 미래 schema는 기존 Director 경계를 따른다. 아직 v0가 없으므로 존재하지 않는 legacy 이관을 만들어내지 않는다.

부분 reset은 **checkpoint group의 snapshot 복원**이다. 경계를 넘긴 핵심 물건/문 상태가 있으면 그 의존 그룹도 함께 복원하거나 복구를 거부하고 전체 시도 checkpoint로 돌아간다. 재시도는 관찰·본 결말을 유지, module reset은 시도를 처음으로 돌리되 본 결말 목록은 유지하는 AI 기본안이다. 전역 기록 삭제를 요청하지 않는다.

첫 게임오버 장면은 진입 또는 명시적 skip 완료 시 `seen_endings`에 한 번 기록한다. 이 메모의 실패 변형은 서로 다른 authored ending으로 보존한다: 움직이는 그림에 먹히면 액자 속 인물이 주인공의 모습으로 바뀌고, ‘유성꾸몽유령’에게 붙잡히면 주인공은 피아노 의자가 되며, 유령이 아닌 것이 들키면 주인공이 쓰던 가면이 유행한다. 각 장면은 첫 회 전체 연출 뒤 재방문에는 짧은 결과와 복구 선택을 제공한다. 중간 종료의 정책은 같은 장면 재생이며, 재실행 후 이미 본 장면 생략을 보장하려면 기존 저장 요청 경로의 성공까지 확인한다. 저장 실패 시 세션 내 중복은 막되 영구 기록 완료라고 말하지 않는다. 같은 failure 처리 중 requested/finished가 중복되지 않아야 한다.

## 9. 구현 순서와 검증 가능한 산출물

1. 0단계 감사 및 실제 레퍼런스 화면/기존 baseline 확보. 임시 ID·catalog 진입 의도와 소유 파일 확정. 필요한 입력 액션과 셸 충돌 확인.
2. 사용자 메모의 순서대로 지도 윤곽→전체 동선→방 구획 수정→연결/장애물/아이템 anchor 표시. 이 단계는 blockout이며 화면 완료가 아니다.
3. 순수 state/action/schedule/risk/checkpoint + 검증용 최소 2동선 작성. UI 없이 실패/재시도/다른 순서의 준비를 검증한다.
4. 방/계획/물건/실패 view를 하나씩 조립. 각 단계에서 앞 절의 구체 reference→상태 전이를 확인한다. 위장/아이템 추가에 모듈 스크립트의 정답 분기가 늘지 않게 한다.
5. 시스템 한계에 맞게 anchor·일정·위험 조정→플레이테스트→수정. 첫 동선 완주와 부분 reset이 검증된 뒤 콜라주 월드 아트·소리·밀도를 입힌다.
6. 정문 탈출·세 종류 첫 실패·발견하지 않아도 되는 보조/이스터에그를 검수하고 새 방/파티 반응을 데이터로 증설한다. test 결과와 실제 시간/스크린샷을 인계한다.

필수 자동 검증:
- 문서 열기/장시간 focus에 tick/위험 불변, 실제 행동 1회에 tick 1회, blocked command 무변경.
- 유령 이동과 문 닫기가 같은 tick일 때 stable 결과, warning→후퇴/은신 탈출, locked 중 안전 동작 가능, hover만으로 사망 없음.
- 시선 밖 어둠의 광기 증가, 유령 근접 중 중첩, 안전 회복, 임계값 99/100, snapshot 복원 동등성.
- 조합 A/B 순서와 무효 조합 원자성, unique item 중복 없음, 위장 전/후 같은 유령 판정 차이, 핵심 물건 실패 후 복구 가능.
- 준비 순서 역전/지도 미열람/선택 발광 아이템 미획득/이스터에그 미발견으로 주 경로 탈출, 두 동선의 상태 일관성.
- map→detail→cancel 포커스, item→target→cancel 무소모, 문서 확대/긴 이름/empty, 모달 중 배경 입력 차단, 재바인딩 이전 대상 제거.
- 눈맞춤 직전·은신 중·행렬 진입 전·실패 직후 저장 round-trip, 부분 reset 경계 물건 보존/복구, seen_endings 중복/skip/저장 실패.
