공통 설계 원칙: `docs/DESIGN_PHILOSOPHY.md`

- `violet_case`: 완료. Case 01 회귀를 보존하면서 Case 02·03, 사건별 상태 저장, 사건 선택, 확정 기록/미확정 이론 분리를 구현했다.
- `paper_moon_clinic`: 미구현
- `quiet_locker`: 미구현

## A. violet_case — 사건 1개짜리 화면에서 "사건 파일 묶음"으로

현재 문제:
- hotspot 3개
- 범인/수법/동기 3칸
- 정답 1개
- 한 번 풀면 끝

### 구조 변경

`module.gd`의 상수 배열을 사건 데이터로 묶는다.

```text
CASES = [
  {
    id,
    title,
    subtitle,
    hotspots[],
    findings[],
    suspects[],
    methods[],
    motives[],
    solution[],
    reconstruction_text,
    observation_id
  }
]
```

상태 추가:
```text
case_index
case_states[]
completed_cases[]
```

기존 "보랏빛 사건"은 case 01로 그대로 보존한다.

### Case 02 — 끝없이 노래하는 오르골

사용자 아이디어 핵심을 사용한다.

플레이어가 처음 알게 되는 사실:
- 이 오르골은 부수거나 묻어도 다시 누군가의 손에 돌아온다는 소문
- 영원히 춤추는 소녀 전설
- 경찰이 데려갔다고 전해지지만 실제 경찰 기록에는 그런 인력이 없음
- 누군가 경찰을 사칭해 소녀를 계획적으로 데려갔다는 설
- 소녀의 유해로 일곱 오르골을 만들었다는 설
- 소녀가 있던 장소의 거대한 청동상 내부에서 아직 춤춘다는 주류설
- 악마가 영원한 춤과 영원한 노래를 함께 줬다는 별도 설
- 사칭범이 소녀를 무한동력으로 이용했다는 경제적 동기설

#### 조사 지점 최소 7개

1. 현재 오르골
2. 오래된 경찰 인계 문서
3. 사칭범 복장 사진/목격 기록
4. 일곱 오르골의 제작 흔적
5. 청동 소녀상 설계도
6. 소녀 실종 전 계약문/소문
7. 무한동력 사업 장부 또는 생산 기록

#### 추리 화면

한 번에 "정답 하나"를 강요하지 않는다.

두 층으로 나눈다.

**확정 가능한 사건**
- 누가 소녀를 데려갔는가
- 어떤 방식으로 데려갔는가
- 오르골과 소녀 사이에 어떤 물질적 연결 흔적이 있는가

**미확정 이론**
- 오르골이 실제 신체 조각인가
- 청동상에 소녀가 있는가
- 악마의 계약인가
- 무한동력인가

확정 사실과 설을 UI상 분리한다.
모든 괴담을 하나의 "진실"로 확정하지 않는다.

#### 특별 대사

어떤 캐릭터가 오르골의 수식어를 잘못 줄이려 할 때:
- "이봐 카엘."
- "수식어가 '영원'이야."

사용자 원문 느낌 보존. 이름 카엘은 해당 장면 임시명으로 두고 정본 캐릭터명으로 승격하지 않는다.

### Case 03 — 붉은 행운벌레

핵심:
- 붉은 진드기/거미 비슷한 생물
- 몸길이 단위가 기괴하게 "잉글랜드 남성의 속눈썹 13토막"
- 목격자는 모두 죽을 위험에서 살아남았다는 전승
- 특정 유명 재난/공간에서도 목격담
- 도감 채우기 보상으로 "목숨 하나 추가"라는 게임적 소문

이 사건은 범인 찾기보다 **목격담 신뢰성 평가**형으로 만든다.

조사:
- 도감
- 생존자 진술 3개
- 사진/표본
- "목숨 +1" 표시가 생긴 기록
- 사망자 중 벌레를 봤다는 반례 여부

목표:
플레이어가 "행운을 준다 / 위험 직전에 나타난다 / 생존자가 기억을 왜곡한다" 같은 가설을 구분.

### 완료 조건

- 최소 3 case를 선택할 수 있음
- case별 상태 저장
- case 01 완료해도 02/03이 독립적으로 남음
- 모든 case 필수 완료 없이 뒤로 나갈 수 있음
- 기존 case 01 회귀 유지

## B. paper_moon_clinic — 카드 3개에서 이상현상 진료기록실로

현재 문제:
- 증상 3개 확인하면 즉시 종료
- 선택 순서만 자유이고 판단이 없음

### 구조

"환자 파일"을 도입한다.

```text
PATIENTS = [
  {
    id,
    label,
    symptoms[],
    examinations[],
    notes[],
    optional_questions[]
  }
]
```

기존 종이달 환자는 Patient 01로 유지.

### Patient 02 — 기억이 해독될지도 모르는 해마

사용자 아이디어:
- "해마의 기본형"
- "해독하면 기억이 나올지도"

진찰은 기억을 직접 보여주지 않는다.
관찰 가능한 패턴/조각을 모으고 플레이어가 어떤 순서로 해독할지 선택.

상호작용:
- 형태 관찰
- 반응 자극
- 조각 순서 바꾸기
- 기록과 비교

### Patient 03 — 코즈믹 호러 기억상실

사용자 아이디어:
- 이해할 수 없는 기억을 억제하기 위해 전두부가 타들어가듯 기능한다는 fictional mechanism
- 억제 기능이 무너지면 광기처럼 보이는 현상

중요:
- 현실 신경과학 설명으로 쓰지 않음
- 이 세계의 **fictional pathology**로 명시

상호작용:
- 기억 노출량 조절
- 환자가 견딜 수 있는 범위 관찰
- 억제 장치/기억 파편 관계 기록
- 전부 열어보는 게 정답이 아님

### Patient 04 — 손 떨림의 자기인식 루프

핵심 질문:
- 먼저 떨린 것인지
- "나는 떨고 있다"는 인식이 행동을 계속 만든 것인지

정답 고정 금지.
검사 순서에 따라 서로 다른 관찰이 나오게 하고, 진료 기록에 **원인 미확정**으로 남을 수 있게 한다.

### Patient 05 — 전 지구적 외계손 증후군

fictional disaster seed:
- 안전하다고 여긴 특정 물질이 장기간 공장 방류
- 세계 곳곳에 축적
- 어느 순간 대규모로 자율적 사지 행동이 발생

진료소에서는 전 지구 사건 자체를 구현하지 않고:
- 샘플 환자 1명
- 오염 지도
- 공장 배출 기록
- 손이 본인의 의도와 다르게 움직이는 짧은 장면
만 제공.

나중에 별도 대형 모듈로 승격 가능.

### 선택적 짧은 기록

- "남유럽식 포도를 몸에 걸친 것은 종양이다" 같은 문장을 **괴상한 진료 메모**로 1회 등장시킬 수 있음
- 현실 병명으로 해석하지 않음

### 플레이 분량 목표

필수:
- 아무 환자 1명만 보고 나갈 수 있음

선택:
- 5환자를 모두 보면 15~25분 정도의 추가 탐색/기록

## C. quiet_locker — 3칸 필수 조사에서 잡동사니 밀도 공간으로

현재:
- 사물함 3개
- 전부 보면 종료

변경:
- 기존 필수 3칸 유지
- 주변에 **선택 조사물 8~12개** 추가
- 선택물은 진행에 필요 없음

### 즉시 사용 가능한 사용자 아이디어

1. 오른손 검지 전용 손톱깎이
2. 오른손 중지 전용 손톱깎이
3. 오른손 약지 전용 손톱깎이
4. 오른손 소지 전용 손톱깎이
5. "전설의 성검 +10 강화 실패" 흔적이 남은 모루 조각/영수증
6. 사이보그 비듬 — 실제로는 도색이 떨어진 것처럼 보임
7. 창밖을 보며 일정한 간격으로 신호 보내는 고양이
8. 오래된 붉은 벌레 도감 페이지
9. 용도를 알 수 없는 귀이개/칫솔 겸용품
10. "혈밍아웃 이후 마을회관 축하회" 같은 전혀 맥락 없는 사진

### 상호작용 규칙

- 한 번 조사한 물건은 짧은 설명
- 두 번째 조사에서는 다른 한 줄
- 일부 두 물건을 연속으로 보면 조합 대사 발생
- 모든 걸 볼 필요 없음
- 3개 필수 사물함 이후 언제든 forward 가능
- optional object 수집률 표시 금지

### 추천 조합 대사

손톱깎이 여러 개를 연달아 조사:
- "엄지용은 없다."
- 그 다음 조사에서야 엄지용이 바닥에 따로 떨어져 있음

사이보그 비듬→모루:
- 금속 가루를 전부 같은 종류로 보려는 플레이어 기대를 한번 깨기

고양이→신호 관련 물건:
- 고양이 신호가 실제 다음 루트와 관련 있는지 끝까지 확정하지 않음

## D. wrong_weather / after_signal / teacup_orbit — 미세 증설

이 세 곳은 대형 리팩터링보다 **선택 상호작용 3~5개**만 넣는다.

### wrong_weather
추가 예보 후보/현상:
- 실내만 눈
- 바닥에서 위로 오르는 비
- 구름 아래가 아니라 구름 위만 젖음
- 기상캐스터 뒤에서만 번개

틀린 예보를 내면 단순 실패 문구가 아니라 각각 별도 방송 사고 한 줄.

### after_signal
추가 흔적:
- 오르골 수리표
- 붉은 벌레를 눌러놓은 투명 테이프
- 손톱깎이 세트 주문서
- "수식어가 영원"이라고 적힌 메모

모두 optional.

### teacup_orbit
7회 클릭 외에:
- 찻잔 방향 반대로 돌리기
- 받침 접촉
- 차 온도 확인
- 빈 찻잔인지 확인
같은 쓸모없는 상호작용 추가.
정답/보상으로 만들지 않는다.
## 시각 증설 규칙 — 2026-09-22

이 문서의 콘텐츠 증설은 plans/visual_overhaul/INDEX.md와 함께 수행한다.

- 조사물 추가를 Label 한 줄과 클릭 영역 추가로 끝내지 않는다.
- 선택 조사물은 화면 안에 실제 월드 오브젝트로 존재해야 한다.
- 새 오브젝트는 at-icons를 원래 의미와 다르게 조합한 collage를 우선 사용한다.
- optional 상호작용 수가 늘어날수록 화면이 개발용 버튼 목록처럼 변하지 않게 한다.
- UI에는 icon을 쓰지 않는다.
- 각 모듈의 상용 레퍼런스는 visual_overhaul 배치 문서의 지정값을 따른다.
