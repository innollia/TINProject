# 구현된 게임별 플레이 재설계 — 최우선

UI 작업 계약: [UI_WORKFLOW](../../docs/UI_WORKFLOW.md). UI 변경이 있는 실행 계획은 화면별 계약과 검수 증거를 구체화한다. 후보/아이디어는 구현 계획 승격 시 적용한다.

사용자 문제 제기(2026-09-22): **구현된 게임 모듈 하나하나가 시답잖은 미니게임에 머물러 있다.** 아래 개편안은 이에 대한 AI 제안이다. 확정된 소재·정서·연결을 보존하되 기존 정답표/필수 조사 수/선택 횟수를 게임성으로 보존하지 않는다.

필수 입력: [설계 철학](../../docs/DESIGN_PHILOSOPHY.md), [지식 판정 기준](../../docs/KNOWLEDGE_BASED_DESIGN.md), [결정 기록](../../PROJECT_DECISIONS.md). 구체 시스템 5종은 기존 game_modules 계획을 따른다.

## 진행 기록

2026-09-22: `rule_rewriting`에 첫 수직 슬라이스를 적용했다. 규칙 선택 뒤 실제 보드에서 블록 밀기/통과, 문턱 접촉, primary·alternate 해결, undo·저장 복원을 검증한다. 이어 D1 `dedution_casework`에 두 사건 번들, 사건별 독립 상태 전환, 현장 재조사, 미완성·모순·그럴듯한 오답·해결 판정을 추가했다. P1 `physics_toolbox`에는 두 배치 경로, 물체 위치·접촉·목표 영역 판정, 목표 밖 실패와 snapshot 복원을 추가했다. T1 `time_loop`에는 persistent 기억과 loop-local 관찰/세계 상태 분리, 재관찰 조건부 alternate route, 상태 복원을 추가했다. O1 `odd_road_adventure`에는 안내인 재회 후 붉은 실로 사당을 건너뛰는 역 우회 경로, 사건 history와 원자적 아이템 실패를 추가했다. 다섯 결과 모두 시스템 증거이며 runtime word parser/Resource loader/장시간 authored content 완료를 의미하지 않는다. 다음 작업은 Resource/content 추출과 시각 검수다.

## 이번 계획의 우선순위 수정

콘텐츠 몇 개 추가, 옵션 몇 줄 추가, 그림 교체로 이 문제를 완료 처리하지 않는다. 기존 콘텐츠 증설 C1/C2/C3는 아래 플레이 구조를 먼저 증명한 뒤 붙이는 재료다. 분량/지역/환자/사건 개수는 깊이의 대리 지표가 아니다.

큰 게임형 5종은 각자 지속 가능한 중심 시스템을 완성한다. 기존 짧은 공간도 자체 규칙이 적용되는 여러 상황 또는 탐색·인물·공간 변화가 있어야 한다. 모든 곳을 대형 퍼즐로 바꾸지는 않는다. 휴식/연출 공간은 재방문·반응·세계 경험으로 역할을 증명하며 독립 게임 완성으로 포장하지 않는다. 사용자가 확정한 무의미한 클리커·짧은 개그는 보상을 억지로 붙이지 않는다.

## 실행 순서와 첫 산출물

1. R1→D1→P1→T1의 기존 지정 순서를 유지한다. 각각 최소 두 상황이 다른 사고/실험을 요구하는 playable slice를 만든다. 시각 완료와 별도로 게임성 검토를 통과해야 다음 콘텐츠를 증산한다.
2. O1은 기존 네 지역 안에서 병렬 사건/상태 재사용을 먼저 증명한다. 지역 수를 늘리지 않는다.
3. 기존 장면은 signal_desk부터 위 표 순서로 검토하되, 기능이 연결되는 세트의 다른 모듈을 동시에 리팩터링하지 않는다. 각 작업 전에 해당 행을 데이터·명령·이관·장면별 상세 계획으로 확장한다. 표만으로 새 subsystem 구현에 바로 착수하지 않는다.
4. clinic/locker의 추가 환자/사물과 기존 미세 증설은 재설계된 문법을 검증하는 데 필요한 것부터 채택한다. 나머지는 기존 계획에 대기시킨다.

## 게임성 완료 게이트

각 모듈의 구현 작업은 다음 증거를 남긴다.

- 플레이어가 배우는 관계/규칙 또는 탐색·서사 문법을 한 문장으로 적는다.
- 처음과 다른 상황에서 그 이해를 다시 쓰는 실제 플레이 경로 두 개를 적는다. 정답 인덱스/문구만 다르면 실패다.
- 플레이어 행동으로 바뀌는 세계 상태와 그 상태가 다음 선택에 미치는 영향을 확인한다.
- 오답 후 정답만 재선택하는 것 외에 관찰·실험·가설 수정·다른 탐색으로 돌아가는 경로가 있다.
- 새 상태/중간 저장/재진입에서 같은 문법이 작동한다. 지식 경로는 숨은 읽음 플래그 없이 검증한다.
- 자동 테스트는 상태/계약 증거다. 실제 플레이에서 ‘답을 누르는 작업’으로만 느껴지는지 별도로 확인하고, 확인 전에는 게임성 완료로 표시하지 않는다.

귀환·지름길·짧은 개그처럼 독립 게임이 아닌 장면은 위 두 해법 조건을 억지로 적용하지 않는다. 그 대신 공간 변화·반응·연속성의 구체 결과를 보고하고, 이들을 늘려 게임형 모듈 수나 깊이를 채웠다고 주장하지 않는다.

## 호환성 경계

저장 ID·사용자 확정 경로·정체성·관찰 기록은 보존한다. 기존 정답표와 클릭 수를 보존하려고 새 플레이를 그 뒤에 추가 미니게임으로 붙이지 않는다. 이관용 legacy 데이터/테스트는 허용하지만 release에 옛 얕은 모드 선택을 상시 노출하는 것은 기본값이 아니다. 새 규칙으로 옮길 수 없는 과거 진행은 완료 이력으로 보존하고 새 상황을 안전한 시작점에서 제공한다.
