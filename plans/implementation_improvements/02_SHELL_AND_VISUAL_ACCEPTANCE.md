# 셸·게임 목록·시각 검수 보완

필수 입력: [MODULE_CONTRACT](../../docs/MODULE_CONTRACT.md), [VISUAL_DIRECTION](../../docs/VISUAL_DIRECTION.md), [시각 계획](../visual_overhaul/INDEX.md). 아래 검증 추가와 배치는 AI 제안이다.

## U1 — 전환과 포커스

소유: `app/app_root.gd`, `modules/game_library/**`, `tests/core/test_cycle_app.gd`. 먼저 기존 `test_settings_library_browses_all_games_and_returns_or_switches`를 실행한다.

| 시작 | 동작 | 기대 상태·실패 복구 |
|---|---|---|
| 게임 진행 중 | 설정→게임 목록→취소 | 원래 모듈의 진행을 유지하고 설정으로 복귀, 원래 버튼에 포커스 |
| 목록 HOME | 전체 목록→뒤로 | HOME의 선택 항목 복구, 확인키 홀드로 즉시 게임 진입하지 않음 |
| 전체 목록 | 첫/마지막 항목 탐색 | 화면 밖 포커스가 스크롤로 드러남, 키보드만으로 모든 항목 접근 |
| 전환 중 | 확인/취소·직접 버튼 콜백 | input_enabled 차단, requested 중복 없음 |
| 목록 | 유효하지 않은 목적지 요청 | 현재 화면/진행 유지, 재선택 가능 |
| 게임 | 저장 복원 실패 | 이전 진행 유지, 설정/기록 오버레이와 입력 상태도 복구 |

목록은 저장 진행 대상이 아니다. 포커스 복원용 일시 상태를 영구 프로필에 넣지 않는다. 목록 항목 수는 catalog/manifest에서 계산하고 숫자를 하드코딩하지 않는다. 테스트는 first_entry와 game_library 제외, 데모 포함 정책을 검증한다.

## U2 — 기록·정체성

소유: `meta/records/**`, `tests/core/test_records.gd`, 필요한 경우 같은 작업자가 `tests/core/test_cycle_app.gd`를 수정한다.

- 기록 편집 중 선택 대상 삭제·모듈 전환·복원 실패 시 초안 처리와 포커스를 확인한다. 기존 테스트로 이미 보장된 경로는 중복 테스트를 만들지 않는다.
- identity 3×3 조합이 first_entry→last_echo→return_cradle에서 동일하게 보이는지 검수한다. 시각 표현을 바꿔도 저장된 shape/color 매핑은 유지한다.
- 전역 관찰은 사실만 기록하고 미확정 이론/동료 임시 이름을 확정 설정으로 바꾸지 않는다.

## V1 — 누락 화면 편입

시각 배치 00의 캡처 목록을 AppRoot catalog와 대조한다. 현재 34개 모두 현황을 찍되 데모 3종은 수정하지 않는다. `first_entry/manifest.tres`도 포함한다. AppRoot 기본/HUD 숨김, 설정, 일시정지, records, game_library HOME/전체목록/스크롤 끝을 별도 행으로 관리한다.

게임 목록은 기존 Nintendo Switch HOME 참고 구현을 유지한다. 상용 화면 실제 확인 후 1152×720에서 상단 프로필/제목 96px, 중앙 커버/격자 500px, 하단 텍스트 조작 안내를 기본 구획으로 검토한다. 원작 로고·자산을 복사하지 않는다. 컬러 사각형만 있는 커버는 모듈의 자체 월드 장면으로 교체하고 기능 픽토그램을 얹지 않는다. 선택/비선택은 테두리·크기·텍스트로 구분한다.

게임형 5종은 각 `game_modules` 계획의 첫 장면·행동·실패·복원·전환 캡처를 담당한다. 기존 visual 배치 03에 끼워 넣어 시스템 보완을 건너뛰지 않는다.

## V2 — 검수 기록 형식

구현 작업마다 모듈 로컬 산출물 또는 작업 결과 경로에 다음 표를 남긴다. 문서 작성만으로 빈 표를 통과 처리하지 않는다.

| 화면/상태 | baseline 파일 | 레퍼런스 원문 URL·화면 종류 | 결과 캡처 | 판정/남은 문제 |
|---|---|---|---|---|
| entry / focus / action / wrong / success / restore / transition | 구현 시 작성 | 구현 시 실제 확인 | 구현 시 작성 | 미검수 |

필수 수동 시나리오: AppRoot에서 진입→선택→오답→수정→메뉴 정지/복귀→중간 저장/복원→성공→귀환. 그림·월드 텍스트와 UI의 역할을 구분해 placeholder 검색 결과를 직접 판정한다. 엔진 headless 통과는 화면 검수나 Iris Xe 프레임 실측을 대체하지 않는다.

## U3 — UI 배율·모션·입력 검수 기반 (후속 작업, 미구현)

필수 입력: [UI_WORKFLOW](../../docs/UI_WORKFLOW.md). 아래 순서·배율 범위·설정 구조는 AI 제안이며 이번 문서 변경으로 구현되지는 않았다.

1. 기존 app/meta의 Theme·레이아웃·설정 저장·InputMap을 조사한다. 공통 UI 프레임워크 대신 기존 셸 안에서 글자/UI 배율과 Reduced Motion의 소유자를 정한다. 필요한 settings 계약 변경은 별도 작업 범위로 명시한다. 모듈에 전역 설정 조회를 추가하지 않는다.
2. 기준 1152×720는 유지한다. 지원할 최소/최대 창 크기, 16:9/울트라와이드/좁은 창 범위와 배율 단계는 실제 레이아웃 점검 후 계획에 기록한다. 현재는 TBD이며 보고서의 breakpoint 예시를 채택하지 않는다.
3. 설정 변경→닫기→재열기→재실행 시 값/표시 복원을 검증한다. 손상/이전 설정은 기존 값과 안전한 기본값으로 복구한다. 설정 저장 파일이나 ModuleContext 확장이 필요하면 실제 소비 모듈과 호환 테스트를 명시한 뒤 수행한다.
4. 설정→기록/목록→뒤로의 포커스/입력 소유권을 자동 테스트한다. 항목 삭제·비활성, 빈 목록, 긴 이름, 확대+스크롤 끝, 확인키 홀드, 장치 전환, 두 오버레이 간 취소를 포함한다.
5. 실제 컨트롤러/키보드/마우스로 핵심 메뉴 과제를 수행하고 장치별 증거를 남긴다. 컨트롤러 미보유/미검수는 자동 입력 테스트 통과와 구분한다.
6. 모션 감소는 first_entry의 과도한 이동/흔들림을 줄여도 키 흡수 진행·외형 선택·배정 결과를 읽을 수 있어야 한다. 사용자 확정 연출의 의미를 없애는 변경은 이 작업의 임의 기본값으로 정하지 않는다.
7. 스크린리더 적용 플랫폼/설치 엔진 지원 범위와 읽기 순서는 조사 항목이다. 이번 단계에서 지원 완료를 선언하지 않는다.

소유 후보: app의 셸, meta/records, game_library와 해당 테스트. 실제 파일 목록은 1단계 조사 뒤 고정한다. 다른 모듈은 소비 경로가 필요한 별도 작업에서만 변경하며, core 계약 변경을 시각 작업에 끼워 넣지 않는다. UI 옵션과 입력 검증이 끝나기 전 U3 완료 처리 금지.

## U4 — 보고서의 탐색 구조를 셸 화면으로 적용

[레퍼런스와 출처](../../docs/UI_REFERENCE_ADAPTATIONS.md). 아래는 Destiny의 Director/아이템 탐색, Persona 5의 선·명도 계층, 보고서의 Tabs/Modal/Toast를 직접 적용한 **TIN 화면 설계안**이다. Nintendo Switch HOME 기반 목록의 기존 구도는 유지하고 상세 공개/복귀 규칙을 보강한다.

**게임 목록:** HOME의 가로 커버와 전체 격자를 오가는 현재 구조에서 기본 항목은 커버+제목, focus 상태는 같은 위치의 테두리와 상단/하단 읽기 영역에 짧은 소개, “상세”는 선택 게임의 설명과 “시작/돌아가기”로 단계화한다. 없는 장르/소개는 자동 추측하지 않는다. 상세 진입 때문에 게임을 시작하지 않으며, 상세 닫기는 같은 커버와 스크롤 위치로 돌아온다. 사용자는 상세를 거치지 않고 명시적인 시작 입력으로 바로 진입할 수도 있다.

Persona 5처럼 선택된 제목이 가장 먼저 보이고 그 제목 아래의 얇은 선/같은 정렬축이 설명 면으로 이어지게 한다. 커버 전체가 동시에 커지거나 흔들리지 않는다. HOME→전체 목록은 focus 대상이 읽기 면으로 이동하는 방향을 유지하고, 되돌아오면 이전 HOME 커버를 복구한다. hover로 얻는 소개는 패드 focus에서도 같다. 확인키를 누른 채 진입했을 때 새 화면의 시작 버튼이 다시 실행되지 않도록 release 경계를 검증한다.

**기록:** 왼쪽 약 1/3에 관찰/메모의 텍스트 분류와 제목 목록, 오른쪽 약 2/3에 현재 항목을 읽는 면을 둔다. 목록 행은 제목/출처, focus는 읽기 면의 요약, 확인은 전문/편집으로 연결한다. 관찰 사실과 사용자 메모는 소제목으로 명확히 구분한다. 필터/분류 변경 후에도 가능한 한 같은 stable ID를 유지하고, 없으면 해당 목록 첫 항목에 focus한다. 목록에서 전문, 편집, 취소를 오가도 한 번에 셸 전체가 닫히지 않는다.

보고서의 전략 inspector/drill-down을 적용해 다수 기록을 한 화면에 전부 펼치지 않는다. 삭제 확인을 열면 취소에 initial focus, 취소 시 해당 기록의 삭제 버튼, 실제 삭제 시 인접 기록으로 돌아간다. 빈 목록은 읽기 면에 빈 상태 설명과 돌아가기만 제공한다. 가상 목록은 실제 최대 데이터의 스크롤 측정 뒤 판단한다.

**설정/확인/알림:** 설정은 왼쪽 텍스트 항목→오른쪽 현재 값·설명 구조로, focus만 옮겨도 설정값이 바뀌지 않는다. reset/삭제의 확인은 취소가 기본이며 아래 화면 입력을 차단한다. 저장 성공은 하단 가장자리의 작은 비차단 문장으로 끝나고 focus를 빼앗지 않는다. 저장 실패는 사라지는 toast만 쓰지 않고 설정 면에 원인과 재시도 동작을 남긴다. reset 같은 파괴적 조작에 긴 홀드를 강요하지 않는다.

모션은 목록 focus 80ms, 상세 진입 140ms 정도 시작값. 닫기는 같은 방향을 거슬러 원래 위치로 돌아온 느낌을 주되 고유 사선/팔레트는 쓰지 않는다. 감소 모드에서는 선택 제목·본문만 즉시 바뀐다. 검수는 “게임 소개 읽고 이전 게임으로 복귀”, “기록 편집 취소 후 같은 항목 찾기”, “삭제 취소/확정”, “음량 변경 후 플레이 복귀”, “저장 실패 재시도”를 각각 세 입력 장치로 수행한다. UI 상태는 셸 소유이며 모듈의 게임 진행 저장과 섞지 않는다.
